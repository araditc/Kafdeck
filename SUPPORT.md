# Support

Kafdeck community support is available through the [GitHub repository](https://github.com/araditc/Kafdeck). Start with the [documentation index](docs/README.md), [installation](docs/operator/v0.9-installation-guide.md), [first administrator setup](docs/operator/managed-identity-setup.md) and [dashboard guide](docs/operator/v0.9-dashboard-guide.md).

## Bugs and feature requests

Use the [issue templates](https://github.com/araditc/Kafdeck/issues/new/choose) for bugs and feature requests. Check existing issues before submitting. Include the release version/source commit, installation method, OS/architecture, database, Kafka/provider versions, relevant configured capability, reproduction steps, expected/actual behavior and correlation/error code. Attach minimal redacted logs. Remove tokens, passwords, certificate keys, private configuration and sensitive Kafka data. For integration failures, distinguish Kafka bootstrap addresses from the separate Schema Registry, Connect or ksqlDB endpoint.

For general usage/design questions, use [GitHub Issues](https://github.com/araditc/Kafdeck/issues) after checking the existing documentation and reports. Community support carries no response-time or availability commitment.

## Security issues

Do not report exploitable vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).

## Commercial support

No commercial support commitment is implied by the open-source repository. Any future offering will be documented separately and will not alter the Apache-2.0 rights of the open-source project.
