# v0.4 W31 Threat-Model Reconciliation

- **Status:** Release-candidate evidence
- **RFC:** RFC-0004
- **Scope:** W25-W30
- **Date:** 2026-09-21

## Preserved hard invariants

The v0.4 candidate must continue to prove:

- no Kafka mutation or produce/replay,
- no consumer offset mutation/commit,
- no Schema Registry mutation,
- no Connect mutation,
- no ksqlDB statement/query execution,
- no generic external HTTP proxy,
- no unbounded collection/polling path,
- no arbitrary server-side JavaScript,
- no v0.3 masking bypass,
- metadata/ecosystem actions do not imply `record.read` or `record.export`.

## Consumer-group threats

### Group side effects

**Threat:** Kafdeck joins a group or changes committed offsets.

**Control:** v0.4 uses Kafka Admin read APIs only. Contracts expose list/describe/offset/end-offset reads and contain no commit/reset/alter/delete operation.

### False zero lag

**Threat:** missing or out-of-range offsets appear caught up.

**Control:** missing committed offsets and committed offsets beyond the observed log end have explicit states. Invalid observations are excluded from aggregate lag.

### Partial authorization

**Threat:** incomplete group/topic access appears complete.

**Control:** upstream authorization failures remain explicit. Collection RBAC filtering adds a safe partial limitation.

## Schema Registry threats

### Mutation through compatibility/schema APIs

**Control:** catalog adapter uses GET-only paths. No schema registration, deletion, compatibility setting mutation, or compatibility-test POST exists.

### Reference/schema complexity

**Control:** item/byte/deadline bounds and local diff input bounds. Redirects are rejected.

### Compatibility provenance confusion

**Control:** subject-specific compatibility is queried first; global compatibility is used only after a subject-specific not-found result.

## Connect threats

### Secret-bearing config values

**Threat:** arbitrary plugin fields or URLs contain credentials.

**Control:** connector config projection is fail-closed. Only a small explicit allowlist may expose clear values; every other value is redacted.

### Trace leakage

**Control:** bounded trace output removes authorization headers and credential-like quoted/unquoted assignments.

### Slow Connect exhaustion

**Control:** separate per-cluster Connect bulkhead under operation deadlines.

## ksqlDB threats

### Statement execution

**Control:** the application contract accepts no SQL text. Adapter uses GET-only info/health paths. Metadata requiring statements returns Unsupported.

### Slow ksqlDB exhaustion

**Control:** separate per-cluster ksqlDB bulkhead.

## SSRF/origin threats

External endpoint origins come only from validated deployment configuration. User requests cannot select arbitrary upstream URLs. Redirects are rejected; credentials are not forwarded to another origin.

## Authorization/audit threats

New actions are default-deny and independent.

Collection preflight prevents unauthorized upstream enumeration, while per-resource checks prevent hidden names from becoming visible. Filtered collections are marked partial.

Authenticated forbidden collection requests emit structured authorization-denial audit events.

## Residual risks

- provider-specific read API behavior varies and must be treated capability-first,
- optional metrics/history have no built-in durable provider in v0.4,
- Connect config redaction intentionally sacrifices visibility for secrecy,
- ksqlDB metadata can remain unavailable on providers that require statement execution,
- one Connect and one ksqlDB endpoint per Kafka cluster is the v0.4 configuration limit.

These limitations are deliberate and do not justify broadening permissions or introducing mutation in v0.4.
