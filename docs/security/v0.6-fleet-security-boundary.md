# v0.6 Security Boundary and Threat-Model Delta

Status: **ADMITTED v0.6 RELEASE SECURITY BASELINE**. Authority #145; tracker #146. Inherits RFC-0005 and the v0.3 masking boundary. Blocked/Unsupported capability states are part of the security boundary and must not be bypassed.

## Assets and trust boundaries

Assets are Kafka availability/durability, ACL grants, SCRAM credentials, quota/config policy, record confidentiality, independent approval evidence, operation/checkpoint truth and remaining budgets. Trust boundaries separate browser/API, Identity & Access, coordinator, durable store, typed adapter, Kafka/Connect provider and any external replication runtime. Inputs from providers, Kafka names and connector errors are untrusted display content, never instructions or executable material.

## Threat-to-control-to-test matrix

| Threat | Required control | Required negative/fault evidence |
| --- | --- | --- |
| Read-to-write or worker-credential bypass | Closed per-kind conjunction; live authorization before each effect | Read-only principal, missing source/export/destination action, changed policy and revoked approver |
| ACL self-escalation or service lockout | Binding-field grant ceilings, protected principals, exact deletion set, CRITICAL broad grants | Wildcard/prefix/ALL, deny removal, escaped names, service-principal deletion |
| Credential leakage/dictionary oracle | Write-only bounded bytes; keyed operation-specific binding; no exposed digest; no credential verification endpoint | Password/salt/verifier sentinels in DB, audit, logs, traces, errors, API/UI/browser storage |
| Preview substitution/TOCTOU | Bound identities, plan, budgets, policy and material digests; relevant readback | Same alias/different cluster, topic recreation, changed ISR, altered plan, changed digest key |
| Lease expiry causes overlapping provider effects | Outstanding-effect obligations independent of observer leases | Crash before/after dispatch, stale worker, failover, concurrent v0.5 topic delete/purge |
| Transfer data exfiltration or masking bypass | Conjunctive permissions, finite mappings/ranges, policy eligibility on every batch | Protected binary/key/header, retention drift, revoked source access, arbitrary destination |
| Hidden MirrorMaker side effects | Fixed tested profile, exact topics, explicit internal writes, ACL/config/group sync disabled by default | New-topic discovery, internal-topic creation, group offset sync, override/transform/class injection |
| SSRF or credential forwarding | Deployment-controlled profiles, fixed routes, origin/redirect/TLS/deadline/size enforcement | Redirect/DNS-origin change, URL/path injection, arbitrary bootstrap server, exception echo |
| Unbounded fleet load/store growth | Parent-total budgets, transport limits, separate bulkheads, bounded retention with no live-obligation deletion | Oversized response/record/plan, counter overflow, two HA workers, storage/audit backlog full |
| False rollback/completion | Per-step evidence, partial/unknown precedence, explicit external prerequisites | Lost acknowledgement, no-op readback after secret rotate, failed throttle cleanup |

## SCRAM material contract

Only finite write-only password bytes enter preview/finalization memory. Persist safe username/mechanism/iteration/change metadata and a domain-separated HMAC binding including operation ID, cluster identity, principal, mechanism, policy and digest-key ID. Do not persist password, salted password, salt, StoredKey or ServerKey. An unkeyed hash is not an acceptable substitute for low-entropy secret material. Digests are internal, not exposed in status or telemetry; matching uses fixed-time comparison.

Clear owned buffers promptly and document managed-runtime limits; do not promise perfect erasure of every runtime copy. Request/body/exception logging and dump collection must not capture secret material. Browser forms clear after submission, are non-cacheable and never store material for delayed approval. Digest-key rotation invalidates or explicitly migrates undispatched previews under reviewed policy; it does not trigger credential redispatch.

Independent approval is completed without secret material. Finalization by the original requester re-submits the same bytes through the common coordinator after eligibility, hash, expiry, state and risk checks. An absent authoritative requester context is not repaired by manufacturing OIDC claims.

## Revocation, partial effects and recovery

Revocation stops future Kafdeck dispatch/batches. Already-issued Kafka changes or an external provider process cannot be assumed undone. Bounded read-only observation may continue to account for effects and retain conflict obligations. If safe stop of external replication is not enforceable under the selected profile, that automatic-control capability is unavailable and its existing activity is clearly labeled externally managed. This limitation must not be disguised as instantaneous revocation.

Uncertain effects cannot be cleared by deleting checkpoints, creating a new idempotency key or ignoring a failed child step. Reconciliation never scans raw payloads merely to guess whether a password/record was applied. No automatic rollback restores old ACLs/throttles over a newer administrator's state.

## Review boundary

The planning and each implementation PR require architecture/security review plus repository CODEOWNER governance. Security tests must include direct API calls as well as UI paths and preserve all existing v0.5 regression evidence. Significant invariant weakening, raw durable material storage or new execution surfaces require explicit owner decision, not a test exemption.
