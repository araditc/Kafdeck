# v0.4 Read-View Security Boundary

- **Status:** PROPOSED
- **RFC:** RFC-0004
- **Scope authority:** Issue #99

## New trust boundaries

v0.4 adds:
1. Kafka consumer-group metadata/offset observations,
2. full read-only Schema Registry browsing,
3. configured Kafka Connect REST endpoints,
4. configured ksqlDB endpoints,
5. configuration-owned catalog metadata.

Existing v0.2 identity/RBAC and v0.3 payload/masking boundaries remain authoritative.

## Security invariants

- default deny for every new action,
- no new permission implies record payload access,
- no offset/schema/connect/ksql mutation method exists,
- external URLs come only from validated deployment configuration,
- no generic proxy/pass-through endpoint,
- credentials never enter response/log/audit/problem details,
- connector secret-like configuration values are redacted server-side,
- schema material is bounded before parsing/diff,
- external responses are size/time/item bounded,
- redirects cannot escape the configured trusted origin,
- cancellation propagates,
- partial/unknown outcomes fail safe and are explicit.

## Key threats and controls

### Offset mutation

Control: Kafdeck-owned consumer observation port contains list/describe/read-offset/end-offset methods only. CI/architecture tests reject commit/alter/delete offset methods in v0.4 implementation paths.

### SSRF through ecosystem profiles

Controls: startup-time absolute URI validation, accepted HTTP(S) schemes, no user-supplied upstream URL, fixed relative routes, redirect restrictions, credential isolation.

### Connect secret leakage

Controls: allowlisted projection, case-insensitive secret-key heuristics plus known Connect password types where available, no raw config passthrough, sentinel leakage tests.

### Registry data/credential leakage

Controls: separate `schema.read`, bounded caches, safe error mapping, no Authorization header/token projection.

### Malicious schema complexity

Controls: byte/depth/reference/version limits, bounded recursive reference traversal with cycle detection, cancellation and timeout.

### ksql execution abuse

Control: no arbitrary statement endpoint. If safe provider metadata cannot be obtained without executing user-controlled SQL, capability is unsupported.

### Enumeration amplification

Controls: bounded pages/items, explicit caps, no recursive "fetch everything" endpoint, per-provider concurrency bulkheads.

### Cross-cluster cache confusion

Controls: cache keys always include cluster/profile identity; authorization is evaluated on every response path.

### Catalog privilege confusion

Control: catalog metadata is descriptive only. It cannot create an authorization binding or alter Kafka access.

## Audit

Audit records action, actor, cluster, resource, provider kind, outcome, limitation/partial state and correlation identifiers.

Audit excludes schema credentials, Connect credentials, connector secret values, record payloads, decoded record fields, tokens and cookies.

## Exit gate

Security completion requires:
- direct-route authorization tests,
- mutation-surface absence tests,
- SSRF/redirect tests,
- secret sentinel leakage tests,
- bounded recursion/response tests,
- cancellation/bulkhead tests,
- v0.3 masking/record authorization regression tests.
