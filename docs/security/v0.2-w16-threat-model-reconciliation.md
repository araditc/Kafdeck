# v0.2 Threat Model Reconciliation — W16

- **Baseline:** `main@699b1cf4452773dc55af160476b51374120a9ce0`
- **Scope:** W16 audit and security hardening
- **Authority:** RFC-0002 / Issue #57 / Issue #68

## Reconciled controls

| Threat | W16 control/evidence |
|---|---|
| Secret/token leakage through audit | Audit contract contains no token/cookie/secret/password field; structured sink logs only bounded fields; regression tests inspect contract and canonical principal. |
| OIDC authentication failure leakage | Failure audit records a fixed reason category only; provider exception/token values are not written. |
| Session fixation | Successful normalization always creates a fresh cryptographically independent session identifier; server-side ticket keys are random 256-bit values and are not upgraded from client input. |
| CSRF/session action abuse | Session cookie is HttpOnly + SameSite Strict; OIDC correlation/nonce cookies retain protocol-safe settings; logout is POST and UI performs top-level POST navigation. |
| Open redirect | Return URL normalization permits local absolute-path targets only and rejects authority-form, backslash and control-character forms. |
| RBAC denial without traceability | Server-side authorization denial emits canonical identity/session correlation plus resource scope and fixed reason category before returning safe 403. |
| Sensitive configuration read | Broker/topic configuration reads emit audit events after authorization succeeds. |
| Legacy deployment-token bypass | OIDC configuration rejects deployment token; Token middleware remains mode-bound and now emits accepted/rejected audit events without token material. |
| Kafka ACL vs Kafdeck RBAC confusion | Existing distinct Problem Details semantics remain unchanged. |
| Kafka mutation/payload regression | No mutation, produce, consume, payload model, or payload route is introduced by W16. |

## Residual posture

Durable audit history and shared multi-replica session persistence remain explicitly deferred by the accepted v0.2 plan. The W16 sink is operational structured logging, not a new durable security database.

## W16 exit evidence required

- exact-head quality/security CI,
- no secret/token leakage regression,
- legacy Token cannot satisfy OIDC mode,
- no unresolved security review finding,
- fresh independent exact-head approval.
