## Trust boundaries and probes

| Threat / entry | Required negative scenario and disposition evidence |
|---|---|
| Catalog import as privilege source | Assign attacker as owner/team, spoof labels/IDs, import cross-scope references: no RBAC/declarative authority change, no hidden-resource oracle. Test UI/REST/CLI and both stores. |
| Approval substitution or replay | Self-approval of critical effect, changed material/revision/requester, expired preview, revoked reviewer, changed policy: dispatch denied; fresh plan/approval required. Verify original actor through audit and actual effect count. |
| Direct/automation bypass | Execute legacy REST/CLI/Terraform/MCP plan without required active-policy request; no effect. Restart or switch HA node between approval and dispatch; same enforcement. |
| Policy privilege/escalation/injection | Unknown/duplicate JSON keys, excessive depth/rules, unsupported operators, scripts/SQL/URL/template expressions: reject before activation. A policy can narrow but never grant missing rights. |
| Policy/request race or unavailable authority | Concurrent activate/approve/execute, revision conflict, transaction read failure, SQLite lock and PG failover: one valid CAS winner or bounded fail-closed result, never stale dispatch/deadlock. |
| Restore or idempotency replay | Restore older approved data with an old worker alive, reuse key with changed material, replay dispatched unknown: generation fence, current authorization and positive reconciliation, no duplicate effect. |
| Exfiltration/SSRF/XSS | Hostile docs link, translated interpolation, import reason, measurement endpoint/DNS redirect, log/telemetry/export: safe escaped output, egress allowlist/TLS checks, no secrets or protected payloads. |
| Cross-scope inference in dashboards | Aggregate/count/explain/page using inaccessible resources: filter before aggregation and redact reasons; no differing existence/error oracle. |
| Fabricated measurements/rates | Missing interval, counter reset, forged provider provenance, stale ownership, decimal overflow, mixed currency: explicit quality/error and residual, no plausible invented zero invoice. |
| Resource exhaustion and leakage | Max+1 policy/import/page/window, cancellation, repeated rejected requests and soak: bounded memory/time, throttling, cleanup, no unbounded cardinality or secrets in failures. |
| Distribution compromise | Tampered archive/chart/image/mirror, mismatched source/SBOM/provenance, secret-bearing rendered values, unsafe container privileges: reject integrity failure and verify real secure-default launch. |

## Review and release requirements

W72 architecture/security review must record reviewed head/tree, boundaries considered, findings, resolution or justified non-issue and reviewer authority. Required GitHub CODEOWNER approval must be fresh on the final code head; do not manufacture another person's review. Review of this design does not establish runtime security.

W78 assigns a reviewer independent of the implementation author for the reviewed source, records identity/independence, exact SHA, actual attack surface and test environment. Findings include severity, reproduction, affected scope, owner, fix SHA and retest; unanswered required findings block closure. Critical/high security findings cannot be hidden by a green aggregate suite. Any accepted residual risk requires explicit owner disposition and documented limitations before readiness. Dependency, container, secret and supply-chain scans use exact candidate artifacts and pinned configuration; suppressions require source-specific evidence, expiry and review.

No public runtime plugin loading, arbitrary scripting, production chaos or registry visibility change is authorized by this plan. Fault fixtures run only in isolated resources with cleanup and test-only credentials. Published evidence must redact credentials, tokens, raw records and private endpoint details.
