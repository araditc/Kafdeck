# v0.8 Security Boundary — Observability, Automation & Platform APIs

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

## Threat delta

v0.8 adds:

- telemetry export;
- metrics history;
- continuous bounded record monitoring;
- outbound notification providers;
- machine/API clients;
- declarative automation;
- Terraform;
- MCP/agent tools;
- compensation.

These create new exfiltration, SSRF, authority-confusion, cardinality/DoS and background-credential risks.

## Security invariants

### Telemetry confidentiality

Never export/log:

- secrets/tokens;
- raw protected record/generated payloads;
- ksql result rows;
- connector write-only configuration;
- arbitrary provider response bodies;
- unrestricted query/request text.

### Cardinality DoS

Metric/trace/log dimensions are declared/bounded.

Untrusted identifiers cannot create unlimited series.

### Exporter SSRF

OTLP/remote collectors are deployment configured. No request parameter becomes an exporter endpoint.

### Metrics history

Authorization applies to historical resource dimensions just as live views.

History absence/partial coverage is explicit.

### Data-quality

Payload monitoring requires exact record permission. Masking applies before any operator-visible exemplar/diagnostic. v0.8 stores no raw exemplars by default.

### Notification SSRF/exfiltration

Notifier endpoints are configured profiles. Redirects are disabled. Remote credentials are secret references. Payload projection is allowlisted/typed and size/rate bounded.

### Automation confused deputy

CLI/GitOps/Terraform/MCP never acquire stronger authority than their authenticated principal.

Plans do not grant execution authority.

### Approval integrity

CRITICAL operations require existing distinct-principal approval even when initiated by automation.

The initiating automation principal cannot count as the independent approver unless it is genuinely a distinct eligible principal under existing policy; self-approval remains prohibited.

### MCP prompt injection

Provider/topic/record text is untrusted data.

Content returned from Kafka/providers cannot become tool instructions, authorization, scope expansion or approval.

### Declarative ownership attacks

Import/adopt requires exact identity and current-state proof.

A manifest cannot claim ownership of a resource it cannot read/identify under policy.

### Compensation

Compensation does not bypass current-state drift, ambiguity, risk or authorization.

## Secret storage

New provider secrets use existing server-side secret-reference mechanisms. No secret is written to:

- browser storage;
- Terraform state in plaintext where a reference can be used;
- GitOps files;
- MCP tool output;
- telemetry;
- audit diagnostics.

## Audit

Record:

- principal;
- automation/client kind;
- exact action/resource;
- plan/desired-state fingerprint;
- risk/approval;
- provider/destination profile ID;
- effect/result/reason;
- operation correlation.

Do not audit raw protected payloads or secrets.

## Air-gap

Every core v0.8 feature must function with private/local:

- OTel collectors;
- Prometheus;
- historical provider;
- notifier endpoints where configured;
- Git/CI;
- Terraform binaries/providers mirrored by operator process.

No public discovery/service is mandatory.
