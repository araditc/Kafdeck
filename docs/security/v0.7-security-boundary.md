# v0.7 Security Boundary and Threat Delta

Status: **ADMITTED SECURITY BASELINE — W60 VALIDATION ACTIVE**. Authority #178/#180; W51 #181 / PR #191; W60 #190 / PR #202.

This document describes the additional v0.7 threat surface. It inherits all v0.5/v0.6 security boundaries and does not weaken them.

## Assets

- Kafka records and record confidentiality;
- Schema Registry subjects, versions, compatibility policy and references;
- Connect connector configurations, lifecycle state and external-system reach;
- connector/provider credentials and secret references;
- durable mutation/job state, approvals, fencing and remaining budgets;
- generated/reprocessed payloads while in bounded memory;
- ksql query text/result data;
- Streams topology/state-store telemetry;
- lineage provenance/confidence truth;
- audit evidence and release integrity.

## Trust boundaries

v0.7 separates:

1. Browser/UI
2. Kafdeck API
3. Identity/RBAC/policy
4. Durable mutation/job coordinator
5. Typed Schema Registry adapter
6. Typed Connect adapter
7. Kafka record read/produce adapters
8. SerDe adapters
9. ksqlDB adapter
10. registered application/telemetry providers
11. external providers/systems reached by connectors

All provider responses, connector error text, schema names/content, topic names, query output and application telemetry are untrusted data, never instructions.

## Provider origin policy

Remote ecosystem profiles must use explicit validated origins.

Rules:

- no user-supplied absolute provider URL in product requests;
- no arbitrary path forwarding;
- redirects are disabled or restricted to same validated origin according to provider client policy;
- remote basic/bearer auth requires HTTPS;
- TLS server validation is on by default and cannot be silently disabled;
- DNS/IP validation follows deployment/network policy; Kafdeck does not become an SSRF relay to arbitrary internal addresses.

## Secret handling

### Connector/provider credentials

Persistent configuration stores only secret references, not secret bytes.

For connector config fields that require secret values:

- prefer Kafdeck secret references;
- resolve immediately before dispatch;
- bind preview/finalization without exposing a reusable unkeyed digest of low-entropy material;
- clear owned buffers promptly where practical;
- do not log request bodies;
- do not include values in durable operation snapshots;
- do not return them after create/update.

A provider-returned secret-like value is redacted fail-closed even if its key was not present in the original request.

### Schema contents

Schema text is not treated as a credential but can contain organization-sensitive definitions. It is authorized under schema visibility and never written to unrelated logs/telemetry.

### Record/generated/query data

Raw records, generated values and ksql result rows are transient bounded data. Default audit/persistence excludes them.

## Schema Registry security

### Subject/version identity

Subject names are provider identities, not filesystem paths or URL fragments. The adapter performs correct escaping/canonicalization.

### Reference graph

Reference traversal is bounded by:

- maximum nodes;
- maximum depth;
- maximum total schema bytes;
- cycle detection.

No reference can retarget the adapter to a caller-controlled provider origin.

### Permanent delete

Permanent delete is distinct and CRITICAL. The UI/API cannot encode it as a hidden query string on the soft-delete route without the server deriving the stronger action/risk.

## Connect security

### Plugin/class policy

Kafdeck does not assume every installed connector plugin is safe to administer.

Deployment policy controls:

- allowed connector classes/families;
- allowed external endpoint schemes/origins where form schemas expose endpoints;
- allowed transforms/converters/predicates;
- whether unrecognized plugin keys are accepted.

Default posture for unknown plugins is read-only inspection or Blocked mutation until policy/schema evidence exists.

### Configuration redaction

Sensitive keys include:

- provider-reported sensitive fields;
- Kafdeck-known secret key patterns;
- plugin-form secret fields;
- unknown fields matching conservative secret heuristics.

Redaction is server-side. A UI flag is not a security control.

## Automation principal model

Auto-restart effects require current authority at effect time.

Permitted models:

1. requester-bound activation that stops when requester eligibility is lost; or
2. explicitly configured service automation principal with dedicated permissions.

The system cannot synthesize OIDC claims or reuse an expired browser session as permanent automation authority.

Every effect records which principal actually authorized the restart.

## Data-job security

### Cross-cluster identity

Two profile IDs resolving to the same physical cluster cannot be used to bypass cross-cluster policies.

### Masking/export

Byte-preserving replay/forwarding is Blocked when active masking policy requires modification of protected bytes. There is no "raw export bypass" permission.

### Transform policy

Closed transforms cannot make arbitrary network/file/process calls.

### Destination preparation

Data jobs do not silently:

- create topic;
- change topic config;
- change ACL;
- register schema;
- create connector;
- purge destination.

Each such effect would require a separate admitted operation/action.

## Generator security

Production generation is deny-by-default.

Server derives environment policy from deployment/cluster configuration, not a client-provided `environment=dev` string.

Templates are data, not code. Loops/recursion/macros are bounded or unsupported. External URL/file/function resolution is forbidden.

## XML security

XML adapter must disable:

- DTD/external entity resolution;
- external schema/resource fetching;
- arbitrary type activation.

Document depth, attributes, node count and total expansion are bounded.

## ksqlDB security

The v0.7 query classifier rejects ambiguous statements before provider I/O.

At minimum blocked:

- CREATE
- DROP
- ALTER
- INSERT
- TERMINATE
- RUN SCRIPT
- persistent query forms
- multi-statement payloads unless every statement is separately admitted and the contract explicitly supports them.

Comments/whitespace/case/encoding tricks must not bypass classification.

Query text is audit-safe only after length bounding and safe handling; results are not audit content.

## UI security

- no provider secrets in React state beyond the immediate write-only form lifecycle where unavoidable;
- no secret values in URL/query/history;
- no payload or query result persistence in local/session storage;
- mutation controls consume backend preview/risk truth;
- command palette navigates/initiates the same typed routes, never hidden privileged endpoints;
- rendered provider/schema/error text is escaped.

## Telemetry

Metrics/traces/logs must not contain:

- record payloads/keys/headers;
- generated payloads;
- connector secrets;
- provider credentials;
- schema text by default;
- ksql result rows;
- unbounded subject/connector/topic labels that cause cardinality explosion.

Use bounded route/action/provider-kind/state dimensions. Resource identifiers belong in sampled/authorized logs only where existing logging policy permits.

## Security admission blockers

W51 cannot be admitted if planning leaves any of the following ambiguous:

- how Connect secrets are finalized/redacted;
- how provider origins prevent generic proxy/SSRF behavior;
- how MM2 guard applies to new lifecycle paths;
- how automation authority is revalidated;
- how unknown effects prevent blind replay/restart;
- how lifetime budgets survive HA failover/restart;
- how ksql mutation statements are blocked;
- how inferred lineage is prevented from becoming authorization evidence.

This document becomes an active baseline only after protected-main planning admission.
