# v0.6 Cross-Cluster Transfer & Replication Security Model

- **Status:** PROPOSED FOR GOVERNED ADMISSION
- **Authority:** Issue #145 / RFC-0006
- **Tracker:** Issue #146

## Security boundary

Cross-cluster transfer moves Kafka record data across cluster/trust boundaries and is therefore treated as a data-exfiltration-sensitive workflow, not merely a fleet-maintenance operation. Transfer/replication authorization is independent from cluster security administration.

## Required authorization conjunction

Planning and execution evaluate source and destination independently.

For execution, the minimum conjunction is:

```text
source:
  cluster.transfer.execute
  + record.read
  + record.export when bytes leave the source trust boundary

destination:
  cluster.transfer.execute
  + record.produce
```

`cluster.transfer.plan` is required for plan creation. A principal with broker-maintenance, ACL or replication-integration permission does not automatically receive record movement permission.

## Canonical transfer plan

A transfer preview binds:
- source cluster identity,
- destination cluster identity,
- explicit materialized source topic/partition scope,
- explicit destination topic mapping,
- start/end/offset/timestamp semantics,
- record/byte/time/rate/concurrency ceilings,
- masking/export policy reference,
- schema/serialization behavior when supported,
- destination create/overwrite/error policy,
- checkpoint/resume semantics,
- risk decision and expiry.

Wildcard discovery may help select candidates, but the executable plan contains a finite frozen scope.

## Data handling

Record keys, values and headers are streamed through bounded memory buffers and are not stored in `MutationOperation`, progress/checkpoint tables, logs, audit, traces, Problem Details or generic job history.

Safe durable checkpoint data may include source topic/partition/offset, provider token, destination acknowledgement position/count and bounded progress metadata. Checkpoints must not contain raw record bytes.

## Masking and export policy

Where source masking/export policy applies, cross-cluster movement cannot bypass it. The plan records the policy/evidence version used for preview. Policy changes that materially alter admissible data before dispatch/resume invalidate or reauthorize the operation according to the typed workflow.

Kafdeck must not label a transfer as an export-safe path when the active policy forbids export.

## Destination behavior

Destination semantics are explicit in preview. There is no silent topic deletion, purge or overwrite as an implementation convenience. Any destructive destination behavior must be separately typed, authorized and escalated to CRITICAL where applicable.

Automatic topic creation, if ever admitted for a transfer workflow, must use the existing governed `topic.create` path or an explicitly composed plan; `record.produce` does not imply topic administration.

## Budgets and isolation

Every transfer has hard configured ceilings for:
- total/rolling bytes,
- total records where known,
- rate,
- duration,
- concurrent partitions/tasks,
- per-cluster concurrent transfer jobs,
- provider request/response size and deadlines.

Transfer workers run in a dedicated bulkhead so record movement cannot starve metadata visibility or mutation governance.

## Resume and takeover

Resume uses the parent operation identity and current execution fencing generation. After worker crash/lease loss:
- both source and destination authorization are rechecked before resuming,
- safe provider/source checkpoint is observed,
- potentially acknowledged destination writes are not blindly repeated when semantics are ambiguous,
- raw payloads are reacquired from the authorized source rather than loaded from durable staging.

If exact safe resume cannot be established, the operation remains `ExecutionUnknown`/`PartiallyApplied` rather than claiming exactly-once transfer.

## Schema and serialization

Transfer does not introduce arbitrary serializer code. Supported serialization/schema behavior uses Kafdeck-owned controlled adapters. Schema Registry interactions remain separately authorized/capability-gated. Unknown schema/provider behavior fails closed when required for a safe transfer.

## Replication integration

MirrorMaker 2/provider replication is a control-plane integration, not the transfer worker itself. Kafdeck may inspect and govern tested replication topology/config/status through fixed adapters. It does not accept arbitrary Connect/provider REST calls or create a general replication scripting surface.

Replication topology mutation risk is HIGH by default and CRITICAL when blast radius/topology/destructive behavior crosses server thresholds.

## Audit

Audit records only safe control-plane evidence:
- operation ID,
- actor/approver,
- source/destination cluster IDs,
- materialized topic mapping summary,
- budget/policy identifiers,
- risk decision,
- dispatch/progress/final outcome,
- checkpoint identifiers where safe.

Payload content and credentials are excluded.

## Failure semantics

- source read denied/capability unavailable before dispatch => definitive pre-dispatch failure,
- destination reject with explicit non-application => definitive per-target failure,
- timeout after possible destination acknowledgement => unknown for that target unless readback/evidence establishes state,
- mixed target outcomes => `PartiallyApplied`,
- inability to establish safe resume => no blind restart from the beginning.

Kafdeck makes no exactly-once claim across independent Kafka clusters unless a future provider-specific contract can actually prove it and is separately governed.

## Mandatory negative tests

- transfer permission without source record read,
- export-required source without `record.export`,
- destination without `record.produce`,
- broad wildcard scope above materialization limit,
- masking/export policy bypass attempt,
- raw payload sentinel appears in persistence/log/audit,
- destination timeout after dispatch followed by attempted blind retry,
- stale worker resumes after lease takeover,
- provider replication endpoint redirect/origin escape,
- arbitrary serializer/provider command injection.
