# v0.2 Identity/RBAC Security Boundary

- **Status:** PROPOSED
- **RFC:** RFC-0002
- **Scope authority:** Issue #57

## Trust boundaries

v0.2 adds two material boundaries to the v0.1 model:

1. browser/operator to Kafdeck authenticated session,
2. Kafdeck to configured OIDC identity provider.

Existing boundaries remain:

3. Kafdeck to Kafka,
4. Kafdeck to secret sources,
5. Kafdeck to telemetry/audit sinks.

## Security invariants

- identity is issuer + subject, never email/display name,
- authorization is default-deny,
- deployment token is not operator identity,
- OIDC mode cannot fall back to deployment-token RBAC bypass,
- OIDC access/refresh tokens never enter browser storage,
- backend authorization is authoritative,
- policy cache/session cache never leaks permissions across identities,
- Kafka adapter remains read-only,
- no payload path is introduced.

## OIDC threats and controls

### Authorization-code interception

Controls: Authorization Code + PKCE, TLS, exact redirect URI.

### Login CSRF / response injection

Controls: state and nonce validation, correlation protection and bounded callback lifetime.

### Forged identity token

Controls: issuer, audience, signature/JWKS, expiry/not-before and algorithm validation.

### OIDC mix-up / wrong issuer

Controls: one explicit configured issuer per provider profile; issuer is part of canonical identity.

### Claim injection or ambiguous mapping

Controls: explicit configured claim names and exact Kafdeck mappings. Unknown claims grant nothing.

### Group overage / oversized claims

Controls: bounded claim count/size. Ambiguous or incomplete authorization claims fail closed.

### Session theft

Controls: HttpOnly cookie, Secure HTTPS posture, bounded lifetime, session rotation, no tokens in JavaScript-accessible storage.

### Session fixation

Controls: issue a new authenticated session after successful OIDC callback; never upgrade an attacker-supplied session identifier.

### CSRF on authenticated endpoints

v0.2 remains read-only, but authenticated application/session endpoints still apply accepted anti-CSRF protections where cookies authorize requests.

### Open redirect

Redirect targets are local/allow-listed. User-controlled arbitrary callback/return URLs are rejected.

## RBAC threats and controls

### Privilege escalation through external role names

External roles/groups are never accepted as Kafdeck permissions directly. They map through explicit configuration.

### Missing policy

Missing/invalid policy fails closed.

### Resource-enumeration leakage

Unauthorized requests do not include protected Kafka metadata in error responses.

### Cache confusion

All protected cache projections include authorization context or are filtered after authoritative policy evaluation before response construction.

### UI-only enforcement

Prohibited. Every protected endpoint is server-authorized.

### Wildcard explosion

Resource globs are bounded deterministic patterns; no unbounded regex engine is required for v0.2.

## Legacy Token mode risk

Token mode is retained only for compatibility.

Controls:

- clearly identified as non-human identity mode,
- cannot satisfy OIDC/RBAC authorization in OIDC mode,
- token material remains secret-referenced,
- remote token mode retains v0.1 fail-closed exposure rules,
- security audit records remote legacy-token operation.

## Audit requirements

Security audit events include:

- timestamp,
- event type,
- canonical operator identity or explicit legacy/deployment principal,
- session correlation identifier,
- Kafdeck cluster/resource scope when applicable,
- authorization outcome,
- reason category.

Never audit:

- OIDC access/refresh/id tokens,
- session cookie,
- deployment token,
- Kafka SASL password/private-key password.

## Secret handling

OIDC client secrets, when required, use existing environment/file secret-reference mechanisms.

No OIDC client secret is returned through API/UI.

## Threat-model exit gate

Implementation cannot complete until tests demonstrate:

- invalid OIDC cryptographic/protocol input fails closed,
- authorization bypass attempts fail,
- cluster/resource isolation is preserved,
- legacy mode cannot bypass OIDC mode,
- session/token values are absent from logs/browser storage,
- Kafka mutation/payload routes remain absent.
