# English/Persian product copy and accessibility contributions (W79)

English is authoritative. This implementation targets [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/); a source change or automated scan does not establish conformance. Acceptance requires the real keyboard, screen-reader, contrast, reflow and governance journeys recorded by the W79 evidence producer. See [the acceptance strategy](../testing/v0.9-test-strategy.md). Record failures, assistive-technology/browser versions and limitations; do not describe unexecuted manual scenarios as passed.

## Resources and review

`src/frontend/src/shared/locales/en.json` is the source-copy catalog. Its English text keys intentionally match application-owned message literals. `fa.json` contains corresponding Persian plain text. Run `node src/frontend/src/shared/locales/generate.mjs` from the repository root after editing them; this validates key/placeholder parity and creates the dependency-free runtime `messages.ts`. The frontend localization regressions verify the generated copy, every source `t("literal")` call and dynamically rendered command/status descriptors. Preserve matching keys when revising English copy. Brand names, protocol/format names and executable examples may be identical in both catalogs.

Add new UI copy through a literal `t("English copy")` in the render path or a UI helper. Render application-owned descriptors through `t` too: initializing a module-level descriptor alone cannot react to a later locale change. Never pass arbitrary backend prose, user metadata, record data, policy source or approval material through the translation lookup. There is no DOM text traversal, backend substring replacement or HTML translation rendering. Backend capability reasons, API error/state codes and frozen evidence retain their authoritative representation; explain them with separately translated application guidance. Metadata authored by users retains its original text.

A Persian-speaking reviewer should review new translations alongside English for meaning, natural reading order and operator safety. Pay particular attention to the distinction between confirmation (تصدیق), independent approval (تأیید مستقل), business approval, execution and verified completion. Replan must require a new operation/revision and new decisions; unknown must prohibit blind replay. Translation review must not turn absence of evidence into success. Community contributors should include screenshots in both themes and record keyboard and screen-reader results for changed surfaces. Maintainer review is required before accepting a translation; fallback English is preferable to an unreviewed claim.

## Direction, data and interpolation

The language selector defaults to English and persists only `kafdeck.locale.v1` (`en` or `fa`). Unrecognized values and unavailable preference storage fall back to English. Cross-tab language updates touch only that preference; they never recover an operator session, restore credentials, acquire authority, issue a mutation or reset a mounted review. Locale is absent from operator/scope/operation component keys and confirmation dependencies.

`setLocale` sets the document's explicit `lang` and `dir`; component rendering updates without replacing the tree. Human text fields use automatic direction. Machine editors and exact challenges use LTR; IDs, hashes, states and machine evidence use isolated LTR markup. Unknown-direction user text uses `bdi dir="auto"`. Follow [W3C inline bidirectional markup guidance](https://www.w3.org/International/articles/inline-bidi-markup/) and logical CSS (`margin-inline`, `padding-block`, `inset-inline-end`). Do not reverse strings or insert directional controls into stored values.

Use indexed plain-text interpolation, for example `t("Duplicate key: {0}", [key])`. React escapes the result. Persian interpolation isolates inserted values; English keeps existing labels unchanged. Preserve placeholder indices. Do not use HTML, `dangerouslySetInnerHTML`, translated selectors/URLs or translated API enum values. Every translated option has an explicit original `value`. Do not localize amounts, decimal separators, units, UTC timestamps, resource identifiers, risk/state codes, policy code, content hashes, confirmation challenges or frozen approval documents. Their exact machine representation remains authoritative. Translated labels can describe invariant data without altering it.

## Accessibility checks for changes

Use semantic headings, native controls, explicit or wrapping labels, column/row table headers and status/error announcements. A table that overflows must be reachable and scrollable with a keyboard. Keep focus visible in both themes and forced colors, and ensure wrapping/sticky UI cannot obscure it. The skip link targets the focusable main region. The command dialog traps focus, makes background branches inert, closes with Escape and restores the trigger; navigation commands instead focus their actual destination. New immutable operation material moves focus to its review heading; refreshing the same material or switching languages preserves focus and confirmation state.

Exercise catalog → inspect/edit → preview → exact confirmation → distinct eligible approval; draft → submit → approve/reject; changed policy/material → explicit replan; and unknown → inspect evidence/receipt without redispatch. Repeat in Persian, with keyboard only, at narrow widths and zoom, and across scope/session changes. Confirm that locale changes preserve text input/focus but never preserve an authorized panel after its session is invalidated or transfer approval to changed material. Automated accessibility findings and static/SSR regressions supplement these real journeys.

On window return, private content is hidden and inert until the actual session endpoint verifies it. Its additive `sessionScope` field is an opaque UI cache boundary derived from the authenticated subject, session instance and authorization policy/groups; it is never an authentication credential or authorization grant. An unchanged valid scope preserves mounted review state and restores connected focus. A changed, missing or denied scope discards private state; older servers without this field conservatively remount it. Late read responses from an earlier scope cannot restore its observations. Initial Local/Token read-only operation still uses independently authorized read responses.
