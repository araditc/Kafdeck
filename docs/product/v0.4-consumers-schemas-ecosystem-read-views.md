# v0.4 Product Specification — Consumers, Schemas & Ecosystem Read Views

- **Status:** PROPOSED
- **RFC:** RFC-0004
- **Scope authority:** Issue #99
- **Tracker:** Issue #100

## User outcome

An authorized operator can understand consumer health, lag, schemas and configured Kafka ecosystem components from one read-only control plane without receiving mutation capability.

## Product surfaces

### Consumers

List and inspect groups, members, assignments, committed offsets, current end offsets and lag.

Show explicit limitation states when:
- group/topic permission is incomplete,
- committed offset is missing,
- partition metadata changed,
- an upstream call timed out,
- a result is partial.

Diagnostics distinguish observation from interpretation. "Stalled" requires evidence such as stable lag growth / no committed progress across a valid observation window; without history it is not asserted.

### Schemas

Browse subjects and versions, inspect type/ID/references/content, compare two versions, and inspect compatibility configuration/results that can be obtained read-only.

No schema lifecycle action is exposed.

### Kafka Connect

When configured, view Connect identity, connectors, connector status and tasks. Secret-like connector config fields are redacted before response.

No pause/resume/restart/update/delete action exists.

### ksqlDB

When configured, show safe discovery/metadata only. There is no SQL editor or arbitrary statement endpoint.

### Topic catalog

Show configuration-owned topic description, owner/team, domain, tags, documentation reference and classification labels.

Catalog metadata does not grant access.

## Authorization

New actions:
- `consumer.read`
- `schema.read`
- `connect.read`
- `ksql.read`
- `catalog.read`

All are independent of `record.read` and `record.export`.

## Product truthfulness rules

- Unknown is not zero.
- Unavailable metrics are not estimated.
- Current observation is not presented as historical evidence.
- A provider capability is not claimed merely because its URL is configured.
- Partial authorization is surfaced rather than silently presenting an apparently complete view.

## Acceptance scenarios

1. Metadata-only user without `consumer.read` cannot list groups.
2. Consumer permission for one group pattern does not expose other groups.
3. Lag is calculated only from explicit committed/end offsets and handles missing offsets safely.
4. No v0.4 consumer path commits or alters offsets.
5. Schema subject/version access is separately authorized.
6. Schema diff is local/bounded and does not mutate registry compatibility settings.
7. Connect config secrets are redacted and raw upstream responses are never passed through.
8. Connect mutation endpoints do not exist.
9. ksqlDB arbitrary SQL cannot be submitted.
10. Catalog metadata does not imply topic/record permission.
11. Missing metrics/history return explicit unavailable states.
12. Slow ecosystem endpoints do not starve Cluster Explorer or Record Explorer.
13. v0.1-v0.3 behaviors remain compatible.
