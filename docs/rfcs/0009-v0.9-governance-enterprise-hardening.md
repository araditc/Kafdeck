## Problem and outcome

Operators need attributable ownership, requests, approval and explainable policy across the same safe execution plane already used by UI, REST, CLI, Terraform and MCP. Enterprise operation also requires measured attribution, accessible localized journeys, repeatable recovery, distributions and independently reviewed security/performance evidence. All Roadmap v0.9 themes remain in W73–W82; none is silently deferred.

## Decisions proposed for admission

1. Keep the modular monolith and existing identity, RBAC, mutation kernel, persistence providers and audit authority. Descriptive ownership and business approval never grant effect rights.
2. Add bounded catalog, request, closed policy and attribution contracts through application ports. [ADR-0010](../adr/0010-governance-effect-boundary.md) fixes effect-time gating, transaction ownership and recovery semantics.
3. Enforce active policy and request requirements at the shared effect boundary, including existing direct routes. Feature-disabled behavior retains v0.8 contract/fingerprint compatibility. Enabling governance cannot create an alternate privileged client.
4. Store metadata, revisions, policy decisions and measured aggregates, never protected record payloads, credential material or arbitrary executable policy. Fail closed when active governance authority cannot be read.
5. Treat observed, estimated, incomplete, stale, unknown and unsupported attribution distinctly. Versioned rate cards provide estimates, not financial settlement or an authoritative invoice.
6. Target WCAG 2.2 AA, English/Persian/RTL, actual supported native distributions and real Helm lifecycle; admit numerical performance budgets only from measured evidence.

## Compatibility and exclusions

New routes and storage are additive; existing persisted action/operation/state enum values are never renumbered or aliased. Existing unsupported provider capabilities remain unsupported until tested. No public runtime plugin loader/SDK, new privileged plane, arbitrary SQL/shell/provider proxy, production chaos, payments, mandatory SaaS/gateway or production deployment is admitted. Registry visibility remains unchanged. v1.0 stability is not promised here.
