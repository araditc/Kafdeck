# v0.4 Authorization Matrix

- **Status:** PROPOSED
- **RFC:** RFC-0004

| Surface | Required action | Resource scope | Does not imply |
|---|---|---|---|
| Consumer group list/detail/offsets | `consumer.read` | cluster + group pattern | `record.read`, offset mutation |
| Schema subject list/detail/version/diff | `schema.read` | cluster + subject pattern | record access, schema mutation |
| Kafka Connect list/detail/status/tasks | `connect.read` | cluster + connector pattern | connector mutation |
| ksqlDB metadata | `ksql.read` | cluster + metadata resource | SQL/query execution |
| Topic catalog metadata | `catalog.read` | cluster + topic pattern | `topic.read`, `record.read` |
| Record Explorer (existing) | `record.read` | cluster + topic | any v0.4 action |
| Record export (existing) | `record.export` | cluster + topic | any v0.4 action |

## Rules

1. Authorization executes before upstream I/O when the resource is known.
2. Collection endpoints filter/project only authorized resources and do not leak hidden names through counts/errors.
3. Detail routes re-authorize directly and do not rely on a prior list response.
4. Provider/Kafka ACL denial is distinct from Kafdeck RBAC denial.
5. Catalog metadata is descriptive and cannot be used as an authorization binding.
6. No v0.4 permission bypasses v0.3 masking.
