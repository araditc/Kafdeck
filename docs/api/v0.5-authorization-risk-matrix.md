# v0.5 Authorization and Risk Matrix

- **Status:** PROPOSED FOR GOVERNED ADMISSION
- **RFC:** RFC-0005
- **Scope authority:** Issue #121

The table defines **minimum** built-in risk. Deployment policy may raise risk or add approval; it may not lower these floors.

| Operation | Authorization action | Resource | Risk floor | Confirmation / approval |
| --- | --- | --- | --- | --- |
| Create topic | `topic.create` | new topic name | LOW | same-actor confirm |
| Alter topic config | `topic.alter` | topic | MODERATE | same-actor confirm; risk may escalate by key/value |
| Increase partitions | `topic.alter` | topic | HIGH | typed target confirm; optional independent approval by policy |
| Delete topic | `topic.delete` | topic | CRITICAL | typed target confirm + independent approval |
| Produce records | `record.produce` | topic | MODERATE | same-actor confirm; bounded batch |
| Alter/reset offsets | `consumer.offset.alter` | consumer group + topics | HIGH | typed target confirm; optional independent approval by policy |
| Delete group/offsets | `consumer.delete` | consumer group | HIGH | typed target confirm; optional independent approval by policy |
| Register schema/version | `schema.create` | subject | MODERATE | same-actor confirm |
| Alter compatibility | `schema.alter` | subject/global scope | HIGH | typed target confirm; optional independent approval by policy |
| Delete schema | `schema.delete` | subject/version | HIGH | typed target confirm; hard/permanent delete -> CRITICAL + independent approval |
| Create connector | `connect.create` | connector | MODERATE | same-actor confirm |
| Update connector | `connect.alter` | connector | MODERATE | same-actor confirm; secret-safe diff |
| Pause/resume/restart | `connect.alter` | connector/task | MODERATE | same-actor confirm |
| Delete connector | `connect.delete` | connector | HIGH | typed target confirm; optional independent approval by policy |
| Purge/truncate records | `records.purge` | topic partitions | CRITICAL | typed target confirm + independent approval |

## Risk escalation rules

At minimum:
- bulk/multiple targets may raise risk one class,
- any included CRITICAL target makes the overall operation CRITICAL,
- permanent deletion raises to CRITICAL,
- topic configuration keys affecting durability/data-loss exposure may raise to HIGH,
- configured blast-radius thresholds may raise risk,
- provider ambiguity never lowers risk.

## Authorization evaluation

Authorization is evaluated:
1. at preview creation for every concrete resource,
2. at confirmation/approval transition as applicable,
3. immediately before dispatch.

A user losing permission after preview cannot execute using an old preview.

## Independent approval

An independent approver:
- must be a distinct canonical principal,
- must satisfy the operation's approval authorization policy,
- sees the immutable preview,
- cannot alter the intent while approving,
- may reject with a bounded reason,
- approval expires with preview.

CRITICAL actions are unavailable when Kafdeck cannot establish this property.

## Bulk requests

Bulk operations:
- materialize targets before preview,
- authorize every target,
- enforce finite target limits,
- expose per-target current/target state,
- compute risk from the maximum target risk plus bulk escalation,
- never silently skip unauthorized targets and execute the rest unless a typed contract explicitly declares partial behavior.

## Configuration-key risk

Topic/connector/schema configuration is not accepted as an arbitrary key/value escape hatch.

Implementation defines typed/allowlisted keys/capabilities. Risk policy can map specific keys/value deltas to higher classes.

Unknown writable keys are Unsupported rather than “MODERATE by default”.
