# v0.7 API, OpenAPI and UI Contract Plan

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**. Authority #178/#180; W51 #181.

v0.7 keeps the public product API under `/api/v1` and adds versioned release OpenAPI evidence for the v0.7 capability set. Existing released routes remain backward compatible unless a separately approved compatibility decision says otherwise.

## Contract principles

- backend authorization/capability/risk truth is authoritative;
- mutation/execution requests never supply their own risk class or permission list;
- non-GET browser routes use the existing authentication/authorization/antiforgery boundary;
- every external-effect route returns/links a durable operation identity;
- provider capability states remain explicit;
- no generic provider URL, method, path or arbitrary SQL/command fields;
- secrets are write-only/server-resolved;
- errors use safe Problem Details semantics and stable Kafdeck error codes;
- large result sets and query/job outputs are bounded/paginated.

## Schema Registry routes

Existing read routes remain:

```http
GET /api/v1/clusters/{clusterId}/schemas/subjects
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions/{version}
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/compatibility
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/diff
```

Proposed v0.7 lifecycle routes:

```http
POST   /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions/preview
POST   /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions
PUT    /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/compatibility/preview
PUT    /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/compatibility
DELETE /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions/{version}/preview
DELETE /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions/{version}
DELETE /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/preview
DELETE /api/v1/clusters/{clusterId}/schemas/subjects/{subject}
POST   /api/v1/clusters/{clusterId}/schemas/compatibility/check
GET    /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/references
POST   /api/v1/clusters/{clusterId}/schemas/mock
```

Permanent delete is represented by a distinct typed intent in the request/preview contract and server-derived stronger action/risk. If route-level separation is clearer during implementation review, W52 may use an explicit `/permanent-delete` route; it may not hide permanent deletion behind an unvalidated provider query flag.

### Schema registration request

Conceptual shape:

```json
{
  "schemaType": "Avro",
  "schema": "{...}",
  "references": [
    { "name": "common.avsc", "subject": "common-value", "version": 3 }
  ],
  "idempotencyKey": "client-stable-id"
}
```

Provider credentials are never accepted in this body.

### Connector config shape

The public contract distinguishes:

- normal config values;
- secret references;
- write-only secret values only where a provider/plugin cannot use references directly.

Conceptual:

```json
{
  "connectorClass": "com.example.SafeConnector",
  "config": {
    "topics": { "value": "orders" },
    "api.password": { "secretRef": "env:CONNECT_API_PASSWORD" }
  }
}
```

A read response never returns the secret value.

## Data-job routes

Replay/reprocess/forwarding use a typed job family:

```http
POST /api/v1/data-jobs/replay/preview
POST /api/v1/data-jobs/replay

POST /api/v1/data-jobs/forward/preview
POST /api/v1/data-jobs/forward

GET  /api/v1/data-jobs/{operationId}
POST /api/v1/data-jobs/{operationId}/cancel
POST /api/v1/data-jobs/{operationId}/reconcile
```

Conceptual plan request:

```json
{
  "source": {
    "clusterId": "prod-a",
    "topic": "orders.dlq",
    "partitions": [
      { "partition": 0, "startOffset": 1000, "endOffset": 2000 }
    ]
  },
  "destination": {
    "clusterId": "prod-b",
    "topic": "orders.replay",
    "partitionStrategy": "Preserve"
  },
  "transform": { "kind": "BytePreserving" },
  "limits": {
    "maxRecords": 100000,
    "maxBytes": 104857600,
    "maxRecordsPerSecond": 1000,
    "maxBytesPerSecond": 1048576,
    "maxDurationSeconds": 1800
  }
}
```

Server applies the minimum of request, deployment policy and hard planning caps. Omitting a limit never means unlimited.

## SerDe tooling routes

Read-oriented local tooling may be exposed as:

```http
POST /api/v1/tools/serde/decode
POST /api/v1/tools/serde/encode
GET  /api/v1/tools/serde/capabilities
```

These routes are bounded and do not forward requests to arbitrary providers. When operating on protected Kafka record data, ordinary record authorization remains required by the calling workflow.

## ksqlDB routes

Existing metadata routes remain.

New bounded query route:

```http
POST /api/v1/clusters/{clusterId}/ksql/query
```

Request:

```json
{
  "statement": "SELECT ...",
  "limits": {
    "maxRows": 1000,
    "maxBytes": 2097152,
    "maxDurationSeconds": 30
  }
}
```

The server classifies the statement before provider I/O. Persistent query/DDL/DML is rejected with a stable blocked/unsupported problem code.

There is no generic `/ksql/proxy` or caller-controlled provider path.

## Operation response

Side-effecting routes return an operation representation rather than provider-specific raw content.

Conceptual:

```json
{
  "operationId": "01...",
  "state": "AwaitingApproval",
  "risk": "Critical",
  "previewHash": "...",
  "requiredApprovals": 1,
  "expiresAt": "...",
  "limitations": []
}
```

Secrets and raw provider request/response bodies are absent.

## OpenAPI

W52–W60 update a checked-in `docs/api/openapi-v0.7.json` and runtime versioned route. CI must verify:

- deterministic output;
- no undocumented mutation route;
- no generic provider proxy route;
- all non-GET product routes carry security/antiforgery expectations;
- secret fields are write-only where represented;
- bounded limit schemas;
- v0.6 released routes remain compatible unless explicitly versioned.

## UI contract

The UI uses only the same versioned backend routes.

Required patterns:

- profile selector never changes backend authorization context implicitly;
- mutation controls render backend preview/risk;
- secret form controls clear after submission;
- job progress uses durable counters, not client-estimated success;
- ambiguous/blocked/unsupported states are visually explicit;
- command palette is navigation/action discovery only and cannot bypass previews or approval;
- pagination/virtualization for large collections;
- no secret/query-result/record payload local storage.

## Contract admission

This plan is not a public API promise until implementation is merged/released. It is the W51 planning boundary from which W52–W60 must not materially depart without reviewed scope/contract change.
