# v0.9 proposed API, authorization and client contract

Status: admitted W72 design; released v0.8 does not contain these additions. [W73/W75 implementation contracts](v0.9-catalog-policy-runtime.md) and [W74/W76 implementation contracts](v0.9-requests-attribution-runtime.md) describe the additive runtime. Exact acceptance is tracked in #427–#430. New families use `/api/v1/governance`; generated discovery is `GET /api/v1/openapi/v0.9-governance.json` under SystemRead and existing `v0.8-bearer.json` remains unchanged. Persisted enum values are preserved; no release/version promotion is inferred.

Request submission references an existing operation; it does not clone material or supply arbitrary raw effect commands. Execution uses existing mutation endpoints and the shared gate. A business decision cannot act as a distinct critical approval unless it is recorded through the existing eligible approval contract against that exact operation; UI must show both requirements separately. Catalog team membership is not an authorization role. Policy management does not grant activation/effect rights. Import/rate-card/policy writes use the existing preview/confirm/idempotency/audit contract rather than plain ungoverned CRUD.

Terraform/MCP retain existing supported declarative/product families. All their underlying effects, automation identities and direct routes obey the new shared gate. New governance management families are UI/REST/CLI parity scope; no unreviewed Terraform resource or model-driven policy activation is implied. Tests must explicitly cover legacy client bypass attempts.

## Wire semantics and finite ceilings

- JSON, exact scope/resource IDs, server-issued IDs, UTC ISO-8601 and invariant decimal strings for monetary quantities. No locale-dependent parsing, secrets or payload fields.
- Lists default 50/max 200, opaque signed scope/filter-bound cursor, stable ID ordering, no arbitrary sort/query language. Caller filters narrow authorized scope before aggregate/count calculation.
- Policy versions have a public capacity of 10,000 immutable versions per cluster, including staged drafts; capacity is checked in the owning write transaction and returns `409 PolicyVersionCapacityExceeded` without eviction. Version pagination streams at most that capacity, retains only page size plus one authorized records, and issues a continuation only when another authorized version exists. Hidden rows cannot create empty pages or a continuation after the final visible record.
- Common body max 256 KiB; import max 1 MiB/500 records, tags max 20 × 64 chars, names 128 chars, descriptions/reasons 2,048 chars, documentation reference 2,048 chars (safe HTTPS/reference text, never server-fetched). Reject control characters/unsafe schemes and render as escaped text.
- Attribution query max 31 days, window minimum 1 minute, max 500 windows/response; explicit continuation and coverage, no silent truncation. Aggregate retention default 90 days/configured max 366; catalog/policy/request audit follows existing operator-governed retention, never eviction of unresolved evidence.
- Mutations require idempotency key scoped to actor/operation/material, expected revision and current auth. Duplicate exact request returns the same durable result; changed material conflicts. Bounded dispatch/timeout/cancellation never assert rollback after dispatch.
- Stable codes: `GovernanceDenied`, `GovernanceUnavailable`, `PolicyVersionConflict`, `RequestApprovalRequired`, `RequestNeedsReplan`, `ScopeDenied`, `EvidenceIncomplete`, `MeasurementStale`, `AttributionUnsupported`; reuse existing kernel unknown/stale codes where applicable. 400 invalid, 403 denied, 404 invisible/missing without existence oracle, 409 version/material/stale conflict, 413 bound exceeded, 429 throttled, 503 authority unavailable. Error contains code/correlation ID and bounded safe details, never hidden policy/resources or stack traces.

Implementation must generate actual OpenAPI and CLI help, add action-to-scope/risk/client parity tests, negative cross-scope fixtures, action-enum persistence tests and capability-map updates before claiming support. No proposed route is added to released v0.8 OpenAPI during W72.
