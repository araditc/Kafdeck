New effect request DTOs are closed to unknown fields; callers cannot supply a
requester, alternate provider command or authorization context. The bearer
boundary limits new effect bodies to 64 KiB before JSON binding. Typed topic
configuration keys are restricted by the existing backend planner. Create and
alter have repeated unique closed `--config key=value` options; alter alone has
`--reset-config key`. All nine keys retain backend semantic/provider validation.
Partition counts align the backend's 1–100000 bound. New previews, cancel and
reject remain exact named routes, not a generic operation-kind or JSON interface.

The CLI retains typed JSON and stable exits for approval (`6`), executing/unknown
effect (`7`), conflict/stale preview (`8`), expiry (`9`) and partial/unverified
effect (`10`). These are never turned into an automatic execute retry. A 200
status response containing `executionUnknown` does not mean the effect succeeded.
An intentional cancel/reject command returning its requested Cancelled/Rejected
state is exit 0, while later generic status of those negative effect outcomes
remains exit 4. Invalid stop transitions and hashes still conflict.

Remaining API/CLI scope includes complete UI read inventory and pagination;
machine token acquisition lifecycle acceptance; other mutation families; typed
approval/cancel/reject lifecycle acceptance; provider capability/error
parity; HA/restart/rotation/revocation and durable ambiguous-effect acceptance.
Deployment access tokens remain limited to the legacy read commands. A manifest,
tool prompt, plan file or CLI argument never grants backend authority.

Local evidence for both new SQLite/PostgreSQL topic verticals is recorded in
`../implementation/v0.8-w67-topic-lifecycle-evidence.md`. It does not establish
DB primary failover, restore resumption, actual delete or the whole A4/A5 scope.

The selected human/service and CRITICAL Linux baseline is integrated on

evidence is reconciled in the acceptance ledger. The new topic/lifecycle

checks. All remaining 26 engine families and full A1–A6 acceptance remain open.
