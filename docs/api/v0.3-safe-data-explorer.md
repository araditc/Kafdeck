# v0.3 Safe Data Explorer API

Status: implementation candidate for W23.

The v0.3 record surface is read-only and is intentionally separate from the v0.1 metadata API. All routes are `GET`; Kafdeck exposes no producer, replay, offset-commit, consumer-group mutation, payload-persistence, or unbounded-scan endpoint.

## Authorization

Record browsing and live tail require the existing cluster/topic visibility permissions plus `record.read`. Export additionally requires `record.export`. Backend authorization is authoritative; hiding a UI control is never the security boundary. Kafka ACL denial remains distinguishable from Kafdeck RBAC denial.

## Routes

- `GET /api/v1/clusters/{clusterId}/topics/{topicName}/partitions/{partition}/records` — bounded page navigation by earliest/latest, offset, or timestamp anchor. Supports bounded pre-filters and deterministic CEL/jq-style structured filters.
- `GET .../records/tail` — bounded server-sent-event live tail. Disconnect propagates cancellation; admission, duration, records, bytes, and rate are bounded.
- `GET .../records/export` — bounded JSON, NDJSON, or CSV export. Export consumes the same already-authorized and already-masked projection used by the browser path.

The normative machine-readable contract is `docs/api/openapi-v0.3.json`.

## Masking boundary

Payload bytes are never returned directly from the Kafka adapter. The runtime path is record read → optional bounded schema decode → bounded filter → authoritative server-side masking → safe projection → API/UI/export. When configured structured masking requires decode and safe decode is unavailable, the record remains visible only as a fully-redacted projection rather than leaking clear raw bytes or silently bypassing policy.

Raw text/hex UI views are therefore available only when the safe projection still contains raw bytes. An active structured masking policy suppresses those raw bytes before they reach the browser.

## Budgets and partial results

Client-provided `maxRecords` and `maxBytes` remain constrained by server hard caps. Page responses expose read/filter budget outcomes and limitations. Live tail and export have their own additional server-side bounds. Budget exhaustion is explicit and is not presented as an exhaustive scan.

## Schema Registry

Schema Registry integration is read-only and exists only to decode authorized records for Avro, Protobuf, and JSON Schema. v0.3 does not expose general Schema Registry browsing or mutation.
