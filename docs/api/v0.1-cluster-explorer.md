# v0.1 REST API Contract — Cluster Explorer

- **Status:** PROPOSED
- **Base path:** `/api/v1`
- **Specification:** OpenAPI 3.1
- **Errors:** RFC 9457 Problem Details semantics

## Contract rules

- v0.1 product APIs are read-only.
- Product routes use GET/HEAD only.
- Runtime access/bootstrap endpoints may use the minimum methods required for access-token UX, but MUST NOT mutate Kafka or cluster definitions.
- Cluster IDs are stable Kafdeck configuration identifiers.
- Topic names are encoded as URL path segments.
- Collection endpoints are bounded.
- Every Kafka-derived response includes observation/freshness metadata or a parent envelope that does.
- Missing capability/authorization is not represented as a misleading empty value.

## Endpoints

### System

```http
GET /api/v1/system/info
GET /api/v1/system/health
```

### Clusters

```http
GET /api/v1/clusters
GET /api/v1/clusters/{clusterId}
GET /api/v1/clusters/{clusterId}/health
GET /api/v1/clusters/{clusterId}/capabilities
```

### Brokers

```http
GET /api/v1/clusters/{clusterId}/brokers
GET /api/v1/clusters/{clusterId}/brokers/{brokerId}
GET /api/v1/clusters/{clusterId}/brokers/{brokerId}/configuration
```

### Topics

```http
GET /api/v1/clusters/{clusterId}/topics?q={query}&cursor={cursor}&pageSize={n}
GET /api/v1/clusters/{clusterId}/topics/{topicName}
GET /api/v1/clusters/{clusterId}/topics/{topicName}/partitions
GET /api/v1/clusters/{clusterId}/topics/{topicName}/configuration
```

No POST/PUT/PATCH/DELETE Kafka administration endpoint is permitted in v0.1.

## Common observation envelope

Conceptual shape:

```json
{
  "data": {},
  "observation": {
    "observedAt": "2026-09-16T05:00:00Z",
    "freshness": "fresh",
    "cacheAgeMs": 1250,
    "partial": false
  },
  "limitations": []
}
```

`freshness` values:

- `fresh`
- `stale`

## Capability response

```json
{
  "data": {
    "clusterMetadataRead": "available",
    "topicListRead": "available",
    "topicMetadataRead": "available",
    "topicConfigRead": "denied",
    "brokerConfigRead": "unknown"
  }
}
```

Capability values:

- `available`
- `denied`
- `unsupported`
- `unknown`
- `temporarilyUnavailable`

## Topic page

Conceptual shape:

```json
{
  "data": {
    "items": [
      {
        "name": "payments.events",
        "partitionCount": 12,
        "offlinePartitionCount": 0,
        "underReplicatedPartitionCount": 1,
        "state": "degraded"
      }
    ],
    "nextCursor": "opaque-value"
  },
  "observation": {
    "observedAt": "2026-09-16T05:00:00Z",
    "freshness": "fresh",
    "cacheAgeMs": 1800,
    "partial": false
  },
  "limitations": []
}
```

Cursors are opaque to clients and do not encode security-sensitive state.

## Topic detail

Includes:

- name,
- partition count,
- partition anomaly summary,
- internal flag if reliably observable,
- observation metadata.

Partition detail includes:

- partition ID,
- leader broker ID or null when no leader is present,
- replica broker IDs,
- ISR broker IDs,
- anomaly reasons.

## Errors

Representative problem types:

- invalid-cluster-id
- cluster-unavailable
- authentication-failed
- authorization-denied
- tls-validation-failed
- invalid-cluster-configuration
- operation-timeout
- unsupported-capability
- invalid-page-size

A request for a specifically protected resource, such as broker configuration, can return authorization-denied. A broader cluster overview should prefer safe partial results when independent metadata is available.

## Headers

Recommended response headers:

- `X-Kafdeck-Observed-At`
- `X-Kafdeck-Freshness`
- standard correlation/trace headers through OpenTelemetry/W3C trace context.

Headers are supplementary; clients must not depend on headers when the contract already carries observation state.
