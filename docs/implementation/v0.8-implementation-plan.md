# v0.8 Implementation Plan — W61 to W71

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

Scope #208; tracker #209; W61 #210.

W62–W71 are blocked until W61 protected-main admission.

## Global rules

Every workstream:

- starts from latest protected main;
- uses DCO/conventional commits;
- requires exact-head CI/review;
- uses expected-head guarded merge;
- preserves server-authoritative RBAC/risk/approval/audit;
- preserves capability truth and no-generic-proxy boundaries;
- preserves finite budgets/cancellation;
- preserves durable ambiguity/fencing;
- preserves air-gap/no mandatory SaaS;
- does not alter v0.8 release identity without later owner approval.

## Dependency graph

Primary:

`W61 -> W62 -> (W63 + W67) -> (W64 + W65 + W66) -> W68 -> (W69 + W70) -> W71`

Permitted overlap after planning admission:

- W63 may proceed after W62 telemetry identity/schema is stable.
- W67 can proceed in parallel with W63 because CLI/API parity does not require durable metrics history.
- W64 depends on W62 and on W63 for historical views, but live analytics can scaffold against W62.
- W65 depends on existing record ports plus W62 metrics/event contracts.
- W66 depends on shared event/telemetry contracts but not W65 completion.
- W68 requires stable typed APIs from affected resource families.
- W69 requires W68 resource schemas declared stable.
- W70 requires stable API/authorization contracts, not Terraform completion.
- W71 waits for all release-scope workstreams.

Tracker #209 owns live activation.
