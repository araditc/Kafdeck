# v0.3 Implementation Plan — Safe Data Explorer + Server-Side Masking

- **Status:** PROPOSED
- **Scope authority:** Issue #75 / RFC-0003
- **Implementation start gate:** v0.3 planning PR must be independently approved and merged
- **Language:** English

## 1. Objective

Implement bounded, separately authorized Kafka record inspection with server-side masking while preserving the released v0.2 identity/RBAC model and the no-Kafka-mutation invariant.

## 2. Workstream sequence

```text
W18 Record-read contracts, authorization & budgets
      |
      +--> W19 Bounded Kafka record reader
      |
      +--> W20 Schema-assisted decoding adapter
                |
                v
W21 Filter/search/live-tail engine
      |
      +--> W22 Server-side masking & bounded export
                |
                v
W23 REST/OpenAPI + operator UI
                |
                v
W24 Security, integration, load/benchmark evidence & v0.3 readiness
```

W19 and W20 may proceed in parallel after W18 contracts are stable.

W22 may proceed once W18 masking/authorization contracts and W20 normalized decode contracts are stable.

## 3. W18 — Record-read contracts, authorization and budgets

Deliver:

- Kafdeck-owned record/range/navigation contracts,
- `record.read` and `record.export` actions/scopes,
- budget model and validation,
- partial/budget outcome model,
- normalized record projection contracts excluding provider DTOs,
- masking policy contract/snapshot interfaces,
- architecture regression tests forbidding producer/commit/mutation paths.

Engineering baseline:

- operation deadline defaults to the existing Kafka 10s safety posture unless narrower evidence is required,
- request count/byte/time limits have conservative defaults and validated hard caps,
- record-read bulkheads are separate from metadata bulkheads,
- no masking-bypass action exists in v0.3.

Exit:

- contracts reviewed,
- default-deny record authorization proven,
- client cannot request unbounded budgets,
- provider types do not leak inward.

## 4. W19 — Bounded Kafka record reader

Deliver:

- explicit topic/partition assignment,
- earliest/latest/offset anchors,
- timestamp-to-offset resolution,
- forward pages,
- bounded previous-page reconstruction,
- low/high watermark metadata,
- cancellation/deadline/budget accounting,
- per-cluster/global record-read bulkheads,
- Kafka failure mapping.

Must prove:

- no `Subscribe`-driven durable group workflow,
- no offset commit,
- no producer,
- one failing/slow cluster cannot starve another.

## 5. W20 — Schema-assisted decoding adapter

Deliver:

- read-only Schema Registry port,
- Confluent-compatible adapter baseline,
- Avro decoding,
- Protobuf decoding,
- JSON Schema decoding,
- bounded schema cache,
- secret-reference integration,
- normalized structured value tree,
- decode/registry failure categories.

Full schema explorer is excluded.

## 6. W21 — Filter/search/live-tail engine

Deliver:

- bounded key/header/range filtering,
- regex with deterministic limits,
- CEL subset/compiler,
- jq-style subset/compiler,
- immutable compiled filter plan,
- budget accounting through filter evaluation,
- SSE bounded live tail,
- disconnect cancellation,
- per-identity/per-cluster tail admission/rate controls.

No arbitrary JavaScript or native SQL engine.

## 7. W22 — Server-side masking and bounded export

Deliver:

- immutable masking policy compiler,
- structured field/path redaction,
- configured header redaction where supported,
- fail-closed behavior when mandatory structured masking cannot be applied,
- safe projection used by all output paths,
- `record.export` enforcement,
- JSON/NDJSON/CSV streaming export,
- export row/byte/time budgets,
- audit metadata for record reads/exports.

Exit:

- sentinel leakage suite passes across UI/API/export/log/audit/errors,
- raw/hex cannot bypass masking.

## 8. W23 — REST/OpenAPI and operator UI

Deliver:

- GET record page endpoint(s),
- GET/SSE live-tail endpoint,
- GET bounded export endpoint,
- OpenAPI contracts,
- partition/offset/timestamp navigation UI,
- structured/text/hex views subject to policy,
- decode/masking/partial/budget states,
- filters,
- export controls,
- clear RBAC vs Kafka ACL vs schema/decode failure UX.

Backend remains authoritative.

## 9. W24 — Security, integration, load evidence and readiness

Deliver:

- full Kafka matrix,
- Schema Registry integration suite,
- cross-cluster isolation tests,
- cancellation/budget/load tests,
- masking/export security suite,
- threat-model reconciliation,
- operator record-access/masking guide,
- upgrade guide from v0.2,
- benchmark methodology/results,
- release/readiness evidence.

Exit:

- exact-head quality/security/integration gates green,
- independent final review,
- no mutation/persistence regression,
- release decision handled by separate explicit gate.

## 10. Data posture

Record payloads are ephemeral and are not persisted/indexed by default.

Schema cache is bounded in memory.

Durable payload search/indexing requires a future RFC.

## 11. Merge discipline

Each workstream:

- branches from exact live `main`,
- maintains the central v0.3 tracker,
- requires applicable exact-head CI,
- receives independent review when ready,
- resolves required review threads,
- merges with `expected_head_sha`,
- reconciles post-merge state before dependent work starts.

## 12. Deferred after v0.3

- full Consumer Group/Lag read views,
- full Schema Registry explorer,
- Kafka Connect read-only views,
- Kafka mutations,
- replay/produce,
- durable payload indexing,
- wire-path gateway.
