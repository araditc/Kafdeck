## W68 D1/D2 candidate

`CandidateSubscriptionManifest.ParseJson` accepts one versioned NotificationSubscription candidate document. The closed JSON grammar requires exactly:

```json
{
  "apiVersion": "kafdeck.io/v0.8-proposal",
  "kind": "NotificationSubscription",
  "metadata": { "deploymentRef": "lab", "name": "ops", "ownerRef": "team" },
  "spec": {
    "destinationRef": "notify",
    "state": "Active",
    "eventClasses": ["Operational"],
    "eventTypes": ["consumer.lag.alert"]
  }
}
```

Limits: 16,384 source bytes, depth 6, 256 decoded value nodes, 1,024 UTF-8 bytes per string, and existing domain identifier/filter bounds. Every object rejects duplicate decoded property names, including escaped-name collisions. Unknown/missing fields, unknown versions/kinds/classes, duplicate filters, malformed JSON/Unicode, endpoint/secret fields and terminal Retired intent are rejected. Exceptions do not echo source values. YAML is **unsupported**; it is never parsed or expanded, so anchors/aliases cannot reach object construction. Full D1 remains open for an admitted JSON/YAML grammar and per-family review.

Fingerprints use SHA-256 over fixed-order JSON and existing NotificationSubscriptionDefinition normalization. Set ordering is stable and identifier/filter case is exact. Deployment identity is included. `ownerRef` is untrusted provenance and deliberately excluded from content drift comparison; a future ownership registry must validate claims and bind owner revision separately. Fingerprints are local comparison aids, **not server-stored plans or authorization**.

`CandidateSubscriptionDrift.Compare` consumes evidence from an authorized backend read. It preserves Inaccessible/Unsupported, rejects identity mismatch as Conflict, treats future/stale/absent/inconsistent evidence as Unknown, preserves authoritative Missing, compares valid current metadata, and treats terminal Retired as Conflict. The helper cannot authenticate evidence, create ownership, adopt, repair or apply. DataQualityPolicy parsing/lifecycle comparison remains Unsupported pending family admission; existing policy readback is not automatic declarative ownership.

Still required for D2: authorized backend observation adapter, per-family canonical identity and omission semantics, persisted observation provenance, end-to-end real read/drift and ownership conflict evidence.

## W70 M2 candidate

`CandidateNotificationReadTool` declares a single typed read tool, `kafdeck_notification_subscriptions_read`, mapped to `GET /api/v1/notifications/subscriptions`. Its JSON schema is closed and accepts only a 1–50 result limit and bounded identifier continuation. Unknown fields, instructions, caller URLs and duplicate argument names are rejected. Tool annotations declare read-only/idempotent behavior.

The adapter performs one call through `IAuthorizedCandidateNotificationReadApi`, whose future implementation must use the same authenticated authorization-filtered REST result. It projects only subscription ID, lifecycle and revision plus pagination truth; no destination, payload, credential, summary, token or arbitrary text field has an output slot. It checks result count, output byte budget, identifiers, duplicate IDs, advancing cursors, and REST authorizationFiltered/continuationRestricted truth. A hidden cursor cannot be emitted, cancellation stops work, and upstream denial/failure propagates rather than becoming empty success.

No transport/package/credential loading or API implementation is wired. This is schema/adapter groundwork and does not satisfy M1, M2 or M5 end to end. Capability/diagnostic tools and other resource families remain open. The adapter is not itself an authorization boundary; annotation hints do not confer authority.
