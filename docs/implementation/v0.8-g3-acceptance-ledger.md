## Explicit family matrix

NotificationSubscription is the first runtime family. Supported lifecycle under
explicit activation: validate, observe, import an existing unowned resource,
plan, drift, create-and-own a missing resource, and update an owned resource.
Delete/terminal Retired reversal, transfer and relinquish are not advertised as
supported through this API. A resource already present but unowned requires an
explicit independently approved import; matching names never establish ownership.

DataQualityPolicy and Kafka topic/ACL/connector families retain their separately
published observation and unadmitted ownership states. Existing UI/API support
does not imply declarative apply support. All later W69/W70/W71 requirements
remain in scope.

## Recovery and operator boundary

Runtime activation requires a deployment generation and a pinned, bounded,
read-only recovery anchor outside database backups. Restores require physically
fenced old writers, quarantined outside authority, explicit offline generation
admission with reviewed fence evidence, then separate manual activation. Neither
startup nor an HTTP request enrolls or advances a deployment generation.

Schema verification is read-only. Installation/verified-v1 upgrade and adoption
of a complete unledgered installation are explicit offline operator actions;
partial or tampered schemas fail closed. Full principals remain in runtime audit
and immutable plans; legacy bounded audit columns contain domain-separated
principal hashes correlated by operation ID, never authentication authority.

## Validation checkpoints

Final source includes separately granted `DeclarativeSourceManage` revision CAS
with a default-off advancement flag. Neither that permission nor a Git commit
confers Apply authority. A→B→A cannot revive an old plan because its exact durable
registration revision is sealed. Confirm and approve use read-only freshness
checks; only a currently eligible distinct human can inspect a pending foreign
plan's sealed before/desired/after/changes and risk/policy/source evidence.

Finite reconciliation skips all planning/writes only when the authorized fresh
observation is InSync, Managed and its exact ownership/source binding is current.
Unknown or unowned observations never cause blind repair/import.
