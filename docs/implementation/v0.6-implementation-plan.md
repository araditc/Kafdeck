## Activation and fail-closed behavior

Runtime handlers register only after their workstream's provider and integration contracts have been admitted and can re-evaluate current authorization immediately before every effect. Domain-only implementation may remain inactive while API integration is pending. Do not invent identity/group rehydration to enable background work. Unavailable pinned-client APIs block dependent adapters; they do not justify a generic execution tunnel or an unreviewed sidecar.

`FleetUncertaintyDisposition` is a safety-only Kafdeck-local transition, not a provider feature. `QuarantineUnknown` cannot clear a conflict. `SupersedeUnknownForNewIntent` retains the original `ExecutionUnknown` record and no-redispatch tombstone; a later conflicting intent is a separate CRITICAL operation that binds the unresolved predecessor and receives fresh preview/approval. No implementation may expose a generic clear/ignore/delete-obligation endpoint.

Changes to a shared prerequisite invalidate dependent branches' final admission evidence. Reconcile each against latest main, resolve real conflicts, rerun checks and obtain fresh exact-head approval. Independent safe work may continue while human review is pending; no heartbeat commits or fabricated approvals.

## Evidence and reporting protocol

Every workstream issue records scope, prerequisite merge(s), current head/base, changed contracts, actual CI/job/artifact IDs, review findings/disposition, CODEOWNER state, capability limitations and next action. Before merge verify exact live head/base, rulesets, all applicable successful checks, zero substantive unresolved threads and fresh `akhiabanchian` CODEOWNER approval. Use `merge_pull_request(expected_head_sha=live_head)`; do not substitute auto-merge or direct main writes. Re-read main/post-merge checks, reconcile/close the workstream issue, then update #146 before activating the next dependency-valid stream.

## Stop boundaries

Request a new explicit owner decision for material scope/architecture departure, new provider mutation class outside #145, weaker independent approval, raw durable payload/credential storage, generic execution surface, stronger uncontrolled cross-cluster delegation, release/tag/publication or v0.7+. A safety-only local reconciliation transition that cannot itself issue provider I/O is governed by ADR-0007/RFC-0006 and does not expand provider capability scope. Keep immutable v0.5/v0.5.1 identities untouched and `.github/release/release.json` unchanged throughout planning. Unsupported capability is not silently removed from accepted scope or called completed.
