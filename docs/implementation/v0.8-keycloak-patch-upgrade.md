# Keycloak patch upgrade acceptance

This laboratory exercises actual Keycloak 26.8.0 and 26.8.1 servers against one fresh PostgreSQL database. It does not replace a patch upgrade with a same version restart. The application verifier remains unchanged.

## Reproduce

Use Java 21, PowerShell 7, PostgreSQL `psql`, a fresh output directory, and the existing isolated G2 identity material. Keep ports 20443, 20444, 7900, and 7910 free. The script creates its own database and role; it does not reuse the previous HA fixture.

```powershell
./deploy/dev/prove-keycloak-g2-upgrade.ps1 -Action Prepare -OutputDirectory <fresh-owned-directory> -IdentityDirectory <identity-directory> -PostgresManifest <private-postgres-manifest> -OldArchive <26.8.0.zip> -NewArchive <26.8.1.zip> -JavaHome <java21-directory>
./deploy/dev/prove-keycloak-g2-upgrade.ps1 -Action Prove -OutputDirectory <same-owned-directory>
./deploy/dev/prove-keycloak-g2-upgrade.ps1 -Action Stop -OutputDirectory <same-owned-directory>
```

Each Java process has a 384 MiB heap and two active processors. HTTPS uses the generated trusted CA and normal hostname validation. Node cache traffic uses JDBC discovery and embedded cache mTLS. Fresh first use requests are issued to both nodes before either response is awaited.

The proof requires old/old membership, rejection of a consumed time valid assertion after an old node restart, compatibility metadata and exit code zero for each replacement, a mixed version phase, and new/new membership. The surviving peer must issue a fresh token during each replacement. Each paired fresh assertion has exactly one successful exchange; subsequent replay must fail on both nodes while the assertion remains time valid.

The pinned archive SHA256 values are:

| Version | SHA256 |
| --- | --- |
| 26.8.0 | `7ed1de3fda2598369262613bf682aab7e233d80a38c405e91588f7a7454370a1` |
| 26.8.1 | `4cd312c889af358a819a74a6c6f068f9ea159a6959e49924607cec95cfd4c1a4` |

The separate exact revision workflow is `.github/workflows/v08-g2-keycloak-upgrade.yml`. Its required test verifies a final genuine access token through the production verifier. Only the named safe evidence JSON files and TRX may be uploaded. Private realm material, database credentials, assertions, tokens, compatibility metadata, native logs, and runtime directories remain excluded.

For the test, set `KAFDECK_KEYCLOAK_UPGRADE_INPUTS` to an absolute private JSON file containing exactly `RootDirectory`, `IdentityDirectory`, `PostgresManifest`, `OldArchive`, `NewArchive`, and `JavaHome`, each an absolute path. `RootDirectory` is a scratch parent; each test creates a fresh child. The PostgreSQL manifest supplies `user`, `bindAddress`, `port`, `database`, `binDirectory`, and `connectionStringFile`. The referenced connection file supplies administrative access to create the isolated lab database and role. These inputs are not uploadable evidence.

```powershell
dotnet test tests/Kafdeck.Architecture.Tests/Kafdeck.Architecture.Tests.csproj --configuration Release --no-build --no-restore --filter FullyQualifiedName~V08G2KeycloakPatchUpgradeTests
```

Without the explicit inputs the test skips; the dedicated workflow additionally requires one passing test, zero skipped tests, and both named evidence files. A skipped or absent scenario cannot satisfy that gate. The test always stops its exact owned nodes in `finally`, retaining their runtime and database data for diagnosis.

## Current evidence and limits

The corrected local native proof passed on 2026-10-16: old/old membership, a separate same version bounce, both actual patch replacements, mixed and new/new membership, compatibility exit codes `[0,0]`, fresh peer tokens during replacement, two paired first use rounds with winners `[1,1]`, and sixteen time valid consumed replay refusals. Safe evidence is `artifacts/g2-complete/upgrade/keycloak-patch-rolling-upgrade-evidence.json`, SHA256 `5804fbaab74def145ef9287797fab6d31ca8a1a2c492a78f2922198c473627e7`. Production verifier follow-up, Linux exact revision, and protected main acceptance remain pending.

Initial local attempts exposed cold readiness timing, a realm import filename mismatch, and JGroups logical name annotations. The first replacement attempt expired a control deadline that included a cold target build; the isolated compatibility command subsequently returned exit code zero. Failed attempts remain retained privately and do not count as upgrade acceptance.

This fixture proves the specified manual patch transition and replay behavior. It does not establish automatic rollback, a load balancer deployment, session continuity, or compatibility across major or minor versions. Follow the official [26.8.1 upgrade guide](https://www.keycloak.org/docs/26.8.1/upgrading/) and [compatibility command documentation](https://www.keycloak.org/server/update-compatibility) for the supported patch transition and configuration matching requirements.
