## Counting and merge policy
- Every status report records **merged**, **open**, **closed-unmerged/superseded**,
  and **unimplemented planned slices** separately per W.
- Historic PR counts are not a reliable denominator; PRs may be corrective,
  superseded, duplicated or shared across W boundaries.
- Each PR must have its own exact-head CI, fresh Codex and independent CODEOWNER.
- After protected-main changes, revalidate branch protections; never bypass
  missing `quality-gate` for throughput.
- The first W68 high-water schema is not an Acquire implementation. No runtime
  lease/owner authority, GitOps Apply or v0.8 release is granted by this document.
