## Provider configuration issue found by the real scenario

The initial lab had removed all default client scopes. Its signed ID token had
the correct human subject, while its signed **access token omitted `sub`**.
The CLI correctly rejected that token at the access-token validation stage.
The realm was corrected with an explicit `oidc-sub-mapper` and
`access.token.claim=true`, then recreated in a fresh isolated lab database.
Validation was not weakened and the ID-token subject was not substituted into
the deficient access token. A signed missing-subject negative regression and the
operator runbook retain this requirement.
