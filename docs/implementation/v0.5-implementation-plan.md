## Sequence

```text
W32 Mutation kernel / persistence / authorization-risk contracts
  |
  +--> W33 Topic administration
  |
  +--> W34 Governed record production
  |
  +--> W35 Consumer offset/group administration

             |
```

W33-W37 may proceed dependency-valid in parallel after W32 contracts are admitted. W38 depends on the mutation kernel and Kafka admin safety primitives. W39 integrates only admitted domain/provider operations.

- SQLite standalone + PostgreSQL HA semantics,
- idempotency binding,
- canonical intent / preview hashing,
- risk engine and built-in floors,
- confirmation/approval model,
- independent-approver enforcement,
- conflict/resource claims,
- bounded executor,
- typed provider mutation port contracts,
- safe operation audit events,
- mutation feature/startup prerequisite gate,
- architecture tests.

Exit:
- exact-head quality gate,
- persistence concurrency tests,
- state-machine/race tests,
- no external provider mutation yet unless required by a narrow contract fixture.

## Merge discipline

Each workstream:
- starts from latest admitted prerequisite head,
- keeps Issue #122 reconciled,
- uses signed-off commits,
- runs fresh exact-head applicable checks after source changes,
- addresses substantive deterministic review findings,
- resolves required threads,
- requires fresh CODEOWNER approval after head changes,
- merges only under repository rules with expected head guard.

Dependency-valid stacked work may continue while a review gate is pending, but no approval may be fabricated and no blocked branch may be merged.

## Global stop conditions

Stop and request owner approval for:
- material departure from #121 scope,
- new mutation class not listed in RFC-0005,
- weakening CRITICAL independent approval,
- adding a generic provider/CLI execution surface,
- storing raw Kafka payloads durably by default,
- release/tag/publication,
- v0.6+ activation.
