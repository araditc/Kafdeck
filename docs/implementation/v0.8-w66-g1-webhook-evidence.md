## Implementation

`WebhookDeliveryEnabled` is a separately parsed default-false host option. Its
admission requires enabled notification persistence, standalone mode and at least
one anonymous Webhook profile; mixed/provider-credential/HA activation fails
closed. The API registers the same production DI extension exercised by the lab.
The background service runs bounded due work and stale-claim recovery using the
existing durable worker and current profile revision checks. Production DNS,
fresh public-IP pins, exact origin/path, platform TLS certificate validation,
payload/rate/concurrency limits and zero redirects remain enforced.

The positive scenario starts a Generic Host with the actual hosted service, seeds

configured SNI/Host, and reopens SQLite to verify its durable receipt. The recovery

clock advanced beyond the stale threshold, and proves no second request occurs.
Wrong-hostname and untrusted-CA scenarios physically dial and send SNI but never
deliver HTTP to the fixture. A physical 302 is never followed and remains unknown.

The test-only resolver supplies a policy-valid public pin which its test-only
dialer maps to an isolated loopback socket; no traffic is sent to `1.1.1.1`.
HTTP and TLS are real; there is no mock HTTP handler. An ephemeral laboratory CA

validation. The Windows fixture imports its generated server PFX into a temporary
Schannel key container without `PersistKeySet`; certificate disposal cleans it up.
No OS trust-store root, credential or private key is committed.

## Limits and remaining acceptance

- This proves the G1 local Webhook host-to-ledger vertical and part of N4 recovery;
  it does not close N1–N5 on protected main or close #215.
- Public DNS/network reachability and deployment owner endpoint admission remain
  environment-specific. Every product event producer is not connected by this slice.
- N2 credential-bound physical delivery, all six N3 providers, N4 HA and full N5
  UI/security/recovery acceptance remain open.
- `KAFDECK_TEST_POSTGRES` was absent. Six existing conditionally enabled PostgreSQL
  cases return early without performing PostgreSQL operations; the 285 pass total
  is not PostgreSQL/HA runtime proof. Genuine durable runtime evidence here is SQLite.
- Process interruption is exercised through hosted-service cancellation and a new
  host; no claim is made of OS process-kill, power-loss or cross-node failover testing.
- `git diff --check` passed locally. Final protected-main commit and required CI
  identities must be added by the integration owner before acceptance.
