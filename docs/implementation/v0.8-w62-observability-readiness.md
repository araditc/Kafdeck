# v0.8 W62 Observability Foundation Readiness

Status: **IMPLEMENTATION CLOSEOUT CANDIDATE**

Authority: Gate 8 #208 / tracker #209 / W62 #211.

## Purpose

W62 establishes the common bounded observability foundation used by later v0.8 workstreams. It does not provide historical metrics, SLO analytics, data-quality monitoring or alerting; those remain owned by W63–W66.

## Implemented foundation

### Slice 1 — Prometheus and cardinality

Protected-main merge: `ac60f4ff800c05d8dd1bab97987e38c86ed7aa29`.

Implemented:

- canonical `Kafdeck.Api` ActivitySource/Meter;
- bounded API request count/duration telemetry;
- process-wide active-series accounting;
- 10,000 default / 50,000 hard active-series contract;
- 8 default / 12 hard labels per series contract;
- 64 B default / 128 B hard metric-label-value contract;
- fixed Prometheus scrape path `/metrics`;
- Prometheus disabled by default;
- dedicated scrape credential and HTTPS requirements for remote bindings;
- fixed-time scrape credential comparison;
- route/method/status normalization;
- explicit dropped-series telemetry;
- `/api/v1/observability/capabilities`;
- static-file and reverse-proxy boundary hardening.

## Slice 2 — stable OTLP trace and metric export

Protected-main merge: `b6c7ac219bdff2c320360161a4a3bfcf117f68b0`.

Implemented:

- OpenTelemetry .NET / OTLP exporter 1.19.1;
- trace provider subscribed to `Kafdeck.Api`;
- metric provider subscribed to `Kafdeck.Api`;
- OTLP gRPC and HTTP/protobuf typed configuration;
- no-redirect HTTP/protobuf transport;
- typed private/remote endpoint validation;
- secret-reference-only exporter headers;
- ambient OTLP header override/clearing;
- resolved credential isolation from deployment, metrics and OIDC credentials;
- strict UTF-8 Basic wrapper inspection;
- exporter runtime-health evidence:
  - no observed export => Unknown;
  - latest trace/metric export failure => Unavailable;
  - latest trace and metric exports successful => Supported.

## Slice 3 — runtime/provider/job instrumentation and safe logs

Closeout candidate adds:

- `Kafdeck.Runtime` ActivitySource;
- governed mutation-dispatch tracing;
- governed data-job provider-effect tracing;
- Data Generator provider-effect tracing;
- data-job/generator worker-cycle safe telemetry;
- closed bounded family/outcome dimensions only;
- no operation IDs, principals, topics, resource keys, payloads, query text, provider bodies or exception text in runtime telemetry;
- isolated OTLP log pipeline that exports only explicit `Kafdeck.Telemetry` fixed-template events;
- host/application/provider logs are not automatically forwarded to OTLP;
- HTTP/protobuf log endpoint is signal-specific `/v1/logs`;
- log attribute and diagnostic-string budgets:
  - attributes default 24 / hard 48;
  - safe diagnostic bytes default 512 / hard 2 KiB;
- OTLP log capability remains `Unknown` while enabled because trace/metric export health is not incorrectly reused as log-delivery proof.

## Data-classification boundary

Prohibited from W62 telemetry:

- raw Kafka keys, values or headers;
- generated payload bytes;
- ksqlDB result rows;
- arbitrary query text;
- passwords, tokens, private keys or connector write-only secrets;
- arbitrary provider response bodies;
- unrestricted exception/request bodies;
- unbounded topic/group/connector/schema/user identifiers as global labels.

Restricted resource identities remain a later explicitly bounded resource-metrics concern. W62 does not add them.

## Failure semantics

- optional observability exporter failure does not authorize or alter Kafka effects;
- exporter failure does not weaken mutation/job durability;
- cardinality exhaustion rejects new series and emits bounded dropped-series evidence;
- OTLP capability reports Unknown/Unavailable rather than fabricating healthy state;
- no mandatory public collector/SaaS exists;
- with OTLP disabled, no OTLP secret resolution/export occurs.

## Air-gap posture

W62 supports:

- local authenticated Prometheus scrape;
- private OTLP collector;
- OTLP disabled;
- no public service discovery;
- no runtime CDN or external observability SaaS requirement.
