# W67 G1 — genuine Keycloak token to shipped Kafdeck host

Date: 2026-10-15. State: local laboratory first vertical demonstrated; W67 A1/A2
remain partially complete, and W67 #216 remains open. Protected-main and hosted
CI evidence are recorded separately after integration.

## What actually ran

The official Keycloak **26.8.1** ZIP and Temurin **21.0.12.1+1** JDK were downloaded,
verified against their published SHA256 values and extracted into the ignored
local laboratory. No Docker, system Java installation or OS trust-store change
was needed. The live Keycloak process bound HTTPS to loopback port 18443.

The imported realm used exact issuer
`https://localhost:18443/realms/kafdeck-g1`, exact API audience `kafdeck-api-g1`, and
per-service asymmetric `private_key_jwt` client authentication. The assertion
private key was generated locally and stayed in the ignored lab directory. The
access token came from the real Keycloak token endpoint over verified local TLS;
it was not created by the Kafdeck test or an artificial signing authority.

The test then launched the **shipped `Kafdeck.Api.dll` entry point**, with the actual
Program.cs, DI registrations, middleware and existing v1 endpoints on
`http://127.0.0.1:18086`. This cleartext endpoint is a loopback-only test transport;
the bearer boundary rejects insecure non-loopback requests. No alternate fixture
API was substituted. Kafka data was not needed for the accepted system read or
for the denied cluster request, which failed in the authorization filter before
data retrieval; Kafka connectivity is not claimed by this identity proof.

## Observed outcomes

| Live case | Expected | Observed |
| --- | --- | --- |
| Keycloak signed client assertion exchange | token issued | HTTP 200 |
| Identical client assertion replay on same live node | denied | HTTP 400 |
| Registered token GET `/api/v1/system/info` | allowed | HTTP 200 |
| Same token GET `/api/v1/clusters/denied/health` outside granted scope | denied by current direct RBAC | HTTP 403 |
| Bearer plus browser cookie | reject conflicting credentials | HTTP 401 |
| Bearer plus deployment access-token header | reject conflicting credentials | HTTP 401 |
| Client assertion submitted as API access token | reject wrong token purpose/identity | HTTP 401 |
| Unadmitted cluster-list endpoint | reject unadmitted bearer route | HTTP 401 |
| Browser-session endpoint with service bearer | no browser impersonation | HTTP 401 |
| Mutation endpoint with service bearer | no mutation authority | HTTP 401 |
| Invalid bearer sentinel | reject safely | HTTP 401 |
| Disabled registration / unregistered subject or client / wrong audience | no authenticated service identity | rejected |

The test checked that raw access-token and client-assertion bytes were absent
from API response bodies and captured host stdout/stderr. Audit entries identify
the service with exact escaped issuer/subject/client/registration, and preserve
safe denial categories and correlation. Neither a browser session ID nor external
Keycloak role/group grants were created for the service.

The actual Keycloak access token **omitted `nbf`**. The verifier therefore explicitly
supports absent `nbf` by using mandatory signed `iat` as activation time; present
`nbf` retains finite timestamp and skew checks. Mandatory original `exp - iat`
lifetime validation remains intact. This is documented in the operator contract
and covered by negative tests; the acceptance evidence records the observed
absence rather than assuming it.

Both Debug and final Release targeted runs completed **36 passed, 0 failed, 0 skipped**, including the
genuine Keycloak test, offline signature/time/audience checks, backend
authorization regression and discovery-stream/gate timeout tests.

```powershell
$env:KAFDECK_KEYCLOAK_G1_LAB = '<absolute-path>/deploy/dev/.generated/g1/identity/lab.json'
dotnet test tests/Kafdeck.Architecture.Tests/Kafdeck.Architecture.Tests.csproj --configuration Release --no-restore --filter 'FullyQualifiedName~V08W67BearerReadTests|FullyQualifiedName~V08W67InertRs256EvidenceVerifierTests|FullyQualifiedName~AuthorizationEnforcementTests' -m:1 --logger 'trx;LogFileName=keycloak-g1-release.trx' --results-directory artifacts/g1/keycloak
```

Generated local evidence:

- `artifacts/g1/keycloak/keycloak-g1-release.trx` — final Release test results;
  `keycloak-g1.trx` records the earlier Debug run.
- `deploy/dev/.generated/g1/identity/keycloak-evidence.json` — safe pinned lab
  identifiers, time, observed status codes and token-claim presence only.
- `deploy/dev/.generated/g1/identity/kafdeck-host.log` — local host audit output,
  checked by the test for raw access-token/assertion leakage.

These generated paths are ignored. Private keys, TLS passwords, PKCS#12 files,
raw tokens and raw assertions are not source artifacts. Use the
[operator runbook](../operator/v0.8-keycloak-g1-lab.md) to reconstruct the lab.
