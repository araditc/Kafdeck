## 1. Definition of success

Every W61–W71 workstream must pass its product, runtime, integration, security, recovery, documentation and compatibility acceptance, then be closed with exact protected-main evidence. A PR merge, simulated adapter, cryptographic helper, RFC, or passing unrelated CI cannot count as a whole workstream accepted. Workstream completion still does not authorize publishing v0.8: owner publication approval is independent.

Current confirmed: all W61–W71 workstreams are complete. All 14 final-main producer workflows and the 124-file strict Main packet passed with zero missing gates. G6 separately published the owner-approved source/archive with verified signatures, SPDX and six package assets. Historical baseline descriptions and prerequisites below remain as the original delivery plan.

**Primary management change:** deliver vertical end-to-end acceptance cases, not a continuous sequence of small isolated library PRs. Every PR declares exactly which acceptance IDs below it closes, which tests and real fixtures prove that, and what remains unavailable.

## 2. Dependency graph and simultaneous work

Critical paths:
- W67 real authentication and governed API -> W68 ownership/plan/apply -> W69 actual Terraform provider -> W71.
- W67 real authentication and API -> W70 authenticated MCP read/plan/status/effect tools -> W71.
- W66 real six-provider notification delivery, authorization and HA -> W71.
- W61–W65 full regression -> W71.

Six concurrent lanes; prevent unrelated blockers:
- Lane A, W66: implement default-off physically hosted webhook; then complete real typed Webhook, Email, Slack, Teams, Telegram, PagerDuty providers, durable recovery and operator workflows.
- Lane B, W67: Keycloak trust and laboratory, bearer GET, registered machine/human CLI identity, typed plan/status/effect/approval API and CLI parity.
- Lane C, W68: admit family-specific schemas, safe bounded parsing, observed state and drift while W67 authority is built; apply waits for W67 mutation admission.
- Lane D, W70: typed read tools, schemas, result masking and injection tests independently; active authenticated effects wait for W67.
- Lane E, W69: provider architecture/tests against stable W68 schema, then real provider resource lifecycles when W68 API is admitted.
- Lane F, W71: immediately maintain acceptance/compatibility/CI/airgap tests; integrated compensation/UX/release gate waits on upstream runtime evidence.

Do not block W66 on Keycloak; do not block W68 read/drift or MCP tool-schema tests on W67 mutations; do not block MCP on Terraform. Git is not authorization, and prompt text is never authority.

## 5. W67 #216 — Keycloak, REST parity and CLI

Existing: GET-only CLI, inert Keycloak documentation/PKCE callback/service proposals and offline JWT verification. The verifier is not host authentication.

- [x] **A1 Trust admission:** select pinned self-hosted Keycloak build/realm and exact HTTPS issuer; explicit API audience, signing-key/JWKS rules, local public CLI client, per-service confidential client, private_key_jwt, owner/scopes, revocation and key rotation. Candidate audience kafdeck-api is NOT production approval.
- [x] **A2 Real bearer read:** default-disabled API scheme only for admitted versioned routes, trusted signing keys, registered principal lookup and current RBAC, exact issuer/audience/client/subject, cookie/bearer/CSRF separation and token/key replay negatives. Real Keycloak-issued token makes an authorized GET succeed and a cross-scope GET fail.
- [x] **A3 Human CLI:** PKCE S256 with literal numeric loopback address and bound ephemeral listener, state/nonce/code proof, short-lived memory-only tokens by default, profile/JSON/cursor/output/error parity, cross-platform tests.
- [x] **A4 Versioned governed API:** explicit inventory of UI parity for read, plan, preview, confirm, execute, approval inspection and operation/status; typed OpenAPI/errors, immutable server-stored plans, exact initiating principal, provider/risk/policy/current-state validation, idempotency and durable unknown effects.
- [x] **A5 CLI effect/approval/status:** named CLI commands only call typed backend API and retain AwaitingApproval/ExecutionUnknown/conflict/expired/denied semantics; CRITICAL requires distinct authorized human approver; legacy deployment tokens can never gain mutation rights.
- [x] **A6 Real identity acceptance:** Keycloak service-account client assertion single-use concurrent jti/HA-upgrade and rotation tests; revoked/unregistered principal, expired/overlong token, wrong audience/issuer/ID-token confusion, TLS/disconnected modes; security, audit, SQLite/PostgreSQL E2E and docs.

**Close #216 only on A1–A6 with real Keycloak, server-side auth and live CLI/API functionality.**

## 6. W68 #217 — Typed config-as-code and GitOps

- [x] **D2:** deterministic normalize/current-state/observe/drift with explicit InSync/OutOfSync/Missing/Unknown/Inaccessible/Conflict/Unsupported.
- [x] **D3:** durable exact ownership registry, adopt/import evidence, authorization, optimistic revision CAS and HA fencing; Git ownerRef never confers rights.
- [x] **D4:** server-issued immutable planId/fingerprint/expiry with original principal, policy version, resource/current-state and desired-state proof, risk and approval requirements.
- [x] **D5:** backend-governed apply with current RBAC AND underlying effect actions, revalidation at effect point, durable idempotency, distinct approval and ExecutionUnknown recovery.
- [x] **D6:** real GitOps parse/validate/plan/drift/apply workflows with CLI/API parity, secrets safe references, concurrent writer/drift/restore and air-gap tests.

**Close #217 on D1–D6 and accepted per-family read/import/plan/drift/apply lifecycle matrices.** Never make irreversible destroy falsely Supported.

## 11. Governance and delivery evidence

Each named acceptance ID must have: state NotStarted/InProgress/Blocked/Integrated/Accepted, accountable implementation owner, exact missing fact, blocker ID, protected-main commit, test/CI job and real runtime/runbook evidence. Record a compact current-state ledger in #209; leave historical comments as audit trail.

Every feature PR links acceptance IDs and names demonstrable product behavior. When possible consolidate the host/API/persistence/tests needed for a vertical into one governed integration slice instead of an indefinite stream of isolated helper PRs. Preserve DCO, exact-head Quality/CodeQL/Dependency/Supply Chain/benchmark checks, zero unresolved P1/P2, fresh CODEOWNER and expected-head protected merge. After merge, verify protected-main gates.
