## Inherited security finding

PR #139 was merged to protected `main` as
`f8e6b702d54bf68edffb3e672dec282f0b499c87`.
Its exact source head
`0fb0e2353b7474305a2a511b1918ec5327b51cb3`
had green language-level CodeQL jobs, while the GitHub Advanced Security aggregate
CodeQL protection check `107045429979` reported **one new High-severity alert**.
The alert was never dismissed or suppressed.

The historical check annotation subresource is not exposed by the current
connector and the old workflow retained no SARIF artifact. W40 therefore retained
the alert as a mandatory release blocker instead of inferring resolution from
later green language jobs.

The PR #139 security-review timeline subsequently exposed the exact aggregate
finding:

- **CodeQL rule:** `cs/insufficient-password-hash`
- **CWE:** CWE-916
- **Severity:** High
- **Path:** `tests/Kafdeck.Architecture.Tests/V05ConnectSecretPreviewTests.cs`
- **Flow:** the test request's `db.password` value flowed into the fake Connect
  observation helper and then into unkeyed `SHA256.HashData`; a direct raw-SHA
  comparison in the keyed-fingerprint test reinforced the same password-hash flow.

This is test-fixture code rather than production credential storage, but W40 does
not waive security-gate findings on that basis. Commit
`44858ef8597385c3650b62b43b1442cef29aa289` removes the runtime raw-password SHA
flow without suppression: fake provider observations use fixed precomputed raw
fingerprint fixtures, while the security assertion now proves non-guessability by
comparing the same sensitive values under two independent governed
`IMutationMaterialDigestService` keys. Fresh exact-head CodeQL/GHAS evidence is
required before this blocker can be considered closed.
