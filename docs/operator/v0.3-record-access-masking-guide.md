# v0.3 Operator Guide — Record Access, Masking and Export

- **Target:** Kafdeck v0.3 Safe Data Explorer
- **Scope:** bounded record browsing, live tail, filtering, masking and export

## 1. Security model

Kafdeck v0.3 separates Kafka metadata visibility from record-data access.

The new actions are:

- `record.read` — permits bounded inspection of record payloads on the granted cluster/topic scope.
- `record.export` — permits bounded export of the already-authorized and already-masked projection.

`topic.read`, `topic.list`, topic configuration permissions, or broker permissions do not imply either record action.

In OIDC mode, role and resource scopes are evaluated against the authenticated operator identity. Local and Token modes remain compatibility deployment boundaries and do not become human OIDC identities.

## 2. Recommended rollout

Start with no record permissions and grant them explicitly to a narrow role and topic scope.

Conceptually:

```text
Role: payments-debugger
  cluster: payments-prod
  topics: payments.events
  actions:
    - topic.read
    - record.read
```

Grant `record.export` only to roles that need extraction outside the interactive browser.

The exact configuration syntax remains governed by the deployed v0.3 configuration contract. Do not infer record permissions from wildcard metadata roles during migration.

## 3. Navigation

The record browser supports bounded navigation by:

- explicit partition,
- earliest/latest anchor where permitted,
- explicit offset,
- timestamp resolved to a concrete partition offset,
- bounded forward page,
- bounded previous-page reconstruction.

Kafka does not provide reverse consumption. Previous-page navigation computes a bounded earlier anchor and consumes forward from that point.

The API/UI exposes low/high watermarks and actual returned offsets where available.

## 4. Budgets and partial results

Every record operation is constrained on the server. Client input cannot create an unbounded scan.

Budget dimensions include:

- record count,
- raw bytes,
- projected bytes,
- wall-clock duration,
- live-tail duration/rate/bytes,
- export rows/bytes/duration,
- global/per-cluster concurrency.

A budget-limited result is explicit. Do not interpret a partial page as proof that no additional matching record exists outside the scanned range.

## 5. Live tail

Live tail is a bounded server-to-client SSE stream.

Operational properties:

- no durable Kafka subscription,
- no consumer-group offset commit,
- bounded duration and rate,
- browser disconnect cancels the server-side work,
- the same authorization, filter, decoding and masking boundary applies to each emitted record.

Use live tail for short operational observation, not as a replacement for a consumer application.

## 6. Schema-assisted decoding

A configured read-only Schema Registry adapter may decode:

- Avro,
- Protobuf,
- JSON Schema.

The registry is a decoding dependency only in v0.3. Full subject/version lifecycle administration remains out of scope.

Registry failures are shown as decode/registry outcomes. They never grant broader record access.

If an active masking policy requires structured fields and the record cannot be decoded safely, Kafdeck returns a fully redacted payload projection rather than clear raw data.

## 7. Filtering

v0.3 supports bounded filters including:

- key predicates,
- partition/offset/timestamp bounds,
- header predicates,
- bounded regex,
- deterministic CEL subset,
- deterministic jq-style subset.

Invalid or over-budget filter expressions are rejected as client-query errors.

There is no arbitrary server-side JavaScript execution and no general-purpose SQL stream engine.

## 8. Server-side masking

Masking is authoritative before browser/API/export projection.

A masking policy may redact:

- record key,
- exact Kafka header names,
- structured payload paths.

Structured paths preserve exact JSON-pointer identity, including significant whitespace in property names. Header rules also preserve exact Kafka header identity.

When mandatory structured masking cannot be applied safely, the payload is returned as fully redacted. Raw/hex presentation is not a bypass.

## 9. Export

Export requires `record.export` for the exact cluster/topic target.

Supported formats:

- JSON,
- NDJSON,
- CSV when the safe projection is compatible.

Exports are generated from the safe masked projection and are bounded by rows, bytes and duration.

### `Indeterminate` export outcome

A generic output stream cannot always prove whether a timed-out write committed bytes. Once a write has started, Kafdeck reports `Indeterminate` when commit ownership is uncertain rather than claiming a definitive non-commit result.

Operators should treat `Indeterminate` as: **the destination may contain some bytes; inspect or discard that destination before retrying.**

Do not automatically retry an `Indeterminate` export into the same non-transactional destination unless duplicate/partial data is acceptable.

## 10. Audit

Successful browse, tail and export access emits a security-audit event.

Audit metadata may include:

- actor/access mode,
- cluster/topic/partition,
- actual offset range,
- masking policy ID/version,
- budget/filter outcome,
- export format/row/byte/outcome metadata,
- correlation/session context.

Audit must not contain record key/value/header values, decoded fields, Kafka credentials, OIDC tokens, deployment tokens, or cookies.

## 11. Common operational states

### Kafdeck authorization denied

The operator lacks `record.read`/`record.export` or the target is outside the granted cluster/topic scope. Resolve Kafdeck policy; do not broaden Kafka ACLs as a workaround.

### Kafka ACL denied

Kafdeck authorized the operator, but the configured Kafka principal cannot read the target. Resolve Kafka-side ACLs while keeping Kafdeck RBAC intact.

### Schema unavailable / decode failed

Verify registry connectivity, authentication and schema compatibility. Clear payload must not be exposed when masking requires successful structured decode.

### Budget exhausted

Narrow the partition/range/filter or use smaller pages. Increasing budgets should be a deliberate deployment decision within hard caps.

### Offset out of range

Refresh watermarks and select a valid anchor. Retention or compaction may have removed previously visible offsets.

### `Indeterminate` export

The destination write may have committed. Inspect/discard the destination and retry into a fresh transactional/isolated target if a clean export is required.

## 12. Production guidance

- Prefer OIDC for attributable multi-user operation.
- Grant record permissions to the smallest practical topic scope.
- Keep `record.export` rarer than `record.read`.
- Configure masking before granting access to sensitive topics.
- Keep hard scan and concurrency caps conservative for production clusters.
- Monitor record-read admission, timeout, budget and Kafka-denial metrics without adding payload-derived metric labels.
- Treat Kafdeck as an out-of-band control plane; it must not enter the producer/consumer availability path.
