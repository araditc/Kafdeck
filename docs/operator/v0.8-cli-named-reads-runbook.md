# v0.8 named API/CLI reads

The shared source inventory contains 67 exact versioned read contracts. Retrieve
it using a registered human or service profile:

```text
kafdeck --oidc-profile human.json views v08-bearer-read-capabilities
```

The response lists each fixed route, method, required read action and permitted
query keys. It grants no authority. A named view requires current registration,
the corresponding explicit read action and the current backend resource scope.
Services use filtered collections; notification management metadata is human-only.

```text
kafdeck --service-profile service.json views v01-brokers-configuration dev 0
kafdeck --service-profile service.json views v07-connect-profile-plugins-list dev connect
kafdeck --service-profile service.json views v07-connect-profile-connectors-detail dev connect connector
kafdeck --oidc-profile human.json views v07-schema-registry-capabilities dev
kafdeck --oidc-profile human.json views v03-records-browse dev orders 0 --request-file query.json
kafdeck --oidc-profile human.json views v03-records-export dev orders 0 --request-file query.json
```

A view with query keys requires a JSON file containing only those keys; `{}` uses
server defaults. For example, record inspection accepts
`{"offset":0,"maxRecords":10,"maxBytes":65536}`. Export also accepts `format`
(`json`, `ndjson` or `csv`). The finite tail command uses `v03-records-tail` and
prints the safe server event stream. CSV/NDJSON export is printed in its original
wire format. Output remains capped by the CLI response limit.

The five POST read tools are `v07-schema-mock`, `v07-serde-encode`,
`v07-serde-decode`, `v07-connect-profile-plugin-validate` and `v07-ksql-query`.
They require the matching closed request file. JSON is bounded to 65536 bytes,
depth 16 and duplicate-free fields before token acquisition. The backend retains
its semantic/provider limits; SELECT-only ksql parsing and configured SerDe
capabilities cannot be overridden by a file.

Only a verified bearer on these exact read contracts uses the separate bearer
boundary. Browser POSTs retain CSRF validation. Bearer/cookie/deployment credential
collisions remain denied. Record output retains server masking and separate
`RecordExport` authority; no browser identity/session is fabricated for export.

Inherited provider Unsupported/Blocked responses remain visible failures. An
empty filtered collection does not imply the underlying provider collection is
empty. Runtime/provider acceptance for each new surface is tracked in the
integrated G2 evidence, separately from this source inventory.
