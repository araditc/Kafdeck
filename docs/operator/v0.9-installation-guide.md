# Install and operate Kafdeck v0.9

**v0.9 was published on 2026-11-12**, from source `01c7553425fbc61ba4a7a21918265c562086ba02`. Download the [official release](https://github.com/araditc/Kafdeck/releases/tag/v0.9), not an earlier candidate CI artifact. [Exact publication evidence](../implementation/evidence/v0.9-release-published-20261112.json)

For a new managed installation, the operator journey is **install and configure HTTPS/Keycloak → issue setup code → create first administrator → sign in → test/save a Kafka connection → use the dashboard → grant users access**. Keycloak and Kafka are separate services and credentials.

## Choose an installation path

| Path | Deliverable and prerequisites |
| --- | --- |
| Docker / Podman | Linux amd64 or arm64; private GHCR read access, or a verified offline image archive |
| Self-contained API/UI, CLI and MCP | Native `win-x64`, `linux-x64`, `linux-arm64`, `osx-x64`, `osx-arm64` archives; no .NET SDK needed to run a self-contained executable; match the OS/RID and its system-library prerequisites |
| Helm | Signed `kafdeck-0.9.0.tgz`, exact image digest, Kubernetes/Helm, external Kafka/Keycloak, TLS, egress and persistent storage |
| Source development | Git, the SDK selected by `global.json`, Node.js 24 and npm; use the [source instructions](../../README.md#building-from-source) |

Kafdeck binaries/MCP use version `0.9.0`. The independently versioned Terraform provider remains `0.8.0`; this is intentional. [Platform and recovery boundaries](../operations/v0.9-distribution-recovery.md)

## Run the released container

The published two-architecture image is pinned by digest, not a mutable `:v0.9`/`:latest` tag. GHCR remains private; use an authorized identity and `read:packages` token when Docker requests a password.

```sh
docker login ghcr.io --username YOUR_GITHUB_LOGIN
docker pull ghcr.io/araditc/kafdeck@sha256:8e84e47793f663e02226cb11ca43f60835f87663dca6f76b1075975a91f489f0
```

For a managed installation, prepare `/srv/kafdeck/appsettings.Production.json` from [this example](examples/v0.9-managed-appsettings.json), a private `/srv/kafdeck/secrets` directory with the PFX and **separate** browser/provisioning client secret files, and persistent state. The image runs as UID 1654; ensure that identity can read configuration/secrets and write its state/home, without granting broad write access. For example, on a Linux host:

```sh
sudo install -d -m 0700 -o 1654 -g 1654 /srv/kafdeck/state /srv/kafdeck/state/home
```

Configure the Keycloak clients/certificates as described in [first administrator setup](managed-identity-setup.md). Inject `KAFDECK_HTTPS_CERT_PASSWORD` privately, then run:

```sh
docker run --detach --name kafdeck --read-only \
  --publish 127.0.0.1:8080:8080 \
  --env ASPNETCORE_ENVIRONMENT=Production \
  --env HOME=/var/lib/kafdeck/home \
  --env ASPNETCORE_Kestrel__Certificates__Default__Path=/run/secrets/kafdeck-https.pfx \
  --env ASPNETCORE_Kestrel__Certificates__Default__Password="$KAFDECK_HTTPS_CERT_PASSWORD" \
  --mount type=bind,src=/srv/kafdeck/appsettings.Production.json,dst=/app/appsettings.Production.json,readonly \
  --mount type=bind,src=/srv/kafdeck/secrets,dst=/run/secrets,readonly \
  --mount type=bind,src=/srv/kafdeck/state,dst=/var/lib/kafdeck \
  --tmpfs /tmp:rw,nosuid,nodev,size=64m \
  ghcr.io/araditc/kafdeck@sha256:8e84e47793f663e02226cb11ca43f60835f87663dca6f76b1075975a91f489f0
```

This binds only the host's loopback interface. Use a deliberate host/interface mapping and certificate SAN for LAN access. The browser's `https://127.0.0.1:8080` origin works only if the certificate and registered Keycloak callback include that exact origin. Kafdeck's container must reach the issuer and brokers using their real reachable/advertised addresses; `127.0.0.1` inside the container is not the host or another container. Configure host/CNI egress for the approved destinations.

Issue a setup code with `docker exec kafdeck dotnet /app/Kafdeck.Api.dll --contentRoot /app --issue-setup-code`, open the HTTPS origin, create the first owner without email verification, then sign in through Keycloak. Continue with [users and recovery](managed-identity-setup.md) and [adding clusters and dashboard operations](v0.9-dashboard-guide.md). `/healthz` confirms the listener, not successful login or Kafka access.

For an offline image, load the verified architecture archive under `v09-media/media/distribution/.../kafdeck-linux-ARCH.docker.tar.gz` and use its retained local image reference/config identity. A loaded Docker archive's local reference is distinct from the published OCI multiarchitecture index digest. Do not assume `docker load` creates the GHCR index reference. Podman can use the same verified media/configuration; account for its rootless user mappings and host volume labels/permissions.

## Native Windows, Linux and macOS

After media verification, select `v09-media/media/native/RID/kafdeck-api-ui-RID.tar.gz` and extract into a dedicated application directory. Stage private configuration, writable identity/application state and TLS files separately. Run `Kafdeck.Api.exe` on Windows or `./Kafdeck.Api` on Unix, with `--contentRoot` pointing at the configuration directory. Set `ASPNETCORE_ENVIRONMENT=Production` and Kestrel certificate settings in the service environment. Windows examples must use absolute Windows state/secret paths, not the Linux paths in the example JSON.

Run the same executable with `--issue-setup-code` and the same content root/environment to provision the first administrator. Do not run a second listener to generate the code. CLI and MCP are separate archives for the same RID; follow the [human CLI sign-in](v0.8-cli-human-oidc-runbook.md) and [MCP](v0.8-mcp.md) guides using the release's `0.9.0` packages. Their versioned authentication/safety contracts remain applicable.

## Helm

Use the verified chart at `v09-media/media/distribution/w81-helm-lifecycle-01c7553425fbc61ba4a7a21918265c562086ba02/kafdeck-0.9.0.tgz` (SHA256 `3e403f55c185ca0eb855ee96347d52b27e15e7729f2f139a4aee3702b3d851d1`). The release also exposes this exact archive as a flattened `media__distribution__...` asset; rename it locally only after hash verification.

Create the namespace and its existing ConfigMap, credential/TLS Secrets, private-registry pull secret and writable PVC. Set `image.repository`, `image.digest`, `image.pullSecret`, `publicHost`, `operatorConfigMap`, `credentialsSecret`, `tlsSecret`, `oidc`, `kafka`, `persistence` and `network` using the [chart defaults/schema](../../deploy/helm/kafdeck/values.yaml) and [chart guide](../../deploy/helm/kafdeck/README.md). The ConfigMap contains `appsettings.Production.json`; TLS keys are `tls.pfx`/`tls-password`. PostgreSQL credentials include `postgres-connection`. Keep credentials out of values files. For managed identity, put the two separate client-secret keys in the existing credentials Secret, and change the example browser secret reference to `file:/run/kafdeck-credentials/kafdeck-browser-secret` and `ManagedIdentity.ServiceSecretFile` to `/run/kafdeck-credentials/kafdeck-management-secret`. The chart already mounts that Secret read-only at `/run/kafdeck-credentials`, the configuration at `/app/appsettings.Production.json`, and the persistent claim at `/var/lib/kafdeck`; its persistent HOME also lives there. Do not copy the Docker-only `/run/secrets` paths unchanged into this chart configuration. External OIDC bindings remain a separate installation mode.

```sh
helm template kafdeck ./kafdeck-0.9.0.tgz --namespace kafdeck --values kafdeck-values.yaml
helm upgrade --install kafdeck ./kafdeck-0.9.0.tgz \
  --namespace kafdeck --values kafdeck-values.yaml --wait --timeout 5m
kubectl --namespace kafdeck rollout status deployment/kafdeck-kafdeck --timeout=5m
```

Both admitted profiles use **one application replica and Standalone execution**: SQLite, or external PostgreSQL with database HA. Multi-application-Pod HA is not claimed. The Service exposes HTTPS port 443; configure ingress/routing to the intended origin separately. Actual release Helm lifecycle tests used Kubernetes 1.34.3 and Helm 3.21.4. Verify egress in the target deployment; the functional Kind test is not NetworkPolicy certification for every CNI. Uninstall retains the precreated claim/configuration objects.

## Upgrade, restore and air-gap

Record the old binary/digest, configuration, issuer, databases and pending/unknown operations. Make and verify consistent backups of the databases, identity state, matching Keycloak realm and Data Protection key ring. Fence old application/background writers before migration. Exercise the upgrade against an isolated restored copy first. After restore, keep quarantine until the owning generation-admission procedure completes; do not restart stale writers or blindly replay unknown effects.

Rollback restores the **pre-upgrade backup with its original binary**, not a presumed down-migration. Follow the [distribution/recovery runbook](../operations/v0.9-distribution-recovery.md#upgrade-and-restore). For air-gap, stage the verified full mirror, Cosign/trust material, external service images/dependencies and private networking/DNS before transfer; verify again inside the enclave. A private local IdP/Kafka/database is still required. Release test scripts that enforce loopback-only namespaces are isolated acceptance fixtures, not a turnkey production installer.

## First-start checklist

- The HTTPS origin and certificate match the browser and Keycloak redirect settings.
- Uninitialized installations accept only a current local setup code; initialized installations show sign-in.
- The first owner can sign in, register/test a cluster and see it selected in Topics.
- A separately created user sees only assigned clusters and changes their temporary password.
- Topic details, consumer lag/offsets and configured ecosystem services return actual provider data.
- Persistent state/key storage survives a service restart; the required Kafka credential lease is reacquired.
- Egress rejects an out-of-policy destination from the actual runtime.

For errors, use the [setup troubleshooting table](managed-identity-setup.md#troubleshooting) and [dashboard guide](v0.9-dashboard-guide.md).
