# Install Kafdeck 1.0.0

Download stable media from the [1.0.0 release](https://github.com/araditc/Kafdeck/releases/tag/v1.0.0). The product source is `0617a87ddc176b8255ca1452fc53c097008d9a51`. Choose the deployment matching your operating environment and the [admitted support matrix](v1.0-support-matrix.md).

## Fresh Windows Server with bundled prerequisites

The supplementary `kafdeck-offline-1.0.0-win-x64.zip` includes the self-contained API/dashboard, Java 21, PostgreSQL, Keycloak, Windows Service wrappers and the Java agent. Follow the [English installation guide](windows-offline-install.md) or [Persian RTL guide](windows-offline-install.fa.md). Run `Install-Kafdeck.ps1` as the Windows installation account with Administrator privileges. It prints the HTTPS URL and a 15-minute first-administrator setup code.

For an existing Windows Services installation, extract the new package into a separate folder and run `Upgrade-Kafdeck.ps1`. The [offline upgrade guide](windows-offline-upgrade.md) explains the automatic verified backup, service restart, health checks and rollback. Existing administrator accounts, Kafka connections, certificates and monitoring history are included in the recovery snapshot.

The supplementary installer has its own checksum inventory. The original native runtime archive is covered by the signed full-distribution manifest. The installer scripts and bundled third-party runtimes have a separate provenance record.

### Native application

Choose `media/native/<rid>/kafdeck-api-ui-1.0.0-<rid>.tar.gz`. Available RIDs are `win-x64`, `linux-x64`, `linux-arm64`, `osx-x64` and `osx-arm64`. Extract the complete archive. The application is self-contained. Keep configuration, secrets and persistent state outside the binary directory.

For a manually managed installation, adapt the [managed configuration template](examples/v0.9-managed-appsettings.json), configure your concrete HTTPS origin and Keycloak issuer, then launch with the intended content root and web root

```powershell
C:\Kafdeck\app\Kafdeck.Api.exe --contentRoot C:\Kafdeck\config --webroot C:\Kafdeck\app\wwwroot
```

```sh
/opt/kafdeck/Kafdeck.Api --contentRoot /etc/kafdeck --webroot /opt/kafdeck/wwwroot
```

Set the Production environment and supply certificate secrets through the documented secret references/environment. Use the [managed identity guide](managed-identity-setup.md) for separate Keycloak browser/provisioning clients, persistent keys, first-owner setup and user management. The bundled Windows installer performs this configuration for a fresh server.

## First administrator and Kafka cluster

1. Open the HTTPS address printed by the installer. For manual deployments issue the setup code using the application executable with `--issue-setup-code` and the same content root/service identity.
2. Enter the code, email and password to create the first administrator. Initial email verification is disabled. Sign in through Keycloak.
3. Open **Kafka connections**, enter bootstrap servers and the security protocol, complete any TLS/SASL fields, test and save. Select the saved cluster in the dashboard.
4. Use **Topics** for configuration and authorized record operations, **Consumers** for member/offset/lag inspection, and **Schemas** or **Ecosystem** for separately configured service endpoints.
5. Open **Monitoring**, select the sampling interval and configure sources. Install the [Java 21-compatible agent](kafka-agent.md) on each broker JVM to collect CPU, GC and broker-local measurements.
6. Create additional users and cluster assignments through **Manage users**.

The [dashboard walkthrough](v0.9-dashboard-guide.md) retains the applicable operating flows. The [current capability matrix](../product/current-capabilities.md) and [compatibility policy](v1.0-compatibility-support.md) define the available and Stable/Experimental surfaces.

## Upgrade and recovery

Use the single-script [Windows offline upgrade](windows-offline-upgrade.md) for the supported bundled Windows Services layout. For manually managed native/container/Helm installations, retain a consistent database/configuration/keyring backup and the original binaries, then follow the [distribution recovery procedure](../operations/v0.9-distribution-recovery.md) and [source-bound RC upgrade admission](../releases/v1.0-rc-admission.md). Restore requires writer fencing and generation reconciliation where governed durable operations are configured. Each historical acceptance record retains its original source and deployment limits.
