# v1.0 compatibility and bounded support

The product owner accepted [RFC-0010](../rfcs/0010-v1.0-contract-stability-support.md) on 2026-11-13. These guarantees take effect for explicitly selected contracts when v1.0 is published. The current released v0.9 bytes and historical evidence are unchanged; this guide is not a v1.0 release announcement.

## Contract selection

The [contract inventory](../implementation/v1.0-contract-inventory.md) and its versioned machine baselines enumerate the selection. A mapped handler alone does not grant Stable status. Stable REST method/path, typed inputs/outputs/errors, authorization semantics and bounds require an enumerated contract. CLI machine outputs/exit meanings and selected MCP schemas/effect boundaries are frozen; human help/table prose is not a machine API. Dashboard onboarding/users/connections/session/CSRF APIs remain Experimental and dashboard coupled, with their existing authentication and regression requirements.

Terraform remains independently versioned at 0.8.0, limited to the admitted notification-subscription resource/data source and schema-1/version-0 migration. No Registry publication, additional resources, provider parity or automatic approval is promised. DOM/CSS, private persistence layouts and undeclared implementation symbols are Internal. Persistence recovery follows ADR-0011; direct table/file editing is not a supported integration.

## Changes, upgrades and support

| Subject | Accepted boundary |
| --- | --- |
| Incompatible Stable change | Applicable major contract/component version plus migration documentation |
| Planned removal | Announce at least one released minor **and** 90 days before removal; removal still requires the applicable major |
| Additive output | Minor-compatible only where unknown fields are explicitly allowed; closed schemas/enums/fingerprints retain version negotiation |
| Emergency security containment | May deny unsafe effects with advisory/reason/upgrade guidance; never bypass owner release admission or weaken authorization |
| Initial upgrade | Released v0.9 to selected v1.0 media, after final RC-bound V1-4 acceptance |
| Rollback | Verified backup, matching private keys, original binary/configuration and fenced workers; no downgrade/mixed-writer or universal zero-downtime promise |
| Security/community fixes | Latest supported released minor and its current patch; backports require explicit selection and affected checks |
| Service commitment | No automatic LTS, commercial SLA, response-time or delivery-date guarantee |
| Supported deployment cells | Exactly the final admitted Kafka/provider/OS/architecture/database/CNI cells; KAF-02 requires deployment-tested egress |

Configuration precedence remains the actual ASP.NET configuration pipeline: application JSON, environment-specific JSON, environment overrides (`__` for `:`) and command-line overrides in their configured order. The Kafdeck loader prefers nonempty `Deployment:ListenUrls` over legacy `ListenUrl`; defaults and validation remain source-bound in the inventory. `env:` and absolute `file:` secret references retain validation and redaction; an environment fallback does not become a secret value in client output. Helm values are limited to the selected chart schema and documented validation; a chart value is not blanket topology acceptance.

Final supported cells, current dependency/image/secret scans, RC/offline-media acceptance, signing and publication remain separate V1-4–V1-7 gates. Reuse successful v0.9 evidence with its original source/platform limits; do not rerun load/soak campaigns merely for this policy document.
