# راه‌اندازی میزبان‌های Kafka از داشبورد

این قابلیت به بیلد دارای راه‌اندازی Fleet از داشبورد نیاز دارد. بستهٔ منتشرشدهٔ ۱.۱.۰ قدیمی، این قابلیت تازه را ندارد. [راهنمای انگلیسی](fleet-dashboard-onboarding.md) مرجع کامل است.

۱. با ادمین اصلی وارد شوید، کلاستر را انتخاب کنید و در **Fleet → Broker hosts → Fleet settings and SSH credentials** مدیریت میزبان را فعال کنید. IP مجاز را به شکل CIDR وارد و ذخیره کنید؛ مثلاً برای یک سرور از `192.168.100.33/32` استفاده کنید. تنظیمات بلافاصله اعمال می‌شوند.

۲. قسمت **Prepare a Linux host from the dashboard** را باز کنید. نام، IP، پورت SSH، کاربر موقت مدیر، رمز یا کلید خصوصی و در صورت نیاز رمز sudo را وارد کنید. اثر انگشت SSH را از کنسول معتبر یا مدیر سرور تأیید کنید. **Test SSH and inspect services** سرویس‌های واقعی و تطابق شناسهٔ بروکر و کلاستر را بررسی می‌کند. برای systemd نیازی به Docker نیست.

۳. سرویس‌های مورد نظر را انتخاب کنید. آدرس HTTPS دریافت متریک باید از خود بروکرها قابل دسترسی و پورت آن در فایروال مجاز باشد. `127.0.0.1` روی بروکر راه‌دور به سرور Kafdeck اشاره نمی‌کند. گواهی عمومی، فاصلهٔ نمونه‌برداری و بازهٔ نگهداری UTC را تنظیم کنید. برای گواهی محلی می‌توانید **Use this Kafdeck server certificate** را بزنید.

۴. نسخه و SHA256 بسته را بررسی و آماده‌سازی را تأیید کنید. حساب‌های SSH محدود، helperها، بستهٔ عامل و تنظیمات اجرا آماده می‌شوند. اطلاعات موقت مدیر در دیتابیس ذخیره نمی‌شود. کلیدهای محدودِ تولیدشده و رمزهای ذخیره‌شده، پیش از ثبت در دیتابیس رمزگذاری می‌شوند. این مرحله Kafka را ری‌استارت نمی‌کند.

۵. در **Offline broker agent** پیش‌نمایش را بگیرید. بعد از تأیید سلامت Kafka و ایمنی replicaها، ری‌استارت همان بروکر را تأیید کنید. تا تأیید سلامت و رسیدن متریک تازه، **Check agent operation** را ادامه دهید. برای بروکر بعدی از **Select the broker for the next agent change** استفاده کنید. عملیات ناتمام را پیش از انتخاب مقصد جدید تعیین تکلیف کنید.

اگر نتیجهٔ آماده‌سازی نامشخص بود، وضعیت همان عملیات را بررسی کنید؛ عملیات تازه و تکراری نسازید. برای آماده‌سازی ناقص، دسترسی موقت مدیر را دوباره وارد و ادامهٔ همان عملیات را تأیید کنید. نبود متریک تازه هرگز موفقیت فرض نمی‌شود.

## کلیدها و پشتیبان‌گیری

کلید خصوصی و رمز ذخیره‌شده قابل نمایش یا دانلود نیستند. برای تعویض، مقدار جدید وارد کنید. لغو اطلاعات ورود، استفادهٔ بعدی از آن را در Kafdeck متوقف می‌کند؛ حذف کلید عمومی از Linux، اقدام مدیریتی جداگانه است.

برای پشتیبان‌گیری سرد، Kafdeck را متوقف کنید و کل وضعیت نصب، دیتابیس مانیتورینگ، کلیدهای Data Protection برنامه و پوشهٔ کامل `<StateFile>.fleet` را نگه دارید. دیتابیس رمز‌شده و پوشهٔ جداگانهٔ `keys` هر دو لازم‌اند. پشتیبان را هم رمزگذاری کنید. کلیدهای Windows به همان حساب سرویس و همان ماشین وابسته‌اند؛ کپی‌کردن آن‌ها به سرور دیگر به‌تنهایی امکان رمزگشایی نمی‌دهد. در Linux مالکیت و مجوزهای محدود فایل‌ها را حفظ کنید.

برای Compose، تنظیمات اجرایی در snapshot محافظت‌شدهٔ root ثبت می‌شوند؛ hash پیکربندی در حال اجرا و فایل‌های اصلی بررسی می‌شود و فقط همان سرویس با image فعلی، بدون pull یا build بازسازی می‌شود. اندازهٔ snapshot نهایی حداکثر ۲۵۶ کیلوبایت است؛ پروژهٔ بزرگ‌تر در همان مرحلهٔ آماده‌سازی رد می‌شود تا هدف غیرقابل‌نصب ثبت نشود. متریک تازهٔ JVM باید همراه با متریک Kafka از همان منبع باشد. زمان تأیید JVM از SSH، شروع کند Java را پوشش می‌دهد و نبود متریک هرگز موفقیت فرض نمی‌شود.
