# نصب آفلاین Kafdeck با یک اسکریپت

این بسته **Java 21، PostgreSQL 17، Keycloak، Kafdeck، عامل Kafka و runtime لازم ویندوز** را داخل خودش دارد. هنگام نصب به اینترنت، نصب جداگانهٔ Java یا Keycloak سازمانی نیاز ندارید.

برای Windows Server 2019/2022 با معماری x64 و شبکهٔ داخلی آماده شده است. حداقل ۴ گیگابایت فضای خالی برای نصب داشته باشید؛ فضای تاریخچهٔ مانیتورینگ جداست. بستهٔ فعلی build آزمایشی مانیتورینگ است.

## فقط این کارها را انجام دهید

1. فایل `kafdeck-offline-win-x64.zip` را روی سرور ببرید. پس از تطبیق checksum تحویل‌شده، آن را در **C:\Kafdeck-Setup** استخراج کنید. برنامه در **C:\Kafdeck** نصب می‌شود؛ این دو مسیر باید جدا باشند.
2. منوی Start را باز کنید، **Windows PowerShell** را پیدا کنید، راست‌کلیک و **Run as administrator** را بزنید.
3. این دو خط را اجرا کنید:

<div dir="ltr">

```powershell
Set-Location C:\Kafdeck-Setup
.\Install-Kafdeck.ps1
```

</div>

4. به سؤال‌ها پاسخ دهید: **IP همین ویندوزسرور**، **IP میزبان‌های Kafka** و **رمز همان حساب ویندوز** برای اجرای خودکار. برای Arad Office فعلی، IP میزبان Kafka برابر `192.168.100.33` است؛ پورت ننویسید. رمز ویندوز، رمز ادمین Kafdeck نیست و در فایل تنظیمات ذخیره نمی‌شود؛ Service Control Manager ویندوز آن را نگه می‌دارد.
5. پنجره را باز بگذارید. راه‌اندازی اول Keycloak چند دقیقه طول می‌کشد. در پایان، **آدرس ساخت ادمین اول** و **کد یک‌بارمصرف با اعتبار ۱۵ دقیقه** نمایش داده می‌شوند.

اگر پیام «running scripts is disabled» گرفتید، پس از بررسی منبع فایل، فقط برای همان پنجره اجرا کنید و دستور نصب را تکرار کنید:

<div dir="ltr">

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\Install-Kafdeck.ps1
```

</div>

اگر فایل دانلودشده مسدود است، در Properties خود ZIP گزینهٔ Unblock را پس از بررسی منبع بزنید و دوباره استخراج کنید. محدودیت Group Policy سازمانی را دور نزنید؛ مسئول ویندوز باید فایل‌ها را مجاز کند.

## ادمین اول را بسازید

آدرسی را که نصب‌کننده چاپ می‌کند در مرورگر **همین سرور** باز کنید. شکل آن چنین است:

<div dir="ltr">

```text
https://IP-OF-YOUR-SERVER:8080/
```

</div>

کد یک‌بارمصرف، ایمیل و رمز ادمین اول را بدهید. رمز حداقل ۱۲ کاراکتر باشد. **ایمیل تأیید ارسال نمی‌شود.** سپس با همین حساب از صفحهٔ Keycloak وارد شوید.

آدرس و کد در فایل خصوصی زیر هم ذخیره می‌شوند:

`C:\Kafdeck\secrets\FIRST-ADMIN.txt`

اگر کد منقضی شد و هنوز ادمین اول را نساخته‌اید، با همان حساب ویندوز اجرا کنید:

<div dir="ltr">

```powershell
C:\Kafdeck\scripts\New-SetupCode.ps1
```

</div>

بعد از ساخت ادمین، این دستور دیگر حساب جدید یا رمز جایگزین نمی‌سازد؛ وارد حساب موجود شوید.

## نصب‌کننده چه می‌کند؟

فایل‌ها و checksumها را بررسی می‌کند؛ Java و Keycloak را در پوشهٔ برنامه قرار می‌دهد؛ PostgreSQL اختصاصی را با احراز هویت SCRAM و پورت **15432 فقط روی 127.0.0.1** راه می‌اندازد؛ Realm، Clientها و حساب نگهداری سیستم ورود را می‌سازد؛ گواهی HTTPS سرور را ثبت می‌کند؛ اجرای خودکار را تنظیم و آماده‌شدن سرویس‌ها را بررسی می‌کند. هر سه جزء Windows Service واقعی هستند و در services.msc دیده می‌شوند: **Kafdeck-PostgreSQL**، **Kafdeck-Keycloak** و **Kafdeck**. PostgreSQL با NetworkService و دو سرویس دیگر با همان حساب ویندوز نصب اجرا می‌شوند؛ حساب ویندوز جدیدی ساخته نمی‌شود. WinSW 2.12.0 داخل بسته است و نیازی به دانلود جداگانه ندارد.

پورت‌های **8080 و 8443** فقط برای LocalSubnet و آدرس‌های Kafka واردشده در firewall باز می‌شوند. هنگام بوت، PostgreSQL با Automatic و دو سرویس دیگر با Automatic (Delayed Start) شروع می‌شوند. وابستگی‌ها به ترتیب PostgreSQL ← Keycloak ← Kafdeck ثبت می‌شوند. علاوه بر وضعیت Running، اتصال واقعی دیتابیس و آماده‌شدن endpoint ورود بررسی می‌شود. بستن پنجرهٔ نصب یا خروج از حساب ویندوز سرویس‌ها را متوقف نمی‌کند. شکست فرایند موجب راه‌اندازی مجدد خودکار سرویس می‌شود. حساب یا دیتابیس نصب قبلی جایگزین نمی‌شود. اگر نصب نیمه‌تمام ماند، همان بسته را با همان حساب و مسیر دوباره اجرا کنید؛ اطلاعات موجود پاک نمی‌شوند. نصب‌کننده نتیجهٔ نامعلوم ساخت دیتابیس را خودسرانه بازنشانی نمی‌کند.

## کنترل سرویس‌ها و بررسی پس از ری‌استارت

در PowerShell مدیریتی وضعیت را ببینید:

<div dir="ltr">

```powershell
Get-Service Kafdeck-PostgreSQL,Kafdeck-Keycloak,Kafdeck
C:\Kafdeck\scripts\Test-InstalledServices.ps1 -RequireReboot
```

</div>

پس از ری‌استارت، هر سه باید Running شوند و آدرس برنامه باز شود. شروع اول Keycloak چند دقیقه زمان می‌برد. برای خاموش‌کردن مرتب، از برنامه به دیتابیس متوقف کنید؛ برای روشن‌کردن، برعکس:

<div dir="ltr">

```powershell
Stop-Service Kafdeck
Stop-Service Kafdeck-Keycloak
Stop-Service Kafdeck-PostgreSQL

Start-Service Kafdeck-PostgreSQL
Start-Service Kafdeck-Keycloak
Start-Service Kafdeck
```

</div>

این بسته برای **نصب تازه** است. اگر بستهٔ قبلی دارای Scheduled Task را قبلاً نصب کرده‌اید، نصب‌کننده آن را خودکار جایگزین نمی‌کند؛ پوشهٔ state یا دیتابیس را برای رفع تداخل پاک نکنید. راه‌اندازی مجدد نصب نیمه‌تمام فقط با همان نسخهٔ بسته، حساب و مسیر انجام می‌شود.

## ورود از کامپیوتر دیگر و عامل‌ها

گواهی داخلی این نصب یک سال اعتبار دارد. برای مرورگر روی کامپیوتر دیگر، فقط فایل عمومی **C:\Kafdeck\public\server-public.cer** را به آن ببرید و با دسترسی Administrator در همان کامپیوتر اجرا کنید:

<div dir="ltr">

```powershell
Import-Certificate -FilePath C:\Path\server-public.cer -CertStoreLocation Cert:\LocalMachine\Root
```

</div>

فقط گواهی نصب خودتان را اعتماد کنید. فایل‌های PFX، DPAPI یا secrets را منتقل نکنید. مرورگر و callback ورود باید از همان IP تعیین‌شده هنگام نصب استفاده کنند. این روش برای شبکهٔ داخلی است؛ انتشار اینترنتی به گواهی و طراحی استقرار مناسب نیاز دارد.

پس از ورود، از **Kafka connections** اتصال بسازید و Test connection را بزنید. برای CPU، GC و نمودارهای بروکر، [عامل Java 21](kafka-agent-java21.fa.md) را روی بروکرها نصب کنید. خود عامل داخل بسته هست؛ endpoint آن باید به IP همین سرور جدید اشاره کند و برای CA خصوصی از فایل عمومی `server-public.pem` استفاده کند. نصب روی ویندوز، عامل را خودکار روی سرورهای Kafka راه دور نصب نمی‌کند.

## اگر مشکل پیش آمد

- اگر نصب‌کننده درخواست ری‌استارت کرد، ویندوز را ری‌استارت و **همان بسته** را دوباره اجرا کنید.
- اگر پورت یا مسیر از قبل استفاده می‌شود، نصب متوقف می‌شود و سرویس قبلی تغییر نمی‌کند.
- لاگ‌های نصب و برنامه‌ها در **C:\Kafdeck\logs** هستند؛ برای بررسی، از پاک‌کردن state یا دیتابیس خودداری کنید.
- در **services.msc** هر سه نام **Kafdeck-PostgreSQL**، **Kafdeck-Keycloak** و **Kafdeck** را ببینید. اگر رمز حساب ویندوز را عوض کردید، در Properties → Log On دو سرویس Kafdeck و Keycloak رمز جدید را ثبت کنید. تغییر حساب اجرا بدون مهاجرت کلیدها باعث خطای DPAPI می‌شود.
- برای این حساب مجوز Log on as a service ثبت می‌شود. اگر Group Policy سازمان آن را منع کرده، مدیر ویندوز باید سیاست را اصلاح کند؛ اسکریپت سیاست سازمان را دور نمی‌زند.
- لاگ‌های سرویس‌ها در logs با چرخش فایل نگه‌داری می‌شوند؛ Event Viewer → Windows Logs → System نیز خطاهای SCM را نشان می‌دهد.
- برای مدیر نگهداری Keycloak، با همان حساب ویندوز فایل **C:\Kafdeck\scripts\Show-RecoveryInfo.ps1** را اجرا کنید. رمز نگهداری را خصوصی نگه دارید؛ این حساب با ادمین Kafdeck فرق دارد. مدیر موقت پس از تأیید حساب دائمی حذف می‌شود.
- برای بررسی رسانه بدون نصب، `Install-Kafdeck.ps1 -VerifyOnly` را اجرا کنید.

از کل **state، config و secrets** و دیتابیس Keycloak پشتیبان هماهنگ بگیرید. کلیدهای Data Protection در **state\keys** نگه‌داری می‌شوند. این نصب به حساب ویندوز و DPAPI همان دستگاه وابسته است؛ کپی‌کردن پوشه‌ها به دستگاه دیگر به‌تنهایی مهاجرت معتبر نیست.

قواعد firewall این نصب برای ورودی‌اند. برای استقرار عملیاتی، کنترل و آزمون egress میزبان همچنان لازم است؛ فهرست IP مجاز ثبت اتصال به‌تنهایی جلوی advertised address جدید یک بروکر را نمی‌گیرد. این همان شرط پذیرفته‌شدهٔ KAF-02 است.
