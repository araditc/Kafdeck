# Integrated automation workflow

Open **Automation** after signing in to the operator UI. The panel is scoped to
the current verified session; returning to a tab revalidates identity and clears
authorization-bound panels. Capability discovery never grants write authority.

1. Inspect fleet telemetry, notification delivery evidence and governed operations
   through the linked sections. Those views retain their independent permissions.
2. Supply the registered source, exact canonical manifest SHA256 and expected
   ownership revision. Paste only a bounded NotificationSubscription manifest
   containing safe destination references. Observe current ownership and drift.
3. Read the source pin using the exact resource ID. An explicit source advance
   uses its displayed generation/revision/hash CAS. SourceManage grants neither
   Plan nor Apply. A changed pin does not silently advance from planning.
4. Keep the request idempotency key for this intent. Create a sealed plan, or
   explicitly preview adoption for an existing unowned resource. No operation
   confirms, approves or applies automatically. A new key means a distinct intent.
5. Review before/desired/after, owner/source/hash, expected revision, risk and
   expiry. Confirm using the exact challenge. A distinct eligible human opens
   the saved operation and inspects the immutable plan before independent approval.
6. Apply only from Ready. Backend current permissions, policy, generation,
   ownership, source and product-state fences remain authoritative. A UI checkbox
   or manifest author field does not replace those checks.
7. ExecutionUnknown is not success. Retain the same operation ID, inspect status,
   and use positive-receipt verification only when authorized. The panel never
   redispatches an uncertain effect or treats an absent receipt as negative proof.

Inspect safe-inverse eligibility for a verified completed plan. Only an admitted
inverse is returned. Stage its manifest, explicitly advance the source when
required, then request a **fresh compensation preview** with a distinct key.
The inverse has its own confirmation, risk, independent approval, CAS, execution
and audit. It is not rollback of notification deliveries or other external effects.
Unsupported, retired, drifted, revoked or unresolved operations have no inverse.

CLI, Terraform and MCP use the same saved plan and operation IDs. Terraform binds
`apply_plan_id` and `apply_plan_fingerprint`; PendingApproval/ExecutionUnknown are
incomplete. MCP effects need explicit operator enablement and backend authorization.
Use the shipped declarative CLI, provider and MCP guides for exact syntax, offline
packages and credential setup. This browser panel accepts no bearer credentials,
shell commands, arbitrary URLs, SQL or provider payloads. No provider destroy or
ownership transfer is advertised. Refresh status after external-client work.

Rendered browser acceptance uses clearly labelled API fixtures to verify keyboard,
mobile, session-loss, masking/escaping and uncertainty UI behavior. Genuine identity,
backend effects and independent-human authority are proven by separate hosted tests.
