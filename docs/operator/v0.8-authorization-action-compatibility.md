# Authorization action identity correction

G2 separates Streams and lineage read grants from Connect restart authority.
The earlier enum assigned the same numeric values to both pairs, so ordinary
enum equality could allow a matching read grant to satisfy a write check.

The original Connect values remain `ConnectRestart=46` and
`ConnectAutoRestartManage=47`. They were introduced in commit `29249d8`; the
later read aliases were introduced in `7851e50`. All original values 1–55 stay
unchanged, preserving numeric mutation snapshots, preview/material hashes, and
the original Connect authorization targets. New actions are
`MutationApprove=56`, `StreamsRead=57`, and `LineageRead=58`.

Role configuration uses action **names**, including supported punctuation
variants. Numeric role configuration remains rejected; do not infer a read grant
from an old ambiguous number. Existing persisted numeric mutation targets 46/47
retain their original Connect meaning. There is no historical persisted read-grant
migration because the policy is loaded from named configuration rather than a
numeric policy store. Review any external custom integration that serialized the
later read aliases numerically and replace those grants with explicit names.

A changed read-action policy has a new policy fingerprint. Outstanding governed
previews must pass current authorization and policy revalidation; an old preview
must not retain authority inferred from the former alias.

`V08AuthorizationActionIsolationTests` guards unique enum identity, every original
numeric value, negative Streams/lineage→Connect authority, named configuration,
numeric configuration rejection, and legacy numeric mutation-target JSON.
