# G2 isolated identity and Kafka laboratories

These are disposable acceptance fixtures. Runtime support and protected-main
acceptance are recorded separately in the G2 ledger. Published release remains
v0.7; these scripts do not approve a production issuer or publish a release.

## Keycloak human CLI

Use the official Keycloak 26.8.1 ZIP after verifying SHA256
`4cd312c889af358a819a74a6c6f068f9ea159a6959e49924607cec95cfd4c1a4`.
The portable Java 21 runtime used for G1 may be reused. No OS trust installation
or certificate-validation bypass is necessary.

```powershell
./deploy/dev/prepare-keycloak-g2.ps1 -KeycloakHome <verified-keycloak-home>
$identity = Join-Path (Get-Location) 'deploy/dev/.generated/g2/identity'
$lab = Get-Content (Join-Path $identity 'lab.json') -Raw | ConvertFrom-Json
$env:JAVA_HOME = '<portable-java-21-home>'
$env:KC_HTTPS_KEY_STORE_PASSWORD = [IO.File]::ReadAllText((Join-Path $identity 'https-password.txt'))
$env:KC_DB_URL = $lab.databaseUrl
& (Join-Path $lab.keycloakHome 'bin/kc.bat') start --db=dev-file `
  --http-host=127.0.0.1 --http-enabled=false --https-port=18444 `
  --hostname=https://localhost:18444 `
  "--https-key-store-file=$(Join-Path $identity 'https.p12')" --cache=local --import-realm
```

On Linux use `bin/kc.sh` with the same options. `KC_DB_URL` avoids Windows BAT
splitting the semicolon in the H2 JDBC URL. Preparation requires a fresh output
directory: reimporting with `IGNORE_EXISTING` must not silently retain old keys
while a manifest points to new ones.

The new realm is `kafdeck-g2`; its exact issuer is
`https://localhost:18444/realms/kafdeck-g2`, audience `kafdeck-api-g2`.
The public client `kafdeck-g2-cli` enables authorization code with required S256,
disables implicit/direct-access/service-account grants and registers only numeric
loopback `/oauth/callback`. Keycloak's native-app rule ignores the port; the CLI
binds its ephemeral listener before navigation and validates the exact callback
address, path, port, state, issuer and code proof. See the official
[redirect rules](https://www.keycloak.org/securing-apps/oidc-layers).

The human client explicitly maps the real user subject into its access token.
Removing all default scopes also removes Keycloak's `basic` subject mapper; an
ID token's subject alone cannot authorize an API access token without `sub`.
The fixture adds `oidc-sub-mapper` and retains mandatory subject checks in both
CLI and API. See the official [basic-scope migration notes](https://github.com/keycloak/keycloak/blob/main/docs/documentation/upgrading/topics/changes/changes-25_0_0.adoc).

Generated keys, passwords, H2 database and tokens must remain in ignored
`.generated` directories. The manifest contains public metadata and paths to
secret files; never print their contents or put passwords on the CLI command line.

```powershell
$env:KAFDECK_KEYCLOAK_G2_LAB = Join-Path $identity 'lab.json'
$env:KAFDECK_G2_EVIDENCE_DIRECTORY = Join-Path (Get-Location) 'artifacts/g2/identity'
dotnet test tests/Kafdeck.Architecture.Tests/Kafdeck.Architecture.Tests.csproj `
  -c Release --no-build --no-restore --filter FullyQualifiedName~V08G2HumanCliLiveTests
```

The acceptance driver submits the real Keycloak HTML login form, then follows
the authorization-code callback to the actual CLI listener. It does not use a
password grant or manufacture access tokens. This establishes the protocol path,
not graphical browser launch/interaction, Keycloak HA or upgrade behavior.

## Disposable Kafka effect fixture

Download official Apache Kafka `kafka_2.13-4.3.1.tgz` and verify SHA512
`c7d7b2318cb51aa0c61d3246a51c349210073c5c9b754947ef965a439f2f939e8600f204e134a75ac31faf3829c9370960ef7c6a9886c8a1dbf0339a21f4c54c`
against the [Apache checksum](https://downloads.apache.org/kafka/4.3.1/kafka_2.13-4.3.1.tgz.sha512).
Extract only after the checksum matches.

```powershell
./deploy/dev/prepare-kafka-g2.ps1 -KafkaHome <verified-kafka-home> -JavaHome <java-21-home>
$broker = Get-Content deploy/dev/.generated/g2/kafka/instance/lab.json -Raw | ConvertFrom-Json
& $broker.javaExecutable -Xms128m -Xmx512m `
  "-Dkafka.logs.dir=$(Join-Path (Split-Path $broker.configFile) 'logs')" `
  "-Dlog4j2.configurationFile=$(Join-Path $broker.kafkaHome 'config/log4j2.yaml')" `
  -cp (Join-Path $broker.kafkaHome 'libs/*') kafka.Kafka $broker.configFile
```

Preparation refuses to reformat an existing instance. Broker/controller bind only
to `127.0.0.1:19092/19093`, automatic topic creation is disabled, and test topics
have unique names. Stop only the fixture's recorded process. This one-node
plaintext loopback experiment is not Kafka TLS/SASL, HA or Windows production
support evidence. Use the repository's Kafka compatibility CI for supported tiers.

The native Windows fixture failed a real topic-delete experiment: Kafka could
not rename an open partition directory, marked its log directory failed and shut
down. Preserve that data/log directory for diagnosis; select a fresh instance
directory for subsequent experiments, never reformat it in place. This failure
cannot establish successful delete readback or Kafka Windows support.

The CRITICAL TopicDelete acceptance therefore requires an explicitly disposable
broker that supports deletion: set `KAFDECK_G2_KAFKA_DELETE_CAPABLE=1` alongside
the Keycloak manifest and bootstrap address. The Linux G2 CI job starts its own
container, forces this case and requires
`critical-human-approval-kafka-evidence.json`. Without that capability the test
reports an explicit skip, which does not satisfy CRITICAL acceptance. This is a
broker-fixture constraint; a Windows CLI against an admitted remote Linux broker
can run the case with that explicit capability.

The identity preparation also creates a second real human
`kafdeck-g2-approver`. Its separate generated password remains in the ignored
directory; the manifest exposes only `approverSubject`, `approverUsername` and
`approverPasswordFile`. The two-human proof must retain exact distinct requester
and approver identities and current grants, not substitute a synthetic approval.
