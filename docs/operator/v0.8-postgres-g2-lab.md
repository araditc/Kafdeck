# G2 portable PostgreSQL acceptance laboratory

This isolated Windows fixture uses PostgreSQL **17.11**, EDB packaging revision
**17.11-5**, on `127.0.0.1:15432`. It installs no Windows service, modifies no OS
trust store, and creates its data, logs and random credentials only under ignored
`deploy/dev/.generated/g2/postgres`.

## Verified distribution

The [PostgreSQL Windows download page](https://www.postgresql.org/download/windows/)
links the [EDB portable binaries](https://www.enterprisedb.com/download-postgresql-binaries).
The pinned archive is `postgresql-17.11-5-windows-x64-binaries.zip` from
`https://get.enterprisedb.com/postgresql/`. Its SHA256 is
`80379b2c04d51c30225532e0ae04509899141e9957ed096fe749d7fd9df8f82f`,
published by the EDB repository contributor on 2026-10-06 in
[EnterpriseDB/edb-installers #731](https://github.com/EnterpriseDB/edb-installers/issues/731).
This is a publisher-supplied archive digest, not a locally invented checksum or
an assertion that each executable carries an Authenticode signature.

`prepare-postgres-g2.ps1` checks the archive before extracting or executing any
file. It extracts only `pgsql/bin`, `pgsql/lib` and `pgsql/share`, refuses path
escape, and records a completion marker. An archive/hash mismatch stops setup.
Existing partial data directories and changed fixture ports require inspection;
the script never deletes or resets a database.

## Prepare and start

Use PowerShell 7 from the repository root:

```powershell
./deploy/dev/prepare-postgres-g2.ps1 -Action Prepare
./deploy/dev/prepare-postgres-g2.ps1 -Action Start
./deploy/dev/prepare-postgres-g2.ps1 -Action Status
```

Initialization uses a cryptographically random password and SCRAM-SHA-256.
The generated `g2_owner` is the fixture's database superuser so existing tests
can create isolated schemas. It is a disposable local identity, with no
production authority. `fsync` and synchronous commits remain enabled. Passwords
and connection strings must not be printed, committed or uploaded as CI artifacts.

## Run actual database checks

Set the connection string in the current process without displaying it:

```powershell
$env:KAFDECK_TEST_POSTGRES = [IO.File]::ReadAllText(
    (Join-Path $PWD 'deploy/dev/.generated/g2/postgres/connection-string.txt'))
if ([string]::IsNullOrWhiteSpace($env:KAFDECK_TEST_POSTGRES)) {
    throw 'A real PostgreSQL fixture is required.'
}
dotnet test tests/Kafdeck.Architecture.Tests/Kafdeck.Architecture.Tests.csproj --no-restore -m:1 `
    --filter 'FullyQualifiedName~V08G2PostgreSqlProofTests|FullyQualifiedName~V08W66NotificationDeliveryStoreTests|FullyQualifiedName~V08W66DeliveryWorkerTests|FullyQualifiedName~V08W66NotificationRoutingTests|FullyQualifiedName~V05MutationPersistenceTests' `
    --results-directory artifacts/g2/postgres --logger 'trx;LogFileName=postgres-durable.trx'
Remove-Item Env:KAFDECK_TEST_POSTGRES
```

Existing external-database tests return early when this environment variable is
absent. A passing offline run therefore proves no PostgreSQL behavior. For a
database proof, retain sanitized `SELECT version()` output and server start time,
the nonempty required environment gate, exact source revision, TRX and exercised
case names. Do not retain the connection string itself.

The selected tests exercise real durable idempotency/CAS, shared database clock,
rate admission under replica clock skew, stale recovery, history pagination,
resource claims, claim-generation fencing and operation lease renewal.
`V08G2PostgreSqlProofTests` additionally proves two independent worker instances
dispatch one contended delivery only once, then reopens the database to verify
the terminal receipt. Its second case leaves a durable unfinished claim, waits
eleven real seconds against the shared database clock, recovers it as
`UnknownExternalEffect`, and rejects late stale-revision finalization and replay.
The third case observes an actual rate denial using the persisted database claim
timestamps. If a slow physical round trip allows another claim, it requires at
least one database-second between those claims and retries at most three times.
It does not assume that several real database round trips fit one second.
These tests explicitly skip if the database environment is absent, and emit
sanitized `postgres-worker-cas-evidence.json` and
`postgres-recovery-fence-evidence.json`, plus `postgres-rate-clock-evidence.json`,
under `artifacts/g2` (or the deployment
test harness's `KAFDECK_G2_EVIDENCE_DIRECTORY`). They do not use a physical
provider, kill a sender process or claim production HA activation.
These checks use repository/worker instances against one real PostgreSQL
process. They do **not** prove PostgreSQL replication/failover, two physical
sending API hosts, Keycloak multi-node replay protection, or HA production
activation. Those require their own physical topology and crash/restore evidence.

## Stop

```powershell
./deploy/dev/prepare-postgres-g2.ps1 -Action Stop
```

Fast shutdown rolls back active transactions and preserves the fixture data.
Run `Start` to resume the same database. Keep runtime and secret files ignored.
No N4/N5/A6 criterion or release is accepted solely because this lab starts.

## Shared database for a separate Keycloak HA fixture

The local setup can provision a separate `g2_keycloak` database and a
non-superuser `g2_keycloak` role. Its JDBC URL is
`jdbc:postgresql://127.0.0.1:15432/g2_keycloak`; keep its random password under
ignored `deploy/dev/.generated/g2/keycloak-ha/database-password.txt` and pass it
to the Keycloak child environment, never command-line arguments. The ordinary
Kafdeck database tests continue using their independent database/schema scope.
Two Keycloak nodes must use this shared database and distributed caches; two
`--cache=local` development processes are not an HA replay acceptance topology.
