# v0.9 distribution, upgrade, offline and localization plan

Status: W72 design. [W80/W81 acceptance](../testing/v0.9-test-strategy.md) must prove these contracts on candidate artifacts before support is claimed.

## Component/platform admission matrix

| Deliverable | Planned cells / required real acceptance |
|---|---|
| OCI API/UI single container | Linux amd64 and arm64: native launch, readiness, real broker/identity/persistence, nonroot/read-only filesystem with explicit writable state, stop/restart/upgrade/restore. A cell remains build-only until native evidence exists. |
| Self-contained .NET API/UI, CLI and MCP | win-x64, linux-x64, linux-arm64, osx-x64, osx-arm64 per component: native start/help, actual authenticated HTTP operation, TLS/config/secret references, packaging install/remove and upgrade. Unsupported component/RID cells must be explicitly reported and cannot silently disappear from W81. |
| Helm chart | Real isolated Kubernetes lifecycle for OCI-supported architecture and pinned Kubernetes/Helm versions; external Kafka/IdP, SQLite single replica or PostgreSQL admitted HA. Install, readiness, upgrade, migration, failed rollout, uninstall and restore with retained state. |
| Existing Terraform provider | Retain five published platform packages and actual provider safety/compatibility checks; does not imply native API/MCP proof for those RIDs. |

Freeze concrete tool/runtime/base-image/chart dependencies and Kubernetes support versions in W81 from primary documentation and tested jobs. Pin images by digest. Helm schema rejects invalid values, plaintext secret values, SQLite replicas >1, missing external service references and unsafe privilege defaults. Configuration uses typed values and existing Secret references; no secrets in rendered release values, logs or examples. Follow [Helm values guidance](https://helm.sh/docs/chart_best_practices/values/). Document ingress/TLS, egress/network policy, service account minimum rights, nonroot security context, resource limits and explicit writable volumes. Uninstall does not silently delete persistent data.

## Upgrade and restore

Use actual immutable released v0.8 source/artifacts and populated SQLite/PostgreSQL data (including pending/approved/unknown operations), not a freshly created v0.9 schema mislabeled as an upgrade. Capture verified backup, migration ledger/schema hash, original binary identity and restore procedure. Upgrade in maintenance/fenced mode; do not run old/new schema writers concurrently. Failure leaves a documented recoverable state; prove interruption and retried migration behavior. Rollback means restore the verified pre-upgrade backup with its original binary and fenced workers, not an assumed reversible down-migration. Unknown dispatched effects require reconciliation before any new attempt.

## Air-gap and supply chain

Prepare a bounded mirror manifest of exact image digests, native archives, chart and dependencies, hashes, SBOM, provenance and signatures. Verify in connected staging, transfer approved media, and verify again offline using the documented trust root/bundle. Actual network-disabled installation must launch and perform the supported local fixture journey without hidden SaaS/download calls. Missing dependency, tampering, wrong source or absent integrity evidence fails installation. Existing private GHCR requires authorized read access; publication/mirroring does not authorize changing its visibility or disclosing historical images. No production cluster deployment is included.

## Accessibility and localization

Target [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) with automated and manual keyboard/focus/contrast/semantics/screen-reader/mobile evidence; automated scans alone are insufficient. English is authoritative. Add structured English/Persian resources, explicit RTL direction and logical CSS, predictable bidirectional identifiers, safe escaped interpolation, fallback and community translation review. Resource identifiers, amounts, timestamps, policy code, API error/state codes and approval material retain invariant machine representation. Locale cannot alter authorization, risk, confirmation or unknown/recovery semantics. Test English/Persian journeys on actual UI and document tooling/browser/assistive technology versions.
