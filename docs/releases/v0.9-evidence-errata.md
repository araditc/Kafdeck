## Reproduction scope

These are historical laboratory sources, not a turnkey installer or production deployment procedure. The runner expects its original disposable WSL distribution name, root in isolated network namespaces, the source revision `8f4f8b228f91ef6b51e9d679b09a47463a40154c`, staged candidate archive/provenance, pinned K3s/pause assets, Kafka, Helm and a prebuilt portable probe. Its original workspace-relative paths and cleanup logic are preserved. The original lab was removed after the test. A new reproduction must provision and review its own isolated fixture and map those inputs explicitly; do not run this harness against a business cluster or production namespace.

The portable probe uses Confluent.Kafka 2.16.0, verified broker TLS and a disposable one-partition topic. It checks metadata after a changed advertised address, a successful positive-control produce and a restricted `NotPersisted` timeout. The runner corroborates unchanged offsets and no outside SYN packets. It tests the Pod's real network boundary; it does not prove the application's registration/authorization path by itself.

Current deployments must test their actual allowed and denied routes. The observed K3s/flannel/kube-router direct-IP result does not establish admission for every CNI or Service DNAT. Use the [accepted independent security disposition](../security/v0.9-w78-independent-review.md), [current installation guide](../operator/v0.9-installation-guide.md) and [final release record](../implementation/evidence/v0.9-release-published-20261112.json).
