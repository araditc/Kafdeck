## Operational boundaries

Mutation responses AwaitingApproval and ExecutionUnknown are not successful
effects. Critical actions retain distinct human approval, current resource scope,
fresh observed-state CAS, durable idempotency and audit. Compensation is a new
governed mutation; there is no generic rollback or recovered deleted Kafka history.

Notification delivery and automation are opt-in. Server-owned destination and
credential references, configured egress/TLS policy, provider-specific response
handling and durable recovery rules remain authoritative. A real transport fixture
does not certify every SaaS tenant or the operator's production credentials.

The owned Terraform/GitOps family is NotificationSubscription; unsupported
destroy/relinquish and unadmitted Kafka/ACL/connector ownership remain explicit.
MCP uses operator-configured stdio identity, closed typed tools and default-off
effects. No arbitrary URL, SQL, shell, direct broker or database tool is admitted.

## Upgrade and offline deployment

The admitted inverse family is an already-owned NotificationSubscription's exact
verified Active/Paused state toggle; it is not deletion, ownership transfer,
configuration restoration or undoing delivered notifications. Inspect the original
operation, explicitly advance its registered source to the exact inverse manifest,
and request a fresh compensation preview. Confirm and obtain distinct human
approval of the new plan, then use normal governed apply. Original/current receipt,
ownership, source, generation and revision must still match at execution.

| Boundary | Inspect/catalog | Fresh inverse preview |
| --- | --- | --- |
| REST | `GET /api/v1/declarative/compensation/catalog`; `GET /api/v1/declarative/plans/{sourcePlanId}/compensation` | `POST /api/v1/declarative/plans/{sourcePlanId}/compensation-preview` with the typed manifest request and stable Idempotency-Key |
| CLI | `declarative compensation-catalog`; `declarative compensation SOURCE_PLAN_ID` | `declarative compensation-preview SOURCE_PLAN_ID --manifest-file FILE --source REF --source-revision SHA256 --ownership-revision REV` with the normal global idempotency option |
| MCP | `compensation_catalog`; `compensation_inspect` | `compensation_preview`, effects explicitly enabled, with the closed plan schema plus sourcePlanId |

Catalog/read requires current declarative read scope; preview/apply keep the
underlying plan/apply and notification permissions, immutable proof, current CAS
and independent CRITICAL approval. None of the inspection/preview tools confirms,
approves or applies automatically. Terraform destroy remains unadmitted.

The stored plan's optional `CompensatesPlanId` is omitted from JSON when absent,
preserving normal pre-G5 plan serialization/fingerprint compatibility. Existing
normal plans do not acquire inverse authority or get silently rewritten. New
inverse plans bind the original ID and preserve that binding in their fingerprint.
No new provider state migration or implicit source-pin advance is introduced.

Back up metadata and keep the external recovery authority separate before upgrade
or restore. Follow the W66/G2 and W68 migration/recovery guides; unresolved sends or
effects cannot be cleared by an automatic replay. Separate deployment generations
require physical fencing and explicit operator admission.

Install the verified image and client packages from approved local mirrors.
Terraform packages include hashes and executable ZIP modes; MCP is a .NET tool.
Use exact tested broker/runtime/OS versions from the accepted packet. Cross-built
packages alone do not claim tested behavior on additional platforms. No mandatory
public SaaS is required; operator identity, broker and notifier configuration stays
explicit and local-deployment controlled.
