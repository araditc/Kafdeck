# v0.9 prepublication media signing

Status: **completed for official v0.9**, published 2026-11-12. This is the retained maintainer procedure, not an installation step or a request for another signature/acceptance run. Use the [operator installation and verification guide](../operator/v0.9-installation-guide.md) for released media. The [final record](../implementation/evidence/v0.9-release-published-20261112.json) binds actual source, signer/publisher, manifest, readiness and publication. References to current main below describe the historical dispatch-time gate; advancing main does not authorize rerunning this frozen publication selection.

This workflow prepares and, after a separate exact owner decision, signs CI media
for offline acceptance testing. It creates no tag, GitHub Release, package feed
entry, or container registry push. An OIDC signature uses the official repository
workflow identity and records the signature/certificate in Sigstore's public
transparency service. Do not request signing until the owner approves that exact
source, scope and manifest digest.

## Scope and trusted producers

`v09-prepublication-signing` accepts only a protected `main` dispatch by both an
original and a triggering actor listed in `.github/release/release-owners.json`;
that policy must match the `/.github/` CODEOWNERS entry. Preparation has only
contents/actions read permissions. Only the signing job receives `id-token: write`.
The workflow never receives contents/packages write permission.

| Scope | Required authenticated producer artifacts | Admission meaning |
| --- | --- | --- |
| `staging-distribution` | Both W81 OCI architectures, Helm lifecycle archive and G2 integration packages | Explicit subset; an exact ancestor of current main is permitted and recorded |
| `full-distribution` | Same distribution artifacts plus native API/UI, CLI and MCP for win-x64, linux-x64, linux-arm64, osx-x64, osx-arm64 | Every producer source must equal current protected main |

Both scopes set `releaseReady: false`. Signing authenticates selected media; W82
acceptance and release publication remain separate decisions. The manifest records
the actual producer source separately from the signing workflow/policy revision.
MCP, chart and native application version is `0.9.0`; Terraform provider retains
its independently versioned `0.8.0` package identity.

Producers are successful completed `push` or `workflow_dispatch` runs on `main`
in `araditc/Kafdeck`, with an exact source SHA, workflow name and workflow path:

- `.github/workflows/v09-w81-distribution-candidate.yml`:
  `w81-oci-{amd64,arm64}-<source>` and `w81-helm-lifecycle-<source>`.
- `.github/workflows/v08-g2-live-acceptance.yml`:
  `g4-external-integration-packages`.
- `.github/workflows/v09-native-distribution.yml`:
  `v09-native-<rid>-<source>` for all five RIDs in full scope.

The assembler verifies each GitHub artifact's run/source binding and immutable
ZIP digest before bounded extraction. It selects known filenames only. It then
checks image/config/SBOM/scan identities, both native OCI startup/restart proofs,
Helm lifecycle identity and results, MCP version, five Terraform checksums, and
the full native matrix when requested. Native evidence must bind all three
archive hashes to successful startup and authenticated operations after archive
installation. Missing, duplicate, expired, foreign or partial producers fail.

## Prepare, review, authorize

1. After these workflows are accepted on protected main, run all necessary
   producers for one exact source. For full scope, use the current main SHA.
2. Dispatch `v09-prepublication-signing` with `source_sha`, the producer `run_ids`
   and the selected `scope`. Leave `manifest_sha256` and `owner_approval` empty.
   This performs no signing. Review the retained prepared media and `manifest.json`,
   including its exact source, workflow revision, artifact provenance, scope and
   SHA256 from the workflow summary.
3. Obtain an explicit owner decision for this exact source, scope and manifest
   hash. Dispatch again with identical selection and the reviewed `manifest_sha256`.
   Set `owner_approval` to the exact text:

   ```text
   SIGN v0.9 <scope> FROM <source_sha> MANIFEST <manifest_sha256>
   ```

   Preparation must reproduce the reviewed digest. The signing guard rechecks
   current main, both owner identities, policy/workflow identity, all media bytes
   and the exact approval before invoking Cosign or requesting a signing identity.
   Any policy/main change requires fresh preparation and review.

## Offline verification

The signing job retains `manifest.json`, `manifest.sigstore.json`,
`trusted-root.json`, selected `media/`, and `offline-verification.json`. Cosign is
pinned to `v3.0.6`; the installation action and all other actions are commit pinned.

Distribute the reviewed manifest digest, expected signing workflow SHA and trusted
root digest independently through the owner-reviewed evidence record. A bundled
root file by itself is not a trust decision. Before consuming media, compare the
manifest and root hashes with that independent record. The verifier pins:

- OIDC issuer `https://token.actions.githubusercontent.com`;
- certificate identity
  `https://github.com/araditc/Kafdeck/.github/workflows/v09-prepublication-signing.yml@refs/heads/main`;
- repository, workflow name, `refs/heads/main`, `workflow_dispatch`, and the exact
  owner-reviewed workflow SHA certificate extensions.

On Linux with Cosign, Python 3, iproute2 and the verifier scripts already available:

```bash
echo '<reviewed-manifest-sha256>  /absolute/media/manifest.json' | sha256sum --check
sudo unshare --net env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin COSIGN=/absolute/path/to/cosign \
  bash scripts/release/verify-v09-offline.sh /absolute/media \
  <reviewed-workflow-sha> <reviewed-trusted-root-sha256>
```

The fresh network namespace must contain only loopback and no IPv4 or IPv6 default
route. After verifying the local Sigstore bundle, strict certificate identity,
trusted root and all selected media hashes/evidence, the verifier performs actual
installation on a Linux x64 host. Docker, nsenter and root permission to create
network namespaces must already be available; it downloads no test dependencies.

It loads the signed amd64 OCI archive, checks its exact config digest, starts it
with `--pull=never`, network `none`, read-only root and UID 1654, and probes health
and packaged HTML from inside that container's network namespace. For
`full-distribution` it also safely extracts the signed Linux x64 API/UI, CLI and
MCP archives into a fresh temporary directory, starts their actual apphosts in the
outer loopback-only namespace, checks API health/static HTML, CLI help and MCP
initialization/tool listing. Staging subsets explicitly report native installation
as absent. All owned processes/containers and temporary native installs are cleaned
up. Only after these checks pass is `offline-verification.json` written.

The offline MCP profile contains fixture identifiers only. This test performs no
authenticated backend read and stages no Keycloak or broker fixture; its report
sets `authenticatedOperation: false`. Real Keycloak HTTPS authenticated reads are
proven separately by the native producer matrix. Upgrade/restart/recovery
acceptance remains in the producer and W82 evidence. No certificate,
transparency-log or signature bypass flags are used.

The Cosign flag contracts follow the pinned upstream
[sign-blob](https://github.com/sigstore/cosign/blob/v3.0.6/doc/cosign_sign-blob.md),
[verify-blob](https://github.com/sigstore/cosign/blob/v3.0.6/doc/cosign_verify-blob.md)
and [trusted-root create](https://github.com/sigstore/cosign/blob/v3.0.6/doc/cosign_trusted-root_create.md)
documentation.
