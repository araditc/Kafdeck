## Operator acceptance

The operator installed the Windows x64 API/UI archive from the signed distribution into an empty directory. Its SHA256 was `39c8654a000f82a549715bb64b03fef6b24d4e7c3743677ebf429d8d4956e168`. The installer compared all 408 extracted files with the selected native inventory before starting the packaged executable. This used an isolated single-broker Kafka 4.3.1 installation, Keycloak 26.8.1, SQLite and Chrome.

1. Issue the initial setup code, create the first administrator in the packaged UI and sign in through Keycloak. The managed user list included the new owner.
2. Test and save a PLAINTEXT connection from the dashboard. Open Topics and select the two-partition fixture topic.
3. Configure metadata sampling for the saved cluster ID and restart Kafdeck with the same state and keys. Sign in from a fresh browser context, open the saved cluster and topic, then open Monitoring.

The same cluster ID and topic were visible after restart. At 13:48:07 UTC the chart showed 64.98 ms for metadata, zero offline partitions and zero under-replicated partitions. This installation exercised the metadata sampler. Broker JVM charts require an enrolled agent.
