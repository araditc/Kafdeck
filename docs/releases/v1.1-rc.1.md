## Fleet acceptance

Host registration, broker logs, offline agent installation and upgrade, dynamic settings and recovery were delivered through [#485–#489](../rfcs/0011-v1.1-broker-host-management.md). The evidence covers Linux/systemd without Docker and an isolated Docker Compose pilot on the Arad Office host. The Compose pilot exercised deliberate failures separately from operational brokers. [Linux acceptance](https://github.com/araditc/Kafdeck/actions/runs/44743543323) · [Pilot acceptance](https://github.com/araditc/Kafdeck/issues/489) · [Fleet operator guide](../operator/v1.1-fleet-operational-recovery.md).

Native installation and authenticated API, CLI and MCP operations passed on five platforms. A separate isolated win-x64 trial used both published `1.0.0` and `1.1.0-rc.1` archives. It retained managed users, roles, Kafka connections and protected credentials, and verified backup restoration for SQLite and PostgreSQL. [Native installation run](https://github.com/araditc/Kafdeck/actions/runs/44754921212).

Stable `1.1.0` requires its own exact-source package, signature decision and publication decision. RFC evidence retains the source and deployment scope above.
