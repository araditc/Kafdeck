# v0.4 Benchmark Methodology — Read Views

## Purpose

Record repeatable bounded in-process evidence for new v0.4 projection paths.

These measurements are not Kafka end-to-end throughput, external-provider latency, or a public SLA.

## Scenarios

The v0.4 benchmark suite measures:

1. consumer lag aggregation over a bounded partition set,
2. local schema diff over bounded schema documents,
3. fail-closed Connect configuration projection over a bounded configuration set.

## Method

- .NET 10 Release configuration,
- deterministic in-memory fixtures,
- warm-up iterations before measurement,
- fixed measurement iteration count,
- no network or Kafka dependency in microbenchmark measurements,
- exact CI revision recorded by workflow logs.

## Interpretation

The benchmark exists to detect gross processing regressions and retain release evidence.

External Kafka/Schema Registry/Connect/ksqlDB latency is validated separately through bounded integration and compatibility tests; it is not inferred from these microbenchmarks.
