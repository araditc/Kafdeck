# v0.7 Provider Capability Matrix

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**. Authority #178/#180; W51 #181.

This document defines the provider evidence required before Kafdeck advertises a v0.7 ecosystem capability as available. Capability state is never inferred from a marketing label or URL shape.

## Capability states

- **Supported** — typed adapter path exists, contract tests pass, and required runtime/security semantics are enforceable.
- **Unsupported** — the provider/version cannot perform the admitted capability through an accepted typed path.
- **Blocked** — a lower-level primitive may exist, but Kafdeck cannot safely activate it under the admitted security/runtime contract.
- **Unconfigured** — no profile is configured.
- **Unavailable** — configured and normally supported, but current bounded observation failed.
- **Unknown** — evidence is insufficient to make a stronger claim.

## Schema Registry

### Reference adapter

Confluent Schema Registry HTTP semantics are the reference baseline. The adapter owns exact URI construction, status mapping, response-size limits and provider error sanitization.

Admitted capability families:

| Capability | Reference evidence required |
| --- | --- |
| Subject listing | bounded list/read fixture |
| Version listing/read | typed version parsing and schema-type evidence |
| Reference graph | explicit provider references with bounded recursion |
| Compatibility check | non-mutating provider compatibility endpoint |
| Schema register | typed register response with readback/fingerprint verification |
| Compatibility alter | exact global/subject scope and readback |
| Soft delete version/subject | tested provider semantics and post-effect readback |
| Permanent delete | separately tested destructive provider semantics |
| Avro | schema-type fixture |
| Protobuf | references/import fixture |
| JSON Schema | references/format fixture |

### Karapace

Karapace is not treated as fully equivalent merely because it implements a Confluent-compatible API. W52 must run provider-specific contract fixtures for every advertised capability. Unsupported differences remain explicit.

### Apicurio

Apicurio uses a separate typed adapter/profile because identity, versioning and compatibility semantics differ materially. No URI translation layer may pretend Confluent subject/version semantics exist when they do not. W52 may expose a narrower capability profile until real tests justify more.

### Safety rules

- no arbitrary URL/path forwarding;
- configured origins only;
- HTTPS required for remote basic/bearer authentication;
- credentials are server-side secret references;
- response bytes/entry counts bounded before/while decode;
- provider error bodies are untrusted and safely summarized.

## Kafka Connect

### Profile model

v0.7 introduces stable `ConnectProfiles[]` under a Kafka cluster profile.

Each profile contains at minimum:

- stable `Id`;
- validated provider `Url`;
- optional server-side authentication references;
- TLS validation policy;
- optional provider capability overrides only where evidence-backed.

Legacy singular `Connect` is normalized to profile ID `default`. Configuring both legacy `Connect` and `ConnectProfiles[]` is invalid.

### Typed capability families

| Capability | Evidence required |
| --- | --- |
| List/read connectors | bounded provider read |
| Connector status/tasks | typed status/task schema |
| Plugin listing | bounded plugin list |
| Config validation | typed provider validation result |
| Create | tested create + readback |
| Update config | tested replace/update + readback |
| Delete | tested delete + absence/readback semantics |
| Pause | tested terminal/non-starting semantics |
| Resume | tested start/resume semantics + common governance |
| Restart connector | tested dispatch + status/readback |
| Restart task | tested exact task dispatch + readback |
| Task stack trace | provider exposes bounded safe diagnostic |
| Metrics | explicit tested endpoint/provider; otherwise Unsupported |
| Auto-restart | requires W55 durable finite policy plus underlying typed restart |

### Connector configuration

Provider adapters may accept only exact configured provider origins and typed connector lifecycle paths. No user input can become an arbitrary URL path, query parameter set or HTTP method.

Connector class is subject to server deployment policy. A deployment can:

- allow specific class names;
- allow specific plugin families with form schemas;
- block transforms/converters/predicates outside policy.

Unknown plugin configuration is not assumed safe. Secret-like keys are treated as sensitive by default. Where a plugin needs secret bytes, Kafdeck resolves secret references server-side immediately before dispatch and never returns the material.

### MM2/replication guard inheritance

Any connector class/profile recognized as MirrorMaker/replication remains subject to the v0.6 shared replication guard. Generic v0.7 Connect create/update/resume/restart/task-restart cannot become an alternate activation path for a capability that v0.6 marked Blocked.

## SerDe providers

CBOR, XML and MessagePack are Kafdeck-internal adapters, not provider HTTP services.

Required evidence:

- deterministic format capability;
- bounded input bytes;
- bounded nesting/depth;
- bounded collections;
- bounded output expansion;
- cancellation where parser API permits;
- malformed-input corpus;
- no external entity/network/file resolution for XML;
- no arbitrary type activation/object materialization.

A decoder that cannot enforce limits is Unsupported.

## ksqlDB

The configured ksqlDB profile is an exact validated origin.

v0.7 capability families:

| Capability | State rule |
| --- | --- |
| Existing metadata/read views | retain v0.4 evidence |
| Read-oriented bounded query | Supported only after statement policy + row/byte/time limits are tested |
| Query cancellation | Supported only if provider/API evidence is reliable |
| Persistent query create | Blocked in v0.7 |
| CREATE/DROP/ALTER/INSERT mutation | Blocked in v0.7 |
| Generic SQL forwarding | Unsupported by design |

The adapter never accepts an arbitrary provider path.

## Kafka Streams / application telemetry

Kafdeck does not query arbitrary application endpoints. Topology/state-store evidence comes only from explicitly configured/registered telemetry providers or already admitted metrics sources.

Capability states:

- topology from explicit application telemetry — Supported when schema/version tested;
- RocksDB/state-store metrics — Supported only when exposed by telemetry;
- inferred topology from naming convention alone — never Supported as observed evidence.

## Lineage

Lineage providers emit typed edges with:

- source entity;
- destination entity;
- provenance source;
- observed timestamp;
- confidence;
- evidence kind `Observed` or `Inferred`.

Inferred edges cannot satisfy authorization preconditions or mutation verification.

## Data-job provider capabilities

Replay/reprocess/forwarding and generator execution use the already governed Kafka record read/export/produce adapter family.

Required capabilities include:

- exact partition range read without joining/committing a consumer group;
- exact destination partition produce where plan requires it;
- bounded batch bytes/records;
- cancellation;
- provider acknowledgement evidence;
- physical cluster identity;
- topic identity/fingerprint evidence;
- current masking/data-policy eligibility.

If an admitted hard cap cannot be enforced with the provider path, the job capability is Blocked/Unsupported.

## Compatibility evidence matrix required before W60

W60 must publish an evidence table covering, at minimum:

- Confluent Schema Registry tested version(s);
- Karapace tested version(s) for each advertised capability;
- Apicurio tested version(s) for each advertised capability;
- Kafka Connect tested distribution/version(s);
- ksqlDB tested version(s) for bounded queries;
- Kafka broker versions retained from the active Kafka compatibility matrix for record jobs;
- CBOR/XML/MessagePack library/version and safety settings.

A blank cell means not tested and cannot be rendered as Supported.
