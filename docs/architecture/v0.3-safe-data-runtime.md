# v0.3 Runtime Architecture — Safe Data Explorer

- **Status:** PROPOSED
- **RFC:** RFC-0003

## Objective

Add bounded payload inspection without turning Kafdeck into a persistent consumer, stream processor, payload database, or Kafka mutation surface.

## Dependency flow

```text
Browser
 -> HTTP/API
 -> v0.2 Identity/RBAC
 -> Record Query Application Service
 -> Budget / Filter / Masking Policy
 -> Record Read Port -> Kafka Record Adapter
 -> Decode Port -> Schema Registry Adapter (optional)
 -> Safe Projection
 -> UI / Export / Audit metadata
```

Inner contracts remain provider-neutral.

## New logical components

### Record Query

Owns:

- record query/range contracts,
- direction/navigation contracts,
- budget contracts,
- record-read result/partial metadata,
- cancellation orchestration.

### Record Read Port

Owns Kafdeck record-read abstractions. Kafka client DTOs do not escape the adapter.

The Kafka adapter uses explicit partition assignment, never subscription-driven group processing, and never commits offsets.

### Decode

Owns normalized decoded value contracts and safe decode outcomes.

### Schema Registry Adapter

Read-only provider interface for schema lookup required for decode. Full registry management remains outside v0.3.

### Filter Engine

Compiles bounded immutable filter plans for key/header/range/regex/CEL/jq-style predicates.

### Masking Engine

Compiles configuration into immutable masking policy snapshots and transforms decoded records into safe projections.

### Export

Streams already-masked projections into JSON/NDJSON/CSV under export budgets.

## Record contracts

Conceptual input:

```text
RecordReadRequest
  ClusterId
  Topic
  Partition
  Anchor (Offset | Timestamp | Earliest | Latest)
  Direction
  Budget
  Filter
```

Conceptual output:

```text
RecordPage
  Records[]
  LowWatermark
  HighWatermark
  FirstReturnedOffset
  LastReturnedOffset
  NextAnchor
  PreviousAnchor
  Observation
  BudgetOutcome
  Decode/MaskingLimitations[]
```

## Navigation

Forward pages fetch from an explicit anchor.

Previous-page navigation computes a bounded earlier start offset from the anchor and fetches forward. The UI/API does not imply Kafka supports reverse fetch.

Timestamp navigation resolves timestamps per partition to explicit offsets before record fetch.

## Concurrency and load safety

Record reads have separate bulkheads from metadata/admin reads so a data-browse storm cannot starve Cluster Explorer.

Required controls:

- per-cluster record-read semaphore,
- global record-read semaphore,
- per-identity live-tail admission bound,
- operation deadline,
- raw/decoded byte accounting,
- rate limiter for live tail/export,
- cancellation propagation,
- no automatic retry after partial record delivery,
- transient retry only where safe before observable delivery.

Exact defaults are implementation configuration with validation and hard caps.

## Live tail transport

SSE is the preferred v0.3 transport because flow is server-to-client only.

A tail request has explicit cluster/topic/partition/filter/budget identity and is cancelled on disconnect.

## Decode architecture

Decode order:

1. detect configured/plain representation,
2. optionally parse Confluent wire framing/schema identity,
3. retrieve schema through bounded adapter/cache,
4. decode into Kafdeck normalized tree,
5. enforce structural limits,
6. return typed outcome.

Schema cache keys are registry/profile + schema identity and have bounded size/TTL.

## Masking placement

Masking occurs after decode/filter evaluation and before any browser/API/export projection.

No controller or exporter accepts raw Kafka bytes directly.

For mandatory structured masking with unsafe decode, projection is fully redacted.

## API posture

v0.3 remains read-only and may use GET/SSE product endpoints only. Query parameters/encoded filter contracts remain bounded to preserve the existing no-mutation HTTP posture.

No endpoint performs Kafka write operations.

## Persistence

Record payloads are not persisted by default.

Schema metadata may be cached in memory within bounds. Durable payload indexing/search requires a future RFC.

## Observability

Trace spans may record operation type, cluster-profile stable identifier, partition count, record/byte counts, budget outcome and safe error category.

No record content, key/header value, schema field value, operator subject/email, or arbitrary topic-derived value is used as an unbounded metric label.

## Failure isolation

A slow/unauthorized/malformed topic or registry must not starve unrelated clusters.

Schema Registry failure degrades decoding only; it does not corrupt authorization or silently expose undecoded clear payload when masking requires decode.

## Architecture exit gate

- dependency-direction tests green,
- no Kafka client type leakage,
- no producer/commit path,
- bounded bulkhead/budget/cancellation tests green,
- masking projection is the only response/export payload path,
- schema adapter failure isolation proven.
