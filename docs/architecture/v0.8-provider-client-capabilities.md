# v0.8 Provider and Client Capability Matrix

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

Authority: Gate 8 #208; tracker #209; W61 #210.

This matrix defines the evidence required before Kafdeck advertises a v0.8 observability/automation/provider/client capability as Supported. Marketing/API resemblance is not compatibility evidence.

## Capability states

- **Supported** — typed implementation exists and required contract/security/runtime tests pass.
- **Unsupported** — provider/client cannot satisfy the admitted contract.
- **Blocked** — a primitive may exist but cannot be safely activated under the admitted contract.
- **Unconfigured** — no provider/profile is configured.
- **Unavailable** — configured normally-supported capability is currently unreachable/failing.
- **Unknown** — evidence is insufficient.

## OpenTelemetry

| Capability | Evidence required |
| --- | --- |
| Metrics SDK/instrumentation | bounded label schema + cardinality tests |
| Traces | attribute classification/caps + secret/payload sentinel tests |
| Logs/events | structured safe fields + diagnostic-size limits |
| OTLP export | exact configured collector origin, timeout/failure tests, no caller-controlled endpoint |
| Disabled/local-only mode | no mandatory external collector/SaaS |

Kafdeck does not claim compatibility with every collector merely because it speaks OTLP. W62/W71 release evidence records exact tested SDK/exporter/collector identities.

## Prometheus

| Capability | Evidence required |
| --- | --- |
| scrape endpoint | stable metric names/types/help + low-cardinality labels |
| private/local scrape | no public dependency |
| resource-scoped metrics | explicit configuration + hard series accounting |
| remote-write | **not admitted by default**; requires a reviewed typed exporter if later needed |

The Prometheus scrape surface is not a generic metrics query/proxy endpoint.

## Historical metrics providers

A provider is Supported only after:

- retention expiry;
- deterministic rollup/downsampling;
- series/point/query-range limits;
- cancellation/deadline;
- migration;
- stale/partial truth;
- authorization filtering;
- standalone/HA behavior where advertised.

Candidate reuse of SQLite/PostgreSQL is an implementation option, not an assumed capability. W63 must publish exact provider evidence before Supported status.

## Data-quality evaluator

Supported rule families must be closed and typed.

Initial candidate families may include:

- required/non-null field;
- scalar type/shape;
- numeric/string range/length;
- schema validity/compatibility observation;
- key/header presence where authorized;
- bounded event-rate/completeness aggregate.

Arbitrary scripts, regex engines without reviewed bounds, external network callbacks, dynamic code or provider-specific executable expressions are Unsupported/Blocked until separately admitted.

## Notifier providers

Provider-specific Supported status requires exact contract fixtures:

| Provider | Minimum evidence |
| --- | --- |
| Generic configured Webhook | HTTPS/origin/path allowlist, no redirects, timeout/retry/dedup, safe payload |
| Email | exact SMTP/API mode, TLS/auth, retry classification, safe subject/body bounds |
| Slack | exact webhook/app API profile, secret handling, rate/error mapping |
| Microsoft Teams | exact workflow/connector API profile, error/rate mapping |
| Telegram | Bot API profile, chat/destination identity, rate/error mapping |
| PagerDuty | Events API profile, dedup/routing-key handling, outcome mapping |

Missing provider features remain explicit Unsupported; Kafdeck does not fall back to generic arbitrary HTTP.

## CLI

A CLI build is Supported on an OS/runtime only when release tests cover:

- authentication/profile handling;
- read/plan/status operations;
- mutation AwaitingApproval flow;
- bounded pagination/output;
- exit-code/problem mapping;
- secret-safe config/output.

CLI support is a client-compatibility claim, separate from Kafka broker compatibility.

## GitOps/configuration-as-code

A resource family is declaratively Supported only if it has:

- canonical resource identity;
- stable normalized desired-state schema;
- deterministic current-state readback;
- ownership/adoption/import semantics;
- secret/write-only representation;
- deterministic plan;
- governed apply/delete;
- drift state.

Otherwise the family is ObservedOnly/Unsupported for declarative ownership.

## Terraform

Terraform resources are admitted one by one after W68 declares their underlying declarative contract stable.

There is no generic passthrough resource.

Release evidence must record:

- Terraform protocol/SDK/provider version;
- exact Kafdeck API contract version;
- tested import/read/plan/apply/destroy;
- asynchronous approval handling;
- state migration/upgrade behavior.

## MCP

An MCP tool is Supported only when:

- it maps to one typed Kafdeck API operation/action;
- its input/output schema is bounded;
- backend authorization/risk/approval parity is proven;
- protected payload/secret exposure matches existing permissions;
- prompt/tool-result injection tests pass.

Transport modes must be explicit. Any remote MCP transport requires authenticated Kafdeck authority; no anonymous remote management endpoint is admitted. A local/stdio client still authenticates to Kafdeck APIs and receives no direct provider access.

## Compensation

Compensation capability is per operation family, not global.

Each Supported inverse requires:

- typed inverse;
- current-state evidence;
- drift rule;
- ambiguity rule;
- risk/approval classification;
- verification fixture.

Unknown/irreversible families are NotCompensatable, not best-effort rollback.

W71 must publish exact tested identities for each advertised Supported provider/client surface. A blank/untested provider/version must not be rendered Supported.
