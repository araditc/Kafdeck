# v0.8 Historical Metrics Persistence, Retention and Query Contract

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

## Principle

Historical metrics are optional Kafdeck application state. They are not written to managed Kafka clusters merely to give Kafdeck history.

## Provider contract

The provider must support:

- append/upsert of normalized time-series samples/rollups;
- exact metric/resource identity;
- retention expiry;
- bounded time-range query;
- server-side series/point ceilings;
- cancellation/deadline;
- schema/version migration;
- standalone/HA semantics;
- health/capability reporting.

## Retention

Planning defaults/hard caps:

- raw/high-resolution: 24 h default, 7 d hard;
- rollup history: 7 d default, 90 d hard;
- interactive query range: 24 h default, 31 d hard.

A deployment may choose lower values.

## Rollup

Rollups use deterministic windows and retain:

- min/max/avg/sum/count as applicable;
- first/last observation time;
- partial/missing evidence markers.

Rollup must not turn missing data into numeric zero.

## Query budgets

- 1,000 series default / 10,000 hard;
- 50,000 points default / 250,000 hard;
- 10 s default / 30 s hard duration;
- 2 default / 8 hard concurrent history queries.

## Truth model

Every response includes:

- requested/effective range;
- source/provider;
- resolution;
- observed coverage;
- freshness;
- partial/stale flags;
- truncation/limit reason.

## Persistence providers

W63 may reuse existing SQLite/PostgreSQL infrastructure only if performance/migration/isolation evidence supports the admitted metrics workload.

A new provider requires ADR/security/supply-chain review.

## HA

HA writers must not create duplicate logical samples outside the provider's documented identity/idempotency model.

Retention/downsampling jobs use leases/fencing.

## Security

Historical state cannot contain:

- raw record/generated payloads;
- connector/provider secret values;
- raw ksql result rows;
- arbitrary user request bodies.

Resource names stored as dimensions remain subject to authorization on query/output.
