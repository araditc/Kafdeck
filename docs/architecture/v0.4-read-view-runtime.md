# v0.4 Runtime Architecture — Consumers, Schemas & Ecosystem Read Views

- **Status:** PROPOSED
- **RFC:** RFC-0004

## Dependency flow

```text
Browser
 -> HTTP/API
 -> Identity/RBAC
 -> Consumer / Schema / Ecosystem Application Services
 -> Kafdeck-owned read ports
      -> Kafka Admin read adapter
      -> Schema Registry read adapter
      -> Kafka Connect read adapter
      -> ksqlDB metadata adapter
      -> optional metrics/history provider
 -> bounded Kafdeck projections
 -> UI / audit metadata
```

Provider DTOs and raw HTTP payloads do not cross inward.

## Components

### ConsumerObservationPort

Read-only operations:
- list groups,
- describe group,
- list committed offsets,
- obtain topic-partition end offsets,
- bounded current assignment/state observations.

It exposes no consumer-group mutation.

### ConsumerDiagnosticsService

Combines bounded observations into:
- per-partition lag,
- aggregate lag,
- missing/stale/partial flags,
- evidence-based diagnostic states.

It does not fabricate historical trends.

### MetricsObservationPort

Optional provider abstraction. Default implementation returns unavailable.

A later observability version may add Prometheus/OpenTelemetry-backed providers without changing consumer contracts.

### HistoryObservationPort

Optional provider abstraction for rebalance/progress history. v0.4 has no mandatory durable implementation.

### SchemaCatalogPort

Extends the existing read-only registry boundary with:
- list subjects,
- list versions,
- get schema/version metadata,
- get references,
- inspect compatibility configuration/results where available read-only.

### SchemaDiffService

Pure bounded application service; deterministic diff over already-authorized schema documents. It never calls mutation APIs.

### ConnectReadPort

One optional configured Connect profile per Kafka cluster for v0.4.

Only fixed read operations are exposed.

### KsqlMetadataReadPort

One optional configured ksqlDB profile per Kafka cluster.

No arbitrary query text is accepted by the port.

### TopicCatalogProvider

Configuration-backed immutable snapshot. Optional descriptive topic metadata only.

## Configuration extensions

`ClusterProfile` gains optional:
- `SchemaRegistry` (existing, expanded read capabilities),
- `Connect`,
- `KsqlDb`.

Kafdeck options gain optional topic catalog entries keyed by cluster/topic.

HTTP ecosystem profiles use secret references consistent with existing configuration security.

## Isolation

Separate semaphores/bulkheads:
- Kafka metadata,
- record reads,
- consumer diagnostics,
- Schema Registry,
- Connect,
- ksqlDB.

One slow upstream cannot consume all application concurrency.

## Caching

Allowed bounded caches:
- schema subject/version metadata,
- Connect identity/status for very short TTL,
- ksqlDB identity/metadata for very short TTL,
- consumer observation snapshots for a short bounded TTL/single-flight.

Caches contain observations, not authorization decisions. Every API response is re-authorized.

## HTTP client safety

Adapters use named/fixed HttpClient instances with:
- configured origin,
- no arbitrary absolute per-request URL,
- bounded timeout,
- response-content size checks,
- safe authentication handler,
- no credential forwarding across origin change.

## API shape

Representative routes:

```text
GET /api/v1/clusters/{clusterId}/consumer-groups
GET /api/v1/clusters/{clusterId}/consumer-groups/{groupId}
GET /api/v1/clusters/{clusterId}/consumer-groups/{groupId}/offsets

GET /api/v1/clusters/{clusterId}/schemas/subjects
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions
GET /api/v1/clusters/{clusterId}/schemas/subjects/{subject}/versions/{version}
GET /api/v1/clusters/{clusterId}/schemas/diff?...
GET /api/v1/clusters/{clusterId}/schemas/compatibility?...

GET /api/v1/clusters/{clusterId}/connect
GET /api/v1/clusters/{clusterId}/connect/connectors
GET /api/v1/clusters/{clusterId}/connect/connectors/{name}

GET /api/v1/clusters/{clusterId}/ksql
GET /api/v1/clusters/{clusterId}/catalog/topics/{topic}
```

All collection routes are bounded/paginated even when an upstream API is not.
