Status: admitted W72 contract (PR #437 / #426). [ADR-0010](../adr/0010-governance-effect-boundary.md) and [API](../api/v0.9-governance-contract.md) govern the shared effect boundary. ## Records and invariants

Every record has server-generated ID, resource scope, immutable created actor/time, updated time and monotonically increasing revision. Identity keys use exact normalized server resource IDs; display labels never identify an authorization scope. Unique keys and reference validation are provider-enforced. UTC instants and invariant decimals are persisted; localized display is separate.

| Record / store family | Required material and concurrency |
|---|---|
| CatalogTeam, CatalogApplication | Exact scoped ID, bounded name/description, team/application links; archive rather than cascade-delete historical references. Existing TopicCatalogEntry.Owner remains descriptive legacy text; no implicit principal or team migration. |
| TopicOwnershipRevision | Cluster/topic stable key, optional team/application IDs, domain/classification/docs/tags, effective interval, provenance/import ID, expected revision. No overlapping active assignment intervals; correction appends history. Topic recreation cannot silently inherit an old identity. |

## Request state model

Business state: Draft → Submitted → Approved or Rejected; Submitted/Approved may become Cancelled or Expired before dispatch. Material/policy/operation mismatch yields NeedsReplan and invalidates previous decisions. New revision is explicit and cannot mutate old decisions. Approval is never an instruction to bypass confirmation/critical approval.

The initial business workflow requires one current scoped human RequestDecide approval from a principal distinct from the requester; automation cannot supply that decision. Any eligible rejection closes that revision. CAS prevents concurrent decision/dispatch from observing a half-transition. More complex quorum/delegation is not implicit in this foundation. The underlying critical operation still requires its own exact-operation distinct eligible human approval.

Execution is separately projected from the existing operation states (Previewed, AwaitingConfirmation, AwaitingApproval, Ready, Executing, AppliedVerified, AppliedUnverified, PartiallyApplied, ExecutionUnknown, Rejected, Expired, Cancelled, StalePreview, FailedBeforeDispatch, FailedDefinitive). Do not allocate replacement kernel state values. A request cannot be cancelled/rejected to clear an executing/unknown effect; it may stop undispatched future steps only under existing kernel rules.

## Policy format and evaluation

Closed JSON schema version 1 permits rule ID, priority, exact typed scope selectors (cluster/resource kind/resource IDs/action), conditions over registered metadata/classification/risk/request-decision facts, and outcomes Deny or RequireApprovedRequest. Defaults cannot Allow rights absent from RBAC. No scripts, regex, expression language, URL resolution or dynamic plugins. Rules sorted by priority then ID; Deny wins; all matching requirements must hold. Missing required facts/active store availability fail closed. Explain redacts inaccessible rule/resource material and returns stable codes/version/digest.

Validation rejects unknown/duplicate keys, invalid UTF-8, duplicate rule IDs, unsupported condition/operator/action, unsafe references and oversize/deep input. Maximum 256 KiB policy, 100 rules, depth 12, 20 IDs per selector and 10 conditions/rule. Dry-run evaluates up to 100 authorized fixed fixtures per call; it creates no approval/effect. Canonical JSON/hash excludes presentation whitespace and includes schema version, exact selectors and ordered semantics.

## Transaction, migration and restore

SQLite remains standalone; PostgreSQL supports admitted HA. Infrastructure owns transactional repositories; no cross-module SQL or nested second-connection read for the gate. CAS checks revision, active policy and restore generation on the owning transaction; lost races dispatch no effect. Schema migrations are additive, numbered and deterministic for both providers with indexes/FKs and migration-ledger digest. SQLite foreign keys are enabled. No catalog legacy owner string is converted into authority. A v0.8 snapshot remains restorable with its original binary; restoring a v0.9 store to a v0.8 binary is unsupported unless separately proven.

Backups include policy/request/catalog/measurement stores plus generation and migration identity, excluding credential values. Restore fences old workers before opening dispatch, verifies database integrity, refreshes current authority and reconciles dispatched unknown operations using positive evidence. Migration interruption, concurrent upgrade and stale worker scenarios must be tested, not inferred from schema creation.

## Attribution provenance and arithmetic

Only registered measured series with explicit units/time coverage may be ingested through an infrastructure metrics port. No generic query proxy or arbitrary PromQL/HTTP input. Configured sources reuse TLS, egress, DNS/SSRF and secret-reference controls. Existing Unsupported throughput signals stay Unsupported until real acquisition is admitted. Consumer lag, record count/length and occasional samples do not prove broker billable bytes.

Direct single-owner measured units are Observed. Shared-resource allocation uses explicit versioned weights and is Estimated; no invented equal split. Allocated units plus explicit residual equal admitted measured units at decimal precision. Missing windows, counter reset, stale sources, incomplete coverage and owner ambiguity retain quality reasons. Attribute ownership by the measurement interval; split only when interval evidence supports it, otherwise report ambiguity. Estimate sums unit quantities × matching rate per window, rounds once per displayed currency total using midpoint-to-even and retains unrounded decimal evidence; reject overflow, negative rates and mixed-currency totals. Never treat unknown as zero.
