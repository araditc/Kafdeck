# W67 Keycloak Reference Identity Profile — v0.8 Candidate

**Status:** REFERENCE PROVIDER SELECTED / IMPLEMENTATION AND ACTIVATION STILL GATED  
**Date:** 2026-10-15  
**Authority:** scope #208; execution tracker #209; W67 #216; dependency RFC [v0.8 non-browser OIDC and automation authority](v0.8-non-browser-oidc-automation-authority.md).  
**Owner direction:** Keycloak is the reference self-hostable IdP for design and acceptance testing. This direction does **not** approve a specific issuer, API audience, principal registry/grant model or runtime enablement.

This is a **reviewable, non-executable contract**. No host authentication middleware, service principal, CLI write operation, unattended approval, publication tag, or v0.8 release is enabled by merging this document. The existing browser OIDC cookie/PKCE path and deployment-token GET-only CLI behavior stay unchanged.

## 1. Proposed reference topology (all literal identifiers below are candidates)

| Component | Candidate | Admission / validation rule |
| --- | --- | --- |
| Keycloak realm | Dedicated realm, e.g. \`kafdeck\` | Real environment's canonical HTTPS issuer **must** be recorded and match discovery and access-token \`iss\` exactly; neither a guessed hostname nor the example value is authoritative |
| API resource | \`kafdeck-api\` | Exact access-token \`aud\` to be explicitly produced by an audience protocol mapper and validated by Kafdeck; do not use the browser client ID or assume \`azp\` alone supplies audience |
| CLI public client | \`kafdeck-cli\` | Authorization Code + PKCE (S256); strictly bound ephemeral localhost loopback redirect, CSRF state, nonce, code replay/expiration; no client secret |
| Automation clients | Distinct confidential client per registered automation identity | Service Accounts enabled; OAuth client-credentials with asymmetric **signed JWT client authentication** (\`private_key_jwt\`) after proof with the pinned Keycloak version; no password/direct access grant, implicit grant or shared deployment token |
| Identity registry | Kafdeck-controlled immutable registration | Bound to \`(issuer, subject, authorized client_id/azp, principal kind)\` and scoped allowlisted actions/resources/tenant/cluster; unknown/disabled/expired clients denied |
| Human approver | Distinct authenticated human principal | CRITICAL approvals never auto-satisfied by the initiating service principal or a second service client; plan/approval current-state and policy evidence mandatory |
| Public Key / TLS trust | Pin deployment-approved issuer, metadata and signing-key origin over HTTPS | Validate signed access tokens with approved asymmetric algorithm, JWKS/key rollover and fail-closed stale-key policy. No discovery from untrusted token header, \`jku\` or \`x5u\` |
| Activation | \`NonBrowserOidc.Enabled=false\` initially (illustrative setting, **not** a currently accepted runtime key) | Separate reviewed configuration/schema/API admission and default-off negative tests before enabling for *any* route |

The configured issuer will resemble \`https://<approved-idp-host>/realms/<approved-realm>\` but the live value must be obtained from that realm's discovery metadata and formally approved. Placeholder hostnames must never be copied into production.

**Important audience distinction:** the Kafdeck **API access-token audience** is \`kafdeck-api\` (candidate); an asymmetric JWT **client assertion** authenticating the OAuth confidential client targets the Keycloak authorization server/token endpoint according to the selected Keycloak version/profile. These are separate JWTs with separate audiences; never conflate them or accept one as the other.

## 2. Authentication and authorization boundary

1. Preserve current cookie-based browser OIDC and antiforgery; a bearer cannot be converted into a browser session, and cookie credentials cannot authenticate an automation service.
2. Allow bearer on an explicitly versioned API route **only** after per-route admission. Reject conflicting browser/deployment/bearer credentials rather than silently selecting a stronger scheme.
3. Check Keycloak's exact HTTPS issuer, discovery and JWKS origins; signature and allowed algorithm; token type/purpose; \`aud\`, \`iss\`, \`sub\`, \`iat\`, \`nbf\`, \`exp\`, and bound client/actor identity. Validate **original** token lifetime \`exp - iat\`, not just remaining TTL. Reject unrecognized/multiple cross-tenant audiences.
4. Never treat Keycloak realm roles, client roles, \`scope\`, \`groups\`, \`azp\` or \`preferred_username\` as a sufficient Kafdeck permission. Effective permission is **Kafdeck's registered principal AND exact backend action/resource authorization AND provider capability AND current risk/approval state**.
5. Introduce no OAuth password grant, no unattended refresh token, no browser-cookie forwarding, no bearer token in URL/argv/stdout/telemetry/manifest/Terraform state, and no fallback from client assertion to plaintext shared-secret authentication.
6. Service-principal registration stores a stable principal ID, owner, exact issuer/subject/client identity, permitted action/resource scope, disable/revocation state, policy revision, credential-rotation authority and audit reference. It does **not** store a private key or access token.
7. Mutating/approval/status operations remain **blocked** until a separately admitted principal and typed API are tested. Plans never confer rights; execution checks fresh auth, immutable preview/current state, policy revision and CRITICAL independent approval. Durable \`ExecutionUnknown\` is not retry authorization.
8. Default deny when IdP metadata/JWKS cannot be refreshed safely. Document offline cache bounds, key rollover and realistic revocation delay; never promise instant cancellation of a previously issued signed access token absent proven revocation enforcement.

## 4. Phased admission: smallest safe implementation first

- **W67-A (contract only):** select reference IdP and record proposed issuer/audience/principal boundaries. This document satisfies only planning.
- **W67-B (disabled middleware):** add explicitly opt-in, fail-closed per-route Keycloak bearer validator and principal normalization with offline negative tests, without changing legacy CLI authority. Requires owner-admitted issuer/audience/algorithms/key lifecycle; no mutation routes.
- **W67-C (read parity):** CLI public PKCE and registered machine principal GET-only paths tested against real Keycloak issuance; Kafdeck permission/secret/pagination parity. No UI cookie forwarding.
- **W67-D (governed mutations):** typed plan/status/approval/mutation APIs; exact initiator binding, risk, current-state, idempotency and durable unknown effects; CRITICAL human approval. Requires independent admission and full operational tests.
- **W68–W70:** only after relevant W67 contracts are admitted, enable per-family read/drift/plan and later controlled apply, Terraform and MCP. Never bootstrap rights by running from trusted CI/Git files/model prompts.

## 5. Required real-Keycloak acceptance tests

| Surface | Positive evidence | Negative and recovery evidence |
| --- | --- | --- |
| Discovery/JWKS | Exact approved HTTPS issuer, public key verification and tested rotation | Wrong issuer/origin, unsigned/weak alg, \`kid\` confusion, malformed/stale JWKS, IdP outage, bounded cache and air-gap restore |
| Access token | Signed API-audienced **access** token from registered client, scoped Kafdeck principal | Wrong/missing audience; ID token/client assertion passed as API token; issuer confusion; \`nbf\` future, missing/future \`iat\`, expired/overlong \`exp-iat\`, disabled client |
| Interactive CLI | S256 PKCE loopback, correct state/nonce/code and no credential output | Callback origin/path/port substitution, replay, intercepted code, wrong token kind and leaked token sentinel |
| Automation | Real client-credentials token obtained using tested asymmetric assertion; exact issuer+client registration | Shared deployment token promotion, client secret fallback, wrong/rotated key, scope escalation, unknown service owner, expired/disabled registration |
| API parity | Same named resource/action read and masking as browser with bounded pagination | Cross-tenant/cluster leakage, pagination scope change, credential collision, cookie CSRF bypass and bearer impersonation |
| Governed effect | Immutable server-stored plan, exact original initiator, authorized execute and independent human approver | Approval self-bypass, stale policy/current-state, revoked client between plan/effect, HA/restart/replay, \`AwaitingApproval\`, \`ExecutionUnknown\`, divergent audit actor |
| Deployment | Pinned Keycloak + Kafdeck versions, runbooks and restore/upgrade evidence | TLS/cert rotation, IdP failover, clock skew, non-default realm/config, disconnected operation and secret sentinels |
