# v0.8 Observability, Cardinality and Data-Classification Contract

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

## Signal model

Kafdeck v0.8 uses three OpenTelemetry signal families:

- metrics — bounded numeric/state observations;
- traces — bounded operation/provider spans;
- logs/events — structured safe diagnostic events.

Prometheus compatibility is provided from the same low-cardinality metrics model.

## Telemetry data classes

### Allowed by default

- Kafdeck version/build identity;
- cluster profile ID;
- provider kind/profile ID;
- API/operation/action family;
- risk/state/result family;
- stable bounded reason code;
- duration/count/bytes/rate gauges and histograms;
- safe capability state;
- coarse runtime component.

### Restricted / opt-in bounded

- topic name;
- consumer-group ID;
- connector name;
- schema subject;
- registered application ID;
- notifier destination profile ID.

These may appear only in explicitly configured resource-scoped metrics and count against hard cardinality budgets.

### Prohibited

- raw Kafka key/value/header values;
- generated record bytes;
- ksqlDB result rows;
- full arbitrary query text;
- access/session/OIDC tokens;
- passwords/client secrets/private keys;
- connector write-only secret values;
- arbitrary provider response bodies;
- full stack traces containing unreviewed secret/request material.

## Cardinality accounting

Each metric instrument has a declared label schema.

Runtime accounting rejects/drops new series beyond:

- 12 labels/series;
- 128 UTF-8 bytes/label value;
- 50,000 active series/process;
- 5,000 resource-scoped series per resource family.

Default operating targets are lower: 8 labels and 10,000 active series/process.

Limit exhaustion emits a dedicated bounded counter/event and safe diagnostic; it never recursively emits the offending unbounded label.

## Trace contract

Spans may include:

- route/action family;
- cluster/provider profile;
- operation ID;
- safe result/reason code;
- duration/budget outcome.

Spans must not include raw request bodies, secret fields, record payloads or ksql result rows.

Trace attribute default/hard caps: 24/48.

## Log/event contract

Structured application events are preferred over arbitrary formatted provider bodies.

Default/hard structured fields: 24/48.
Default/hard safe diagnostic text: 512 B / 2 KiB.

Provider errors are mapped to safe bounded codes and summaries before logging.

## Export configuration

Exporter origins are deployment configuration.

No API request can supply an arbitrary OTLP/remote-write target.

Remote authenticated exporters require HTTPS unless explicitly loopback/local under a reviewed provider contract.

## Air gap

No observability feature requires a public collector/SaaS. Operators may:

- expose local Prometheus scrape;
- send OTLP to private collectors;
- disable all external export;
- retain live Kafdeck observability only.

## Failure semantics

Exporter failure:

- does not block Kafka observation/mutation by default;
- is visible as exporter Unavailable/Degraded evidence;
- is rate-limited to avoid log storms;
- does not buffer without a finite configured memory/disk bound.

Security/audit durability requirements remain separate from optional observability delivery.
