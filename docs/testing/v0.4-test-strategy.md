# v0.4 Test Strategy — Consumers, Schemas & Ecosystem Read Views

- **Status:** PROPOSED
- **RFC:** RFC-0004

## Objectives

Prove that v0.4 read views are authorized, accurate, bounded, secret-safe, failure-isolated and non-mutating.

## Authorization tests

- each new action defaults deny,
- cluster/resource pattern scoping,
- consumer/schema/connect/ksql/catalog actions do not imply `record.read`,
- direct route enforcement,
- partial visibility does not leak hidden resource names through detail routes.

## Consumer tests

- group listing/state/member projection,
- assignment projection,
- committed offset handling,
- end offset handling,
- per-partition/aggregate lag,
- missing offset / deleted partition / partial ACL cases,
- cancellation and timeouts,
- no offset commit/alter/delete,
- no durable group join/subscription.

Real Kafka integration runs on 4.3.1/4.2.1/4.1.2/3.9.2.

## Diagnostics tests

- unknown is not zero,
- metrics unavailable is explicit,
- no history => no historical trend claim,
- stalled/inactive classifications require documented evidence,
- partial snapshots never produce a falsely complete diagnostic.

## Schema Registry tests

- subjects/versions/references,
- Avro/Protobuf/JSON Schema metadata,
- reference cycles/depth limits,
- deterministic bounded diff,
- read-only compatibility inspection,
- auth denial/timeout/malformed response,
- no compatibility or schema mutation HTTP verb/path.

## Connect tests

- worker info,
- connector list/status/tasks,
- error/trace size caps,
- secret-field redaction,
- auth denial/timeout/malformed response,
- no mutation verb/path,
- redirect/origin protection.

## ksqlDB tests

- configured/unconfigured capability state,
- safe server metadata,
- no arbitrary SQL parameter in public/application contracts,
- no statement execution endpoint.

## Catalog tests

- immutable config loading,
- cluster/topic scoping,
- no authorization side effect,
- safe optional metadata.

## Resilience/load

- independent bulkheads,
- bounded page/item counts,
- slow registry/Connect/ksql does not starve Kafka metadata/record browser,
- cancellation releases resources,
- bounded caches and response sizes.

## Leakage regression

Sentinel secrets must be absent from:
- API responses after redaction,
- Problem Details,
- logs,
- audit,
- traces/metric labels.

## Architecture regressions

CI fails if v0.4 introduces:
- consumer offset mutation,
- Kafka producer/replay,
- schema mutation,
- Connect mutation,
- ksql arbitrary statement execution,
- generic upstream URL proxy,
- unbounded list/poll API,
- metadata action automatically granting record access.

## Readiness evidence

W31 records:
- exact-head CI/security evidence,
- Kafka compatibility matrix,
- ecosystem adapter fixture integration,
- bounded latency/load measurements,
- operator/upgrade documentation,
- threat-model reconciliation,
- release candidate identity.
