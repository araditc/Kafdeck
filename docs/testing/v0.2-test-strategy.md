# v0.2 Test Strategy — Operator Identity and RBAC

- **Status:** PROPOSED
- **RFC:** RFC-0002

## Test objectives

Prove that adding operator identity/RBAC:

- authenticates valid OIDC users,
- rejects invalid protocol/cryptographic input,
- enforces server-side default-deny authorization,
- prevents cross-cluster/resource leakage,
- preserves v0.1 read-only/no-payload invariants,
- preserves Local/Token compatibility,
- remains bounded and observable.

## Unit tests

### Identity normalization

- issuer + subject canonical key,
- presentation claims cannot replace subject identity,
- malformed/missing required claims fail,
- claim count/size bounds.

### Authorization

- default deny,
- exact subject binding,
- exact group binding,
- multiple role union,
- cluster scope allow/deny,
- topic/resource glob semantics,
- config-read permission separated from topic/broker read,
- unknown action denied,
- invalid policy rejected.

### Session

- rotation after login,
- expiry,
- logout invalidation,
- no OIDC token exposed to client projection.

## HTTP/security integration tests

- unauthenticated OIDC-mode request challenges,
- valid callback establishes session,
- invalid state rejected,
- invalid nonce rejected,
- invalid issuer rejected,
- invalid audience rejected,
- invalid signature/JWKS rejected,
- expired token rejected,
- open-redirect attempts rejected,
- unauthorized resource returns stable denied response without metadata leakage,
- alternate route cannot bypass authorization,
- cookie security attributes verified.

Tests use a controlled test OIDC authority/discovery/JWKS endpoint; public Internet identity services are not required.

## Authorization matrix tests

At minimum:

1. viewer allowed Cluster A / denied Cluster B,
2. viewer can list topics but cannot read topic configuration,
3. config-reader can read topic config only in permitted cluster,
4. exact subject binding works without group binding,
5. group binding grants only configured roles,
6. unknown group grants nothing,
7. policy/session change does not reuse another user's projected cluster list.

## Regression invariants

Tests MUST continue to fail if any of these appear:

- Kafka mutation HTTP route,
- Kafka mutation application port/command,
- record producer/consumer browser path,
- payload response model,
- direct ZooKeeper administration,
- deployment token accepted as OIDC operator identity.

## Kafka integration

The existing Kafka compatibility/security matrix remains applicable.

RBAC integration tests operate above the existing Kafka adapter and MUST demonstrate:

- Kafdeck allow + Kafka allow,
- Kafdeck allow + Kafka ACL deny,
- Kafdeck deny without Kafka call where practical,
- partial capability semantics remain correct.

## Logging/audit tests

Verify secrets are absent from:

- application logs,
- audit events,
- Problem Details,
- browser-visible bootstrap/session data.

Verify audit identity for:

- login success/failure,
- logout,
- authorization denial,
- configured sensitive read events.

## Performance/load tests

- authorization snapshot evaluation under concurrent requests,
- bounded session-store growth,
- login storm does not bypass global HTTP protections,
- authorization denial does not trigger Kafka I/O where unnecessary.

## CI gates

v0.2 implementation PRs require, where applicable:

- quality-gate,
- dependency-review,
- CodeQL,
- identity/RBAC unit and integration tests,
- existing Kafka smoke/compatibility tests for source changes touching runtime paths,
- security regression tests for no-mutation/no-payload invariants.

Any source-head change invalidates prior exact-head security/review evidence.
