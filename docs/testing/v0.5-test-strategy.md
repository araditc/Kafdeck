# v0.5 Test Strategy — Safe Administration & Controlled Mutations

- **Status:** PROPOSED FOR GOVERNED ADMISSION
- **RFC:** RFC-0005
- **Tracker:** Issue #122

## Objectives

Prove that every mutation path is:
- explicitly authorized,
- capability-gated,
- bounded,
- preview-bound,
- confirmation/approval governed,
- durable and idempotency-aware,
- conflict-safe,
- truthful about ambiguity/partial application,
- secret/payload-safe,
- isolated from read paths.

## Authorization

Test:
- each new action defaults deny,
- read permissions do not imply mutation permissions,
- resource pattern scoping,
- bulk per-target authorization,
- authorization re-evaluation before dispatch,
- direct-route/API enforcement,
- no hidden UI-only control.

## Risk engine

Test:
- deterministic built-in floors,
- client cannot set/lower risk,
- deployment policy can raise but not lower,
- bulk escalation,
- hard/permanent delete escalation,
- CRITICAL always requires independent approval.

## Preview / confirmation

Test:
- canonicalization is deterministic,
- preview hash changes when material intent/preconditions change,
- expired preview rejected,
- altered body rejected,
- typed confirmation challenge required where specified,
- changed provider/resource state becomes stale when material.

## Approval

Test:
- self-approval rejected,
- distinct eligible principal succeeds,
- unauthorized approver rejected,
- expired approval rejected,
- approval for old preview rejected,
- rejection is terminal until new preview/operation,
- Local/Token modes cannot satisfy CRITICAL independent approval.

## Idempotency and concurrency

Test:
- same key + same intent returns same operation,
- same key + different intent conflicts,
- concurrent preview creation races collapse to one binding,
- concurrent executor claims dispatch once,
- conflicting resource operations do not race,
- lock/claim loss stops safe execution where required.

Run race tests repeatedly and under both persistence providers.

## Persistence

SQLite:
- standalone mutation operation lifecycle,
- crash/restart persistence,
- startup rejects multi-instance mutation configuration.

PostgreSQL:
- concurrent executor claim,
- unique idempotency binding,
- resource conflict claims,
- transaction rollback behavior,
- process crash/restart.

Read-only mode must continue without mutation persistence.

## Ambiguous outcomes

Fault-inject:
- timeout before dispatch,
- connection failure during dispatch,
- response lost after provider applies change,
- process termination after dispatch start,
- verification timeout.

Expected:
- pre-dispatch failure may be safely retryable,
- possibly-dispatched failure becomes `ExecutionUnknown`,
- no blind redispatch,
- verification can resolve only when evidence is sufficient.

## Topics

Test:
- create,
- typed configuration alter,
- partition increase,
- delete,
- explicit finite bulk operations,
- unsupported config key fails closed,
- partition increase/delete risk floors,
- current-state drift invalidates stale preview.

Real Kafka integration uses the supported compatibility matrix.

## Record production

Test:
- record-count/byte ceilings,
- topic authorization,
- schema-validation pass/fail,
- ephemeral payload digest binding,
- payload mismatch rejection,
- broker ack evidence,
- ambiguous timeout,
- no payload in DB/log/audit/trace/problem details.

## Consumers

Test:
- explicit offset targets,
- earliest/latest/specific offset,
- timestamp -> explicit offset resolution,
- per-partition delta preview,
- group state/provider preconditions,
- delete where supported,
- replay/skip warnings,
- no silent clamping.

## Schema Registry

Fixture/provider tests:
- register version,
- compatibility mode update,
- soft delete semantics,
- permanent/hard delete semantics where supported,
- risk escalation,
- no arbitrary endpoint,
- auth/timeout/malformed response.

## Kafka Connect

Fixture/provider tests:
- create/update,
- pause/resume/restart,
- delete,
- redacted config diff,
- secret sentinel leakage,
- no arbitrary URL/path,
- redirect/origin protection,
- partial/error mapping.

## Purge

Real Kafka tests:
- explicit DeleteRecords offsets,
- timestamp resolution frozen in preview,
- CRITICAL approval,
- partition-target mismatch,
- low-watermark verification where observable,
- no undo/reversibility claim,
- partial result mapping.

## CSRF

For cookie sessions:
- mutation without antiforgery fails,
- valid antiforgery succeeds subject to authorization,
- GET cannot mutate,
- cross-origin unsafe request fails.

## Leakage regression

Secret/payload sentinels must be absent from:
- persisted operation non-secret fields,
- audit,
- logs,
- Problem Details,
- traces,
- metric labels,
- browser-safe preview projections.

## Architecture regressions

CI fails if v0.5 introduces:
- generic provider command proxy,
- HTTP handler -> provider adapter direct path,
- raw Confluent.Kafka DTO leakage to application/API,
- mutation execution without durable operation state,
- CRITICAL same-actor-only path,
- blind retry wrapper around possibly-dispatched mutations,
- raw payload/secret fields in audit DTOs.

## Load/resilience

Measure:
- per-cluster executor concurrency,
- read-path latency while mutations run,
- bounded bulk planning/execution memory,
- cancellation before dispatch,
- persistence contention,
- operation-status polling behavior.

## Readiness evidence

W40 records:
- exact-head CI/security evidence,
- Kafka compatibility results,
- Schema/Connect fixture results,
- persistence-provider results,
- fault-injection/ambiguity tests,
- benchmark/resource evidence,
- threat-model reconciliation,
- operator/upgrade documentation,
- final release candidate identity.

Release/tag/publication is not performed without a separate explicit owner decision.
