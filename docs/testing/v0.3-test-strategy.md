# v0.3 Test Strategy — Safe Data Explorer + Server-Side Masking

- **Status:** PROPOSED
- **RFC:** RFC-0003

## Objectives

Prove that record access is authorized, bounded, maskable, non-persistent, failure-isolated, and incapable of mutating Kafka.

## Unit tests

### Range/navigation

- earliest/latest anchors,
- explicit offset,
- timestamp resolution,
- previous-page bounded start calculation,
- low/high watermark edges,
- offset-out-of-range,
- empty partition,
- partial/budget result semantics.

### Budgets

- record count,
- raw byte count,
- decoded/projected byte count,
- deadline,
- live-tail duration/rate,
- export rows/bytes,
- invalid client-requested oversize budgets rejected/clamped according to contract.

### Authorization

- metadata-only user denied record read,
- `record.read` separate from `record.export`,
- cluster/topic scope isolation,
- denial before Kafka I/O where practical.

### Decode

- UTF-8,
- JSON,
- binary/hex projection,
- Avro,
- Protobuf,
- JSON Schema,
- unknown schema,
- registry unavailable,
- malformed framing,
- decode depth/size limits.

### Filter engine

- key/header/range predicates,
- regex limits/timeouts,
- CEL deterministic subset,
- jq-style deterministic subset,
- invalid/oversized expression rejected,
- no external I/O or host-code path.

### Masking

- exact paths,
- pattern paths where supported,
- nested arrays/objects,
- header masking where configured,
- undecodable payload + mandatory masking => fail closed,
- raw/hex view cannot bypass policy,
- stable redaction markers contain no original data.

## Kafka integration tests

Using real containerized Kafka versions in the accepted matrix:

- read explicit partition offsets,
- timestamp offset lookup,
- watermark behavior,
- bounded forward fetch,
- previous-page reconstruction,
- live-tail cancellation,
- Kafka ACL denial,
- no offset commit,
- no group subscription,
- no record production,
- one slow cluster does not starve another.

## Schema Registry integration tests

Controlled test registry fixtures for:

- Avro,
- Protobuf,
- JSON Schema,
- references where required for decode,
- cache hit/miss,
- registry auth denial,
- registry timeout/unavailable,
- incompatible/malformed schema response.

Public Internet registry services are not required.

## HTTP/API integration

- direct route authorization,
- safe pagination/navigation metadata,
- filter validation,
- SSE disconnect cancellation,
- export permission,
- JSON/NDJSON/CSV content after masking,
- RFC 9457 safe errors,
- no payload in error details.

## Leakage regression tests

Secrets and record data must be absent from:

- application logs,
- audit sink,
- traces,
- Problem Details,
- metric labels,
- unauthorized responses,
- browser bootstrap/session state.

Sentinel cleartext values are used to detect leakage.

## Load/resilience tests

- concurrent record reads respect per-cluster/global bulkheads,
- metadata Cluster Explorer remains responsive under record-read load,
- budget exhaustion stops fetch/decode/filter work,
- cancellation releases resources promptly,
- slow Schema Registry does not starve unrelated reads,
- live-tail admission/rate limits,
- bounded memory under large records within configured caps.

## Benchmark evidence

W24 records repeatable representative measurements for:

- page-read latency,
- bytes/records processed within bounded scans,
- filter overhead,
- masking overhead,
- schema decode overhead,
- concurrent read impact on metadata endpoints,
- memory/RSS under representative browse/tail workloads.

Measurements are evidence, not universal throughput promises.

## Regression invariants

CI must fail if any of these appear:

- Kafka producer path,
- offset commit,
- consumer-group mutation,
- unbounded scan API,
- payload persistence by default,
- masking bypass path,
- arbitrary server-side JavaScript,
- metadata permission automatically granting record access.

## CI gates

Applicable v0.3 PRs require:

- quality-gate,
- dependency-review,
- CodeQL where triggered,
- architecture/security tests,
- Kafka smoke/compatibility for runtime changes,
- Schema Registry integration tests when decode adapter changes,
- exact-head independent review.

Any source-head change invalidates prior review/CI evidence.
