# v0.1 Test Strategy — Cluster Explorer

- **Status:** PROPOSED
- **RFC:** RFC-0001

## Test layers

### Unit

Covers:

- configuration validation,
- secret-reference parsing,
- health-state projection,
- partition anomaly classification,
- capability projection,
- pagination/cursor validation,
- error normalization,
- safe-bound validation.

### Module/component

Covers application modules with fake Kafdeck ports, not Confluent.Kafka types leaking inward.

### Kafka integration

Uses real containerized Apache Kafka.

Mandatory cases:

- plaintext development cluster,
- TLS,
- mTLS,
- SASL_SSL PLAIN,
- SASL_SSL SCRAM-SHA-256,
- SASL_SSL SCRAM-SHA-512,
- topic listing,
- partition topology,
- topic config read,
- broker config read,
- authorization denied,
- unavailable broker/cluster,
- timeout/cancellation.

### Compatibility matrix

Tier 1 at the current design date:

- Apache Kafka 4.3.1
- Apache Kafka 4.2.1
- Apache Kafka 4.1.2

Tier 2:

- Apache Kafka 3.9.2

The matrix is recalculated at release time against Apache Kafka's supported-release list.

### Contract

OpenAPI/HTTP tests ensure:

- all v0.1 Kafka product routes are read-only,
- RFC 9457-shaped problems,
- bounded page sizes,
- stable enum serialization,
- observation/freshness semantics,
- secret redaction,
- partial-result behavior.

### Frontend

Covers:

- cluster switching,
- loading/empty/error/denied/stale states,
- large topic lists,
- keyboard navigation,
- accessibility checks,
- refresh behavior,
- no accidental mutation controls.

### Load/resilience

Tests:

- cache stampede/single-flight behavior,
- per-cluster bulkhead,
- global bulkhead,
- slow/unavailable clusters,
- cancellation,
- stale-on-error,
- many concurrent readers,
- high topic count,
- memory bounds.

## Negative security tests

- non-loopback bind without configured access token must fail closed,
- invalid token cannot access APIs,
- credentials never appear in API serialization,
- credentials never appear in normal error/log output,
- invalid TLS cannot silently downgrade,
- user input cannot select arbitrary broker destinations outside configured clusters.

## Release evidence

The v0.1 release candidate must publish or retain CI evidence showing:

- exact commit SHA,
- Tier 1 matrix results,
- backend/frontend tests,
- contract tests,
- security tests,
- CodeQL/SAST result,
- dependency review,
- container build/scan when the distributable image is introduced.
