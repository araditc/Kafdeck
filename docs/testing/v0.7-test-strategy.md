# v0.7 Test, Performance and Release Evidence Strategy

Status: **ADMITTED TEST BASELINE — W60 EXACT-HEAD VALIDATION ACTIVE**. Authority #178/#180; W51 #181.

v0.7 adds ecosystem-provider mutations and finite data movement/generation. The test strategy therefore treats provider truth, ambiguity, secret handling, finite budgets and HA fencing as release-critical.

## Test layers

### 1. Unit/domain contract tests

Cover:

- canonical target encoding;
- server-derived authorization conjunctions;
- risk floors/escalators;
- provider capability state mapping;
- preview/fingerprint stability;
- budget validation and overflow;
- statement classification;
- transform/template admission;
- lineage provenance/confidence semantics;
- secret redaction/write-only models.

### 2. Architecture/security boundary tests

Must prove absence of:

- generic Schema Registry proxy;
- generic Connect proxy;
- generic ksqlDB proxy;
- arbitrary shell/CLI/raw-protocol/reflection/sidecar execution;
- public runtime plugin loading;
- arbitrary script/template/transform execution;
- browser secret persistence;
- raw payload durable staging by default;
- mutation routes that skip common preview/approval/durable-operation middleware;
- MM2 activation bypass through new Connect routes.

### 3. Provider contract fixtures

Every advertised provider capability needs a deterministic fixture and, before release, a real-provider test where practical.

Minimum provider evidence:

- Confluent Schema Registry lifecycle;
- Karapace advertised subset;
- Apicurio advertised subset;
- Kafka Connect connector/task lifecycle;
- plugin config validation where used;
- ksqlDB bounded query;
- Kafka record read/produce path for data jobs.

A missing provider fixture means the capability is not advertised as Supported.

## Schema Registry tests

### Read/lifecycle

- subject/version enumeration;
- Avro/Protobuf/JSON Schema round-trip registration;
- references and reference graph;
- compatibility check;
- compatibility mode read/change;
- soft delete version;
- soft delete subject;
- permanent delete if provider supports it;
- exact readback/fingerprint evidence;
- stale provider/profile identity;
- authorization revocation before dispatch;
- timeout/ambiguous external effect;
- provider-specific unsupported semantics.

### Reference safety

- cycle;
- missing reference;
- excessive depth;
- excessive total nodes/bytes;
- cross-provider retarget attempt;
- escaped/unicode subject identity.

### Compatibility risk

- global vs subject scope confusion;
- relaxation escalates to CRITICAL;
- stale prior compatibility value;
- client-supplied risk ignored.

## Connect tests

### Multi-profile configuration

- legacy singular profile => normalized `default`;
- multiple new profiles;
- mixed legacy + list rejected;
- duplicate IDs rejected;
- duplicate/ambiguous origins rejected per validation policy;
- cluster switch/profile switch isolation;
- secret refs resolved server-side.

### Lifecycle

- create;
- update;
- pause;
- resume;
- restart;
- task restart;
- delete;
- provider validation failure;
- provider 4xx/5xx safe mapping;
- timeout after dispatch => unknown/no blind retry;
- provider profile retarget => stale preview;
- class/plugin policy denial;
- transform/converter injection denial;
- secret sentinel absent from persistence/audit/log/trace/API/browser storage.

### Replication guard

Every new effect-capable path attempts recognized MM2/replication connectors and proves:

- create blocked;
- update that starts/resumes blocked;
- resume blocked;
- restart blocked;
- task restart blocked;
- alternate profile/alias cannot bypass;
- generic Connect permission cannot replace replication-specific guard.

## Auto-restart tests

- disabled default;
- attempt default/hard cap/cap-plus-one;
- exponential backoff;
- jitter bounds;
- circuit open/close rules;
- activation lifetime;
- restart/failover does not reset attempts;
- fresh approval does not reset attempts;
- authorization revocation stops future restart;
- provider identity/class/config drift stops;
- ambiguous restart consumes attempt and blocks;
- MM2 guard blocks;
- two-worker duplicate attempt prevented;
- store/audit failure fails closed.

Use fake time for deterministic boundary tests and at least one real Connect failure/recovery scenario before W60.

## SerDe tests

### Common

- size limit;
- nesting/depth limit;
- collection limit;
- cancellation where supported;
- malformed corpus;
- deterministic output where encoding contract defines it;
- no arbitrary type activation.

### XML

- DTD rejected/disabled;
- external entity resolution disabled;
- external schema/resource fetch disabled;
- billion-laughs/entity expansion corpus;
- deep nesting;
- oversized attributes/text.

### CBOR/MessagePack

- deep nested maps/arrays;
- very large declared lengths;
- invalid/truncated input;
- extension/custom type handling fail-closed unless explicitly supported.

## Data-job tests

### Plan

- exact physical source/destination identity;
- alias same-cluster detection;
- frozen ranges;
- timestamp/latest resolves once;
- source gap;
- destination missing;
- masking policy incompatible with byte-preserving;
- hidden metadata/config permission;
- transform family unsupported;
- canonical plan hash stability.

### Budgets

For every count/byte/rate/duration limit:

- default;
- hard cap;
- cap plus one;
- zero;
- negative;
- integer overflow;
- policy tightening;
- restart/failover non-reset;
- approval/confirmation non-reset.

### Checkpoint/fault

- crash before read;
- crash after read before dispatch marker;
- crash after dispatch marker before produce;
- produce timeout;
- crash after broker ack before durable checkpoint;
- restart refuses unresolved batch replay;
- durable known checkpoint resumes exactly after acknowledged offset;
- cancellation;
- authorization revocation mid-job;
- policy/provider identity drift;
- destination topic recreation;
- store full;
- audit backlog full;
- two-worker lease/fencing race.

### Real two-cluster evidence

Before W60:

- finite completion;
- cross-cluster authorization denial;
- masking-policy denial;
- cancellation;
- restart from durable checkpoint;
- ambiguous no-replay scenario or deterministic fault injection at the provider boundary;
- rate/byte cap evidence.

No benchmark should claim exactly-once semantics across crash unless the contract is formally strengthened and proven.

## Generator tests

- schema-backed generation;
- deterministic seed;
- invalid schema/template;
- production deny-by-default;
- explicit production policy path;
- record/rate/byte/duration default/cap/cap-plus-one;
- destination permission revocation;
- cancellation;
- HA failover non-reset;
- no payload persistence sentinel;
- no arbitrary code/template escape;
- bounded memory under hard-cap batch.

## ksqlDB tests

### Statement classifier

Must reject, regardless of case/comments/whitespace/encoding tricks:

- CREATE;
- DROP;
- ALTER;
- INSERT;
- TERMINATE;
- RUN SCRIPT;
- persistent query forms;
- multi-statement bypass unless contract explicitly admits every statement.

Admitted read statements require deterministic parser/classifier evidence. Ambiguous syntax fails closed.

### Query limits

- row default/cap/cap-plus-one;
- byte default/cap/cap-plus-one;
- duration timeout;
- cancellation;
- concurrency bulkhead;
- provider unavailable;
- result truncation/limit metadata;
- no durable result storage;
- no result rows in audit/telemetry.

## Streams/topology/lineage tests

- observed topology from registered evidence source;
- missing telemetry => unavailable, not empty/healthy;
- state-store metrics only where exposed;
- observed vs inferred edge rendering;
- confidence/provenance retained through API/UI;
- inferred edge cannot satisfy mutation authorization;
- stale evidence explicit;
- hidden entity authorization prevents lineage leak.

## API/OpenAPI tests

- released prior routes preserved;
- every v0.7 route documented;
- no undocumented non-GET route;
- no generic proxy route;
- stable Problem Details codes;
- request bounds in OpenAPI;
- secret fields write-only;
- mutation routes require expected security/antiforgery path;
- API/UI capability parity;
- command palette does not access hidden endpoints.

Checked-in `openapi-v0.7.json` must be reproducible from the runtime contract or a deterministic source of truth.

## Accessibility/UI tests

- large table semantics;
- loading/denied/blocked/stale/unknown states;
- secret fields cleared after submit;
- no secret/payload local/session storage;
- reduced-motion behavior;

## Performance tests

W51 defines budgets, not performance claims.

W52–W60 must add repeatable measurements for:

- schema subject/version/reference list scale;
- large connector/task lists;
- SerDe throughput/memory on bounded payloads;
- data-job controller overhead separate from Kafka broker capacity;
- generator limiter accuracy;
- ksql result streaming/memory;
- lineage graph scale;
- UI rendering of large bounded pages.

Regression gates should compare against checked-in baselines with documented variance. They must not weaken hard safety caps to improve benchmark scores.

## Release gate

v0.7 cannot be declared release-ready until:

- every advertised capability has evidence-backed state;
- all Blocked/Unsupported states are documented;
- no unresolved required review thread;
- exact release candidate checks green;
- provider compatibility evidence complete;
- budget/fault/ambiguity suites green;
- security scans/gates green;
- SBOM/signing/provenance evidence green;
- owner separately authorizes publication.

Planning admission does not satisfy the release gate.
