# v0.8 Test, Performance, Security and Release Strategy

Status: **PROPOSED FOR GOVERNED PLANNING ADMISSION**

## W61 admission

W61 is docs/governance only:

- exact-head repository checks;
- DCO/conventional commits;
- substantive architecture/security review;
- fresh CODEOWNER approval;
- zero unresolved required threads;
- expected-head guarded merge.

## W62 observability

Test:

- every declared metric label schema;
- cardinality default/hard/cap-plus-one;
- malicious/high-cardinality resource names;
- trace/log attribute caps;
- no secret/payload/query-row sentinel in metrics/traces/logs;
- exporter timeout/unavailable behavior;
- private OTLP collector;
- Prometheus scrape correctness;
- disabled/no-export mode;
- bounded exporter buffering.

## W63 historical metrics

Test:

- retention default/hard/cap-plus-one;
- downsampling correctness;
- missing data != zero;
- stale/partial coverage;
- series/point/query-range/duration/concurrency caps;
- cancellation;
- migration;
- standalone + PostgreSQL/HA if admitted;
- failover/lease fencing;
- authorization filtering.

## W64 analytics/SLO

Test:

- broker/topic/consumer evidence mapping;
- no fabricated throughput;
- lag trend gaps;
- SLO window math;
- burn/violation boundary cases;
- clock/time-zone independence;
- history unavailable;
- large bounded chart datasets;
- accessibility.

## W65 data quality

Test:

- record permission denial;
- masking sentinel;

- no offset commits/group join;
- no unbounded historical scan;
- malformed rules;
- arbitrary-code escape corpus;
- no raw payload persistence;

- redirect rejection;

- attempt/backoff/lifetime caps;

- unknown external effect;

## Performance

Publish repeatable measurements for:

- metrics scrape/export overhead;
- series-cardinality memory;
- history write/query/rollup;
- lag/SLO query;
- data-quality reader overhead under caps;
- notifier fanout/retry controller;
- declarative plan on 1/100/1,000 resources;
- CLI serialization;
- MCP tool latency/response size.

Hard safety caps are never weakened to improve benchmark scores.

## Security/supply chain

Retain:

- CodeQL;
- dependency review;
- locked restore;
- repository secret policy;
- SBOM;
- High/Critical image vulnerability gate;
- cosign/signing/provenance.

New SDK/provider dependencies require explicit supply-chain review.
