`src/frontend/scripts/v09-accessibility-manual-evidence.cjs` exports `fingerprint(root)`, `validate(record,currentFingerprints,artifactDirectory)`, `stages` and `matrixCells`. Production and test/driver inventories come exclusively from tracked `git ls-files` paths, with CRLF normalized to LF before hashing text. Untracked files are neither inventoried nor read. The complete compiled frontend is separately hashed as exact bytes. Documentation, generated laboratory evidence, build intermediates and dependency directories are excluded. Commit all task source before capturing the manual baseline. A later commit that retains the same source/asset contents can be compared without putting a commit SHA inside an artifact that determines that SHA. Record the actual checked-out SHA and dirty status separately in the run ledger.

Capture these fingerprints before the first observed stage and check them again when validating. The CLI `node src/frontend/scripts/v09-accessibility-manual-evidence.cjs <record.json> [repository-root]` rejects changed content, missing stages, failed/unobserved cells and incomplete cleanup. It checks record completeness and consistency; it cannot attest that a human or agent actually observed a screen reader. Never populate a pass from a browser accessibility tree or generated expectations.

The JSON record has `schemaVersion: 1`, `status: "complete"`, `sourceFingerprints` from `fingerprint`, and the following fields:

- `environment`: `osBuild`, `browserVersion`, `at: {name:"NVDA",version,executableSha256,installerSha256,signatureStatus:"Valid"}`, and `synthesizer: {name:"eSpeak NG",speechMode:"talk",volume,observedVoices:{en:{available:true,selected:true},fa:{available:true,selected:true}}}`. Populate voice observations only after inspecting the running test copy and its actual synthesizer/voice selection.
- `observations`: exactly one row for each English and Persian stage: `before-actions`, `catalog`, `submitted`, `reviewer-before-approval`, `approved`, `expired`, `replanned`, `unknown`, `recovered`. Each row contains `locale`, `stage`, `actor`, `outcome`, `observedAtUtc`, `authenticatedApplication:true`, `actualReaderRunning:true`, `voiceLanguage`, `expected`, `observed`, bounded actual `utterances`, and relative safe `artifacts`. The Speech Viewer variant uses `readSource:"NVDA Speech Viewer"` and actually received `nativeKeys`.
- `artifactHashes`: map each observation artifact's relative path to its SHA-256. The final CLI also verifies these files relative to the record's directory; the record itself is excluded to avoid a self-referential hash.
- `nativeWindowReturns`: one proof per locale from the headed browser driver, with `profile:"headed"`, `actualWindowSwitch:true`, `nativeEventsVerified:true`, actual `blur` and `focus` event rows, `sessionHttpStatus:200`, `opaqueScopeStable:true`, `selectedMaterialAndInputsPreserved:true`, `originalInputNodeAndFocusPreserved:true`, and hashed `artifacts`. Headless page activation retains a form-preservation check but cannot establish native focus/revalidation and is explicitly reported unsupported. It cannot satisfy this manual gate. No synthetic focus event may stand in for this proof.
- `matrix`: rows keyed by `catalog`, `submit`, `approve`, `expiry-replan`, `unknown-recovery`, `locale-fallback`, `keyboard-focus`, `semantics-at`, `contrast`, `mobile-reflow`, `preferences`. Each row contains `outcome`, an actual `observed` explanation and `evidence` references. A scan alone cannot establish a manual contrast or AT result. Browser-emulated preferences retain that provenance.
- `limitations`: explicit limits, including any absence of human pronunciation/community translation review, untested AT/browser combinations, and the distinction between speech-viewer/vendor-log observation and an audible pronunciation audit.
- `cleanup`: `ownedReaderStopped`, `noGlobalSettingsChanged`, `fixtureResumed`.

The alternative actual-reader variant uses `readSource:"NVDA vendor speech I/O log"`, `inputSource:"Playwright Chromium keyboard"` and `nativeWindowsGestureClaimed:false`. It records genuine browser keyboard actions while the real NVDA/eSpeak process observes the compiled application. Do not label those inputs as Windows-native gestures. Set `actualDriverKeyboardActions` to the exact safe `keyboardActionsSincePrevious` array from a hashed `keyboardEvidenceFile` copied from the driver's corresponding ready checkpoint. No typed values, credentials or authentication fields enter these metadata. The validator checks this binding against the artifact.

Every vendor-log row also has `vendorTrace:{file,startByte,endByte,processId,readerVersion,synthesizer:"eSpeak NG",synthesizerVersion,rawLogSha256}`. The hashed public trace `file` contains only reviewed actual application utterances and provenance. Offsets identify the actual UTF-8 source log byte range `[startByte,endByte)`; `rawLogSha256` hashes the private raw-log snapshot ending at `endByte`. Retain that original snapshot privately. A nonempty log, startup say-all or generated expected strings cannot establish the workflow result. Actual relevant control/action labels and resulting state must be observed; a deficient stage remains failed or unobserved. This variant retains all 18 stages, all 11 matrix cells and both headed native-window/session proofs.

For each paused stage, the observer may write `focus-<locale>-<stage>.json` and wait for `focus-<locale>-<stage>-ready.json`. This asks the genuine driver only to bring its known actor page forward and verify authenticated visible content and actual document focus. It does not resume the workflow, fabricate a focus event or invoke a mutation. The normal `resume-...json` remains separate. The driver brings that actor page forward before publishing ready and again after resume. In the private AT profile, startup `virtualBuffers.autoSayAllOnPageLoad=False` may prevent unrelated automatic narration while actual focus speech, eSpeak and nonzero volume remain enabled; record that preference explicitly.

The headed manual window-return check uses `ready-window-away-<locale>.json` and `ready-window-return-<locale>.json`. Activate the actual reviewer window before writing `resume-window-away-<locale>.json`; then wait for the return-ready marker before activating the actual requester window and writing `resume-window-return-<locale>.json`. The real session-response listener is armed before return-ready is published. Each external handoff has a two-minute synchronization bound within the unchanged 45-minute case; actual request and authority expiry remain unchanged. Actual blur/focus events, session GET 200, opaque scope, original input node/focus and selected material must still pass. These native readback/window gestures are recorded separately from Playwright workflow inputs. Only manual cases dwell 1500 ms at each final keyboard target before its key action, recorded as `manualActionDelayMs`; ordinary automated cases retain zero dwell.

Playwright 1.62.1 enables simulated page focus by default, which masked actual window blur/focus in earlier failed attempts. For headed manual cases only, after both genuine actors authenticate, the producer disables that override on each actor's CDP session with `Emulation.setFocusEmulationEnabled:{enabled:false}` for the entire manual journey. This removes focus simulation; it does not generate a focus event or control the native desktop. Per-actor/locale configuration is recorded in `manualNativeFocusConfiguration`; nonmanual cases retain their existing configuration. Before each manual focus wait, `safe-authenticated-actors-<locale>.json` publishes the current authenticated actor and stage. The native controller can activate that actor's actual window before the normal ready marker appears; the marker alone does not authorize a workflow resume. Focus waits are bounded at two minutes within the unchanged case deadline. All actual native-window/session assertions and AT requirements remain unchanged. See the [official focus-emulation protocol definition](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Emulation.pdl).

Immediately after the official CLI starts the owned reader, the observer atomically writes `<manual-handoff-directory>/owned-reader.json` with `pid`, absolute `exePath` and the actual process `processStartUtc` (not a later observation timestamp). This directory is the value of `KAFDECK_W79_MANUAL_DIRECTORY`, normally `<manual-root>/handoff`. The test host's final cleanup stops that process only if its current executable exactly matches the record, lies within this repository's generated `w79-nvda` directory and its actual start time matches within one second. Missing or unverifiable ownership never authorizes stopping a reader. In the same operation that creates any resume marker, the observer must verify one live Node process with this exact case/script and a nonterminal host log. A fresh focus acknowledgment under 120 seconds, matching the exact source and paused stage, establishes the current paused stage even when its original ready marker is older; record that original marker's age. An old ready marker alone does not establish a live fixture. This liveness check does not extend actual preview, request, approval or authority expiry and does not relax any AT stage or matrix requirement.

Before closing its manual browser, including its own error exits, the driver writes `owned-reader-stop-request.json` in that same handoff directory and waits up to ten seconds for `owned-reader-stop-ready.json` with `ownedReaderStopped:true`. The test host verifies/stops only the declared owned process before writing that acknowledgment. An unverifiable stop yields a closed failure and retains the browser rather than closing it under a still-running reader. The host's own final cleanup repeats the same ownership check before terminating its Node/browser process.
