## Mandatory fault matrix

Inject faults immediately before durable dispatch marker, after marker/before network send, during provider call, after broker acceptance, after acknowledgement/before checkpoint commit, during audit staging, after lease loss, on worker restart, at profile/policy revocation and after database restore. Expected effects are explicit for each case. Never turn a known ambiguous window into an automatic retry to make a test green.

Test two workers against the same operation, two conflicting operations, same cluster through different aliases, a stale generation, cross-cluster slot saturation, topic delete/purge versus transfer/reassignment, out-of-band ACL/config/assignment edits, and digest-key rotation. Show that read-only observation may recover while further dispatch stays blocked without current requester authorization.

### Unresolved-effect disposition matrix

For an obligation that bounded readback cannot resolve, prove:
- caller without `mutation.reconcile` is denied,
- caller with `mutation.reconcile` but without the unresolved original effect's complete current action/resource conjunction is denied,
- requester cannot self-satisfy the required independent CRITICAL approval,
- disposition preview binds original `OperationId`, step IDs, conflict keys and latest evidence and becomes stale when those facts change,
- `QuarantineUnknown` retains the conflict obligation,
- `ObservedNonApplication`/`ObservedTerminalEffect` release only with typed readback evidence,
- `SupersedeUnknownForNewIntent` preserves original `ExecutionUnknown` history and permanent no-redispatch tombstone,
- retry/crash of the disposition is idempotent and cannot erase evidence,
- a later conflicting operation is rejected unless it binds the unresolved predecessor, is at least CRITICAL, revalidates current state and receives fresh independent approval,
- neither disposition nor later recovery path can redispatch the old step.

## Leakage regressions

Inject unique password, salt/verifier-like, record key/value/header, JAAS and provider-error sentinels. Search operation/progress/checkpoint/audit persistence, application logs/traces/Problem Details, safe provider evidence, preview/status JSON and browser storage/telemetry. None may contain raw material. Tests must cover malformed input and exception/cancellation paths, not only successful requests. Never upload sensitive real-world test data as CI evidence.

## Real provider matrix

Retain Kafka Tier 1 4.3.1 / 4.2.1 / 4.1.2 and Tier 2 3.9.2. Use isolated multi-broker/multi-log-directory KRaft fixtures where topology semantics require them, plus two-cluster transfer fixtures and an explicit tested Connect/MM2 profile. A single-broker smoke test cannot certify RF/evacuation safety. Include TLS/SCRAM authorization denied and unavailable capability paths. Negative support evidence is required where an operation is intentionally unavailable.

Pinned-client compile probes precede feature claims. Fixture mocks prove deterministic mapping; they do not substitute for real Kafka side-effect/readback tests. Record exact client/broker/profile versions, source SHA, test topology, logs with secret redaction and retained artifacts.

## Numerical and performance tests

Use the runtime budget table as the authoritative initial limits. Exercise cap-minus-one/cap/cap-plus-one, UTF-8 versus character size, overflow/NaN/negative inputs, aggregate child budgets, response cap before allocation, cumulative resume counters, status-poll floods and bounded store backlogs. Specifically test the 2-hour default / 24-hour hard cumulative active-observation window using controllable time: restart, lease renewal, HA takeover, clock rollback and restore must not reset/reduce the durable total; at cap automatic hot polling stops, state becomes reconciliation-required/`WaitingForExternalAction`, and outstanding obligations remain blocking. No test may wait wall-clock hours; use deterministic injected time.

Benchmark ordinary read latency/throughput during mutation/observation/transfer load, with machine/topology/workload disclosed. Keep v0.3/v0.4 regression benchmarks and existing v0.5 persistence/security suites. Do not invent throughput/SLO claims from microbenchmarks.
